# 01: 抓帧探针——WGC 能不能抓到微信窗口

**What to build:** 一条命令，在目标机器上抓到微信窗口的一帧并存盘，让人眼能直接
判断像素对不对。这是整条链路的第一个真跑环节。

命令要能按**进程名 + 窗口标题规则**找到主窗口（不是按面积挑最大的——微信同进程
还有工具窗和看图窗，面积可能更大），走 Windows Graphics Capture 取一帧，
写成 PNG 到 `target/probe/`，并打印尺寸、格式、耗时。

同时验证：窗口被其他窗口盖住时仍然能取到画面；窗口最小化时能用
"不激活还原 + 压到最底"的方式继续被读取，而不是强行抢焦点。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] `cargo xtask probe frame` 在微信主窗口开着时能找到窗口，并打印识别到的
      进程名与窗口标题
- [ ] 存盘的 PNG 能正常打开，尺寸与窗口客户区一致，通道顺序正确（不是蓝底那种
      BGRA/RGB 搞反）
- [ ] 微信被另一个窗口完全盖住时，抓到的帧仍然是微信的内容，不是上面那个窗口
- [ ] 微信最小化时命令能取到内容，且不夺取前台焦点（肉眼可见前台窗口没变）
- [ ] 抓到的帧不是全黑（GPU 合成窗口黑屏是已知失败模式，必须显式检出并报错，
      而不是把黑图当成功输出）
- [ ] 命令在写盘前打印一行明确提示，说明它会把截图写到 `target/probe/`
- [ ] 找不到窗口时给出可操作的错误（进程名、当前枚举到的候选窗口列表），
      而不是一句 "not found"
