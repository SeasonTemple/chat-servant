# 02: 锚点探针——消息区能不能从像素里认出来

**What to build:** 从一帧里推导出 `ChatPane`（消息列表区）的矩形，规则必须由
**像素内容锚定、不写死坐标**，同一份代码要同时吃深色主题、浅色主题、
125%/150% DPI、任意窗口尺寸。

命令打印推导出的矩形和推导依据（面板底色是什么、从哪条边推出来的、输入框顶边
在哪），并把带框的图存盘供肉眼核对。

推导失败（窗口太小、拖动中布局没铺好）必须返回"认不出"并让上层重试，
**不能猜一个默认值**。

**Blocked by:** 01

**Status:** 部分 done（2026-10-07 对账。命令名与票面不一致；多 DPI 未实测）

- [x] 命令在微信窗口上打印出 `ChatPane` 矩形和面板底色
      —— `cargo xtask layout`（**票面写的 `probe layout` 不存在**）；
        实测面板底色 `rgb(30,30,31)`，锚点 `(304,31)-(1156,618)`
- [ ] 同一个窗口在深色主题和浅色主题下都能推出同一个矩形位置
      —— **只有深色实测过**；规则里 chroma/sidebar 判据按深色调过，
        浅色未验
- [ ] 125% 和 150% DPI 下都能推出正确的矩形 —— **未实测**，需要实机切 DPI
- [x] 窗口拖动、缩放后重跑命令仍能推出矩形，不需要重启
      —— 锚点由像素推导、无缓存；窗口实测在 1262x958 / 1275x900 / 1175x900
        三种尺寸间变过，均能推出
- [x] 窗口窄到一定程度时返回"认不出"，而不是推出一个明显错误的矩形

      —— `xtask probe frame` 存帧后由 `perceive` 打锚点；
        实测锚点下沿 618 正好在输入框上沿
