# 03: OCR 探针——中文能不能认出来、说话人能不能分

**What to build:** 在抓到的帧上跑本地离线 OCR，把每个识别框归类成
`Me` / `Them` / 噪声，并画出彩框存盘。

要回答两个只能实机回答的问题：
1. `Windows.Media.Ocr` 在这台机器上认不认中文（依赖系统语言包，装没装只有跑了
   才知道）。认不出必须明确报错并指出缺语言包，不能静默返回空。
2. 微信气泡颜色规则在**当前微信版本**上成不成立（参考项目锁的是它当时的版本）。

**Blocked by:** 02

**Status:** done（2026-10-07 实机复核。⚠ 命令名与票面写的不一致，见下）

- [x] 打印每一行的文本、**置信度**、归类结果和**归类依据**
      —— `cargo xtask perceive --file <png>` 打出说话人/归类/底色/墨色/对比/彩度/纯度
- [x] 存盘的彩框图能一眼看出哪句是对方说的、哪句是我发的 —— `xtask read` 存帧
- [x] 消息区里的时间戳、引用块、群里的发言人名、链接卡片**没有**被当成消息
      —— 实测 `20：37` 判成「灰字」、卡片里的字判成「图内字」，均不进消息流
- [x] 表情包/头像/图片里的文字**没有**被当成消息
      —— 实测表情图里的「What can I say」判成「图内字」（纯度 0.09，
        对比纯文字气泡的 1.00 是反的）；另有语义遮罩与单测兜底
- [ ] 同一个气泡里的多行文字被合并成一条 `Message` —— **未实测**：

- [x] 识别引擎在系统缺对应语言包时，报一个说清楚"缺什么、去哪装"的错误
      —— `OcrError::NoEngine` 带完整安装路径
- [x] 命令打印单帧 OCR 耗时 —— 实测 `OCR 223 ms`
- [x] 颜色/对比度阈值改动后，重跑命令能看到归类结果随之变化的对比输出
      —— `xtask measure` 逐行打印底色/墨色/对比度

**⚠ 票据与实现对不上**：票面写的 `cargo xtask probe ocr` **不存在**。
拆成了两条：`cargo xtask ocr <png> [--scale N]`（只跑 OCR，用来区分
「识别器没读出来」和「归类错了」）与 `cargo xtask perceive --file <png>`
（跑完整管线并打归类依据）。`probe ocr` 的原意由前者覆盖。

**实测挖出的缺陷已修（`c4e6e42`）**：对方那条只有一个「乐」的气泡，
OCR 压根读不到。必要条件有两个：≥2 倍放大、左侧有真实文字上下文。
原先「裁剪消息区再 OCR」的配置两个都不满足 → 对方短消息被整段丢弃。
