# 04: 冻结夹具——把探针产出变成回归基线

**What to build:** 把 01/02/03 抓到的真实帧，连同每帧"应该识别出什么"的期望值
一起冻结成夹具。这是让管线接缝可测的**前置重构**，必须先做完。

夹具要覆盖的差异维度：深色/浅色主题、100%/125%/150% DPI、
有表情包、有引用块、有图片消息、滚动到中途、切过会话。

每份夹具记录：原始帧、帧的 sha256、DPI、主题、微信版本、以及期望的 `Message[]`。

**Blocked by:** 03

**Status:** done（2026-10-07 对账。夹具只有**深色**两份，浅色与多 DPI 维度未做）

- [x] 每份夹具带 manifest：sha256、DPI、主题、微信版本、期望 `Message[]`
      —— 实测两份 `.toml` 都在，记录 width/height/chat 矩形/调色板/锚点
- [ ] 夹具覆盖 spec 里列的全部差异维度，深色和浅色各有代表
      —— **只有深色**：`wechat-dark-2side` / `wechat-dark-myside`。
      浅色主题、125%/150% DPI、引用块、滚动到中途都没做
- [x] 夹具里的聊天内容是**为测试构造的**，不含真实联系人信息
      —— 原始帧不入库；脱敏按面积挑布局色，非底色像素一律刷成块底色
- [x] 帧文件可读回并校验 sha256，损坏的夹具在测试启动时报出是哪一个
      —— 生成时当场校验「调色板封闭 + 锚点与脱敏前逐像素相同 + 面板底色相同」，
        任一不成立就拒收不写盘；`golden` 测试另有三条断言在跑
- [x] 加一个命令能重新生成/更新夹具，但**更新需要显式确认**，不能默默覆盖
      —— `cargo xtask fixture --name <名> --source <png>`；更新基线需手动删 png
