# 05: 管线接缝——帧到消息的黄金测试

**What to build:** 管线接缝的回归能力：一张录好的帧进去，`Message[]` 出来，
中间全部真跑——锚定、调理、OCR、归类、去重，一处都不 mock。

这条接缝是整个系统里最贵的调试杠杆：有它，改一个颜色阈值能秒级看到影响；
没它，每次改动都要开着微信窗口跑完整条链。

**Blocked by:** 04

**Status:** done

## 一个绕不开的前提：夹具里没有墨色像素

ticket 04 的脱敏会把文字、头像、图片全部刷成所在块的底色——**这正是它必须
做到的事**。于是 `probe_bubble_bg` 要测的 `ink` / `contrast` 在夹具上恒为零，
分类判据无从测量。

所以「一张可入库的帧进去跑出 `Message[]`」**按构造就不可能**。
接缝只能拆在唯一带隐私的那一步上：

| 步骤 | 黄金测试里怎么跑 |
|------|------------------|
| `anchor::derive` 锚定 | 真跑，读真实像素 |
| `Palette::learn` 学配色 | 真跑，读真实像素 |
| OCR 取文本框 | **注入** `LineSource`——唯一带隐私的一步 |
| `classify_all` 归类 | 真跑，读真实像素（外圈众数 + 框内墨色） |
| `group` 归并 | 真跑 |

这比原设想弱吗？**不弱**：几何与配色由 `golden.rs` 锁死真实帧基线，
分类与归并由合成帧锁死判据数值，接缝本身由真实帧端到端跑过一次确认。
只是「消息文本」这一项永远是合成的——它本来也不该锁（OCR 是微软的）。

- [x] `chatservant_perceive::read` 走完整管线，锚定/裁剪/配色/归类/归并一处不 mock
- [x] 断言外部可观察结果（说话人、顺序、消息文本），不是内部函数返回值
- [x] 失败的输出里能看出**具体哪一行**归类错了、期望是什么、实际是什么
      （`Attribution::evidence` 的 `Display` 带上全部判定依据）
- [x] 测试不联网、不需要微信窗口开着、跑得完（整个套件 < 1 秒）
- [x] `xtask perceive` 改成走**同一条**生产接缝，探针能跑即产品能跑

## 实测（真实帧，端到端）

小号会话帧 1262×958：OCR 读出 **13 行**，归并成 **7 条消息**。

- 时间戳 6 行全部判成 `Gray`，不进消息流 ✓
- 我方气泡彩度 91 → `Me`；对方彩度 1 但底色 ≠ 面板色 → `Them` ✓
- 多行日文消息（两行）正确合并成一条 ✓
- 气泡内**蓝色链接文字**对比只有 119.9（低于标题阈值 140），
  仍被判成 `Me` 正文——因为先判了「在不在气泡里」。判据顺序不能反，实测再次印证。
