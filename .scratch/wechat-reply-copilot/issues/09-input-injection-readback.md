# 09: 输入注入与回读验证——以回读为唯一判据

**What to build:** 把选中的候选送进微信输入框，并且**停在那里**。
同时提供"确认后发送"这一档。

真正的验收标准不是注入函数的返回值，而是**回读**：注入后读回剪贴板内容，
与候选原文**字节级相等**。投递函数返回成功而没有回读，等于没有证据。

注入要移动真实鼠标的问题也在这条里解决：优先不移动鼠标的路径，
焦点被系统拒绝时走备用路径，并在失败时如实上报。

**Blocked by:** 08

**Status:** ready-for-agent

- [ ] 候选文本进输入框后，回读剪贴板与候选原文字节级相等
- [ ] 注入过程**不移动用户的鼠标指针**（肉眼可见指针不动）
- [ ] 微信被其他窗口盖住时仍能注入；失败时报出真实原因，不假装成功
- [ ] `Confirm` 档下未确认不发送；确认后发送并回读验证
- [ ] 连续填入多条候选时内容总是追加在最后，不串行错乱
- [ ] 会话名识别/切换导致输入框位置变化后，注入仍然落在正确位置
- [ ] 注入失败时 `DeliveryReceipt` 如实反映失败原因，不是 `Sent`
