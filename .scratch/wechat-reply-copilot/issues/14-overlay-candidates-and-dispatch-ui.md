## 关键发现：attachment 不是 action

autofixer 反复报「考虑用 attachment 代替 action」，一开始以为它在吹毛求疵。
查官方文档才看清：**真正的 attachment 语法是 `{@attach fn}`**，
`use:fn` 是上一代的 action。两者差别是能力，不是风格：

| | `use:`（action） | `{@attach}` |
|---|---|---|
| 触发 | 只在挂载时跑一次 | 跑在 **effect** 里 |
| 重跑 | 手写 `update()` | **自动**：读到的 state 变了就重跑 |
| 清理 | 返回 `{ destroy() {} }` | 返回普通函数 |

本项目要的三件事恰好全是「重跑」语义——档位切了要重量位置、理由变了要闪、
消息多了要滚到底。按 action 写就得额外维护「记住上次值」的状态。
`{@attach flash(reason)}` 把 prop 读进依赖就完事。

## 动效的四个判断

- **入场位移只有 10px**：面板悬浮在**用户的聊天窗口**上，大幅飞入会遮挡
  正在发生的事，也会让人分不清是新内容还是整个面板在动。
- **指示块用像素值不用百分比**：百分比要相对定位父级算，而指示块自己在移动，
  滑到一半就会偏。
- **只在消息数增长时滚到底**：用户往上翻历史时来了新消息就把他拽回底部，
  是最招人烦的行为。
- **`prefers-reduced-motion` 时取消位移**（不是把时长缩到 0.1 秒），
  只留淡入。这是无障碍要求，不是风格选择。
