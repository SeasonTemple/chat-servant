# 16: 端到端——抓到、读懂、填入、回读验证

**What to build:** 一条命令走完整条真链：微信窗口开着 → 抓到帧 → 调理 → OCR →
判断 → 起草 → 填入输入框 → **回读验证**。

这是整条链路的验收，也是唯一一个能同时证明六个阶段都成立的证据。

它在开发机上真跑，需要微信窗口开着和真实的模型 key，**不进 CI**。
它治的是接缝测试治不了的集成性故障：WGC 在这台机器上的实际行为、
webview 窗口层的问题、上游模型 API 契约的变化。

断言全部是行为性的，不写"回复质量好"。

**Blocked by:** 06, 07, 09, 14

**Status:** ready-for-agent

- [ ] 命令从开着的微信窗口一路走到候选填入并回读成功
- [ ] 帧非黑、尺寸符合窗口、缓冲区合法
- [ ] `PaneAnchor` 解出且矩形在窗口内、高度超过下限
- [ ] 至少 1 条 `Attribution` 为 `Them`
- [ ] 推理在超时内返回 ≥ 1 条候选
- [ ] **回读剪贴板内容与候选原文字节级相等**
- [ ] 全程只有一个命令、一个明确的中文成功/失败结论，不需要中途看日志猜
- [ ] 失败时能指出**是哪一阶段**失败（锚定/OCR/判断/起草/注入），不是一句"失败了"
- [ ] 端到端跑完之后，确认没有帧被写盘（除非显式要求 probe 模式）
