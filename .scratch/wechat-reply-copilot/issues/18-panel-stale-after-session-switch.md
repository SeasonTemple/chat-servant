# 18: 切换微信会话后，面板内容不更新

**What to fix:** 观察循环在微信里切到另一个会话之后，面板上的聊天内容不动。

**Status:** ready-for-agent

⚠ **本票从另一台设备的快照并入（`docs/HANDOFF.md` §11.6）。
2026-10-10 用户实机报出，2026-10-11 本机复跑时微信会话状态不同，没有复现。**
**未定位、未修。** 任何人接手都别当成已修。

## 复现前先分清

这是「**面板停在旧内容**」，还是「**面板清空了**」？
**两者的根因完全不同**，先分清再动手。这条不确认清楚，
后面四条方向全是猜。

## 四条方向（按怀疑度排序，来自 §11.6）

1. **观察循环是否还活着。** 切会话不改变窗口 HWND。如果循环是靠
   「窗口句柄变化」或「一次性捕获会话」驱动的，切会话可能**根本触发不了
   新一轮**。`AGENTS.md` 记着「WGC 会话别每帧新建」——
   那么反过来，**这个会话是不是被缓存住、再也不刷新了**？
2. **帧条件化 / 去重。** `docs/adr/0002-frame-conditioning-pipeline.md`
   是「帧 → 条件化 → 归类」。切会话后画面变了，但**去重集合**里
   可能已经把这一帧判成「跟上一帧一样」丢掉了。
3. **会话锁定锁的是 HWND 还是微信内部的会话标识。** 锁 HWND 的话，
   切会话后会拿新会话的画面配旧会话的名字——症状会表现为
   「内容不更新」**或**「名字对不上」。两者要分清。
4. **感知层。** `crates/perceive` 把 OCR 框归类成对话人 / 噪声；
   切会话后左右气泡的分布变了，归类阈值可能整片失效。

## 验收项

- [ ] 先回答「停在旧内容」还是「清空了」，写进本票
- [ ] 能稳定复现，命令行可重现（`xtask perceive --file <帧>` 或等价入口）
- [ ] 有 golden 用例覆盖「同一窗口 HWND、内容换一批帧」这个场景
- [ ] 根因定位到**具体哪一行**，不是「大概在某一层」
- [ ] 修完有实机证据：切会话后面板跟着换
- [ ] **不许靠「重锁一次会话」当修复**——那是绕过症状

## ⚠ 一条容易踩的假修法

如果根因落在方向 1（会话被缓存住），修法**不能**是
「每次切会话就重建 WGC 会话」——那正好把 `AGENTS.md` 里
「WGC 会话别每帧新建」那条实测结论**重新违反一遍**，
而且旧会话泄漏 12 线程的坑会原样回来。
