## forced-colors 实测：测到一半，边界要说清楚（2026-10-14）

**做法**：把 `@media (forced-colors: active)` 临时改成
`(forced-colors: active), (min-width: 0px)`（第二条恒真），无头 Chrome 出图，
量完回退。**探针已回退，`app.css` 与 HEAD 逐字一致**（`git diff` 空）。

### 量到了什么

| | 结果 |
|---|---|
| token 替换生效 | ✅ `--cs-paper` `#EDF0F1` → `#FFFFFF`，**2068 / 3952** 采样像素变了 |
| 顺带发现 | `#EDF0F1` 与 `Canvas` 白**肉眼几乎分不出来**——所谓「冷灰配置底」的视觉区分度比想象中小得多 |
| 药丸（墨底）在探针态下 | **仍是 `#000000`，没变** |

### ⛔ 测不到的那一半（这条别当已验）

**像素没变，恰恰说明探针只测到了一半。**
它触发的是**本项目自己那段媒体查询里的 token 替换**，
而 forced-colors 真正的机制是**浏览器在绘制层接管作者的 `background-color`**
——这要求真的进入 `forced-colors: active` 媒体特性，
无头 Chrome **不会因为一条 CSS 媒体查询恒真就进入**。

⇒ 所以「药丸在高对比度下会不会整个消失」**是规范推理，不是实测**。
本轮**没有**验证过绘制层接管。验收项里那一条仍然留着。

### 因此做的改动（是保险，不是修复）

`SegSlider` 的选中态原本只有两条通道：药丸满铺墨底 + `font-weight: 600`。
若墨底失效，12.5px 中文里 400 / 600 差得很轻。

⇒ 在 `@media (forced-colors: active)` 里给 `.cs-seg-btn.on` 加一条
**下划线**：`text-decoration` 的存在与粗细**不是颜色属性**，系统不会抹掉。
常态不画（平时墨底已经说清楚了）。

⚠ **本节下面那条「仍然没测」已被作废**——真开系统主题后验过了，
见下一节。下划线最终保留，是因为它在真主题下确实能扛过绘制层接管
（15.13 : 1 那张图里，选中项既有描边也有下划线）。

## ✅ forced-colors 实测完成（2026-10-14，真机系统主题）

**上一版的「测不到一半」已作废**——真开了系统「高对比度 #1」之后发现，
**无头 Chrome 会继承系统对比度主题**，于是绘制层接管**可以真截图**。
（之前的推断「测不到」是因为只改了 CSS 媒体查询，那只是本项目自己的
token 替换；真开主题后浏览器才真的接管。）

已核对主题确实生效：`HKCU\Control Panel\Accessibility\HighContrast`
的 `Flags = 127`（bit0 置位）、方案「高对比度 #1」。

### 量到并修掉的三个真缺陷

| # | 缺陷 | 实测 | 修法 |
|---|---|---|---|
| 1 | `SegSlider` 选中项**读不出来**。`--cs-ink` → `CanvasText`（深色主题下白）把药丸刷成白底，而文字色 `--cs-surface-raised` 是纯白 | **对比度 1.67 : 1** | `--cs-surface-raised/sunken` 补进 HC 块；药丸在 HC 下改成 `background: Canvas` + `border: 1px solid CanvasText`，强调交给描边 |
| 2 | **纸纹与 HC 互斥**：纸是 `background-image` 位图（不接管），而规范要求 UA 把每个元素的 `background-color` 强制成 `Canvas`——两者一叠，归属行/正文/两枚档位名各变成**浮在奶油色纸上的深色矩形** | 图上可见 | `@media (forced-colors: active) { .cs-sheet { background-image: none } }`。⚠ **不用** `forced-color-adjust: none` 去保纸——那是把用户的无障碍设置顶掉 |
| 3 | 红勾 `--cs-pencil-red` 不在接管列表，HC 下仍用作者的红 | — | 映射到 `LinkText`（本机该主题下是青色，与 `CanvasText` 的字区分得开） |

|---|---|
| `SegSlider` 选中项 | **15.13 : 1** AA |
| 正文 / 归属行 / 档位名 | **15.13 : 1** AA |

### 量具上的两个坑（都踩了）

1. **单点采样取文字颜色会取到笔画之间的空隙**，报出来的其实是背景色。
   ⇒ 改成**区域内主色直方图**才拿得到真正的字色。
2. 头一版对比度脚本 `GetPixel` 的下标越界（`$fg[1]`/`$fg[2]` 实为
   `$fg[0]`/`$fg[1]`），四点全打在图像顶部的背景上，报出一片 `ratio=1`。
   **量具自己坏掉时，输出看起来仍然很像一个结论。**
