# 27: 紧凑模式在真实窗口里是死代码

**What to build:** 面板窄到一定程度时真的切进紧凑布局。

**Blocked by:** None（但要改哪块面板取决于票 **25**）

**Status:** ready-for-agent · **2026-10-13 文档整理时从作废件里挖出来的**

## 症状

```text
tauri.conf.json              "minWidth": 340
(panel)/+page.svelte         const COMPACT_AT = 340;
(panel)/+page.svelte         compact = entry.contentRect.width < COMPACT_AT;
```

`340 < 340` **永远不成立** ⇒ 紧凑分支在真实窗口里是**死代码**。

而它的注释写着「实测 320px 时三栏并排会挤成两行」——那个 320 是
**在浏览器里把演示外框拖窄**量出来的，真实窗口拖不到那么窄。

## 为什么之前没人发现

这条**只记在 `docs/面板设计.md` 里，而那份文档第一行写着「已作废」**。
一个仍然成立的产品缺陷，唯一的记录处是一份没人会照着做的文档——
典型的「重要结论被埋在错误的信息层级里」。

2026-10-13 整理文档时才把它挖出来。

## 两条修法，都要人拍

| 方案 | 做什么 | 代价 |
|---|---|---|
| **A** | `minWidth` 降到 300 左右 | 承认 320 本来就是想要的下限 |
| **B** | `COMPACT_AT` 抬到 360 | 窗口下限不动，让 340 那档真的走紧凑 |

⚠ **在票 25 定下来之前不要动手**：这段代码在 `(panel)/`（被判冻结的旧面板）
上，而新面板 `/panel` 根本没有紧凑分支——用 `width: 100%` 铺满。
**如果票 25 选了 C（合并路由），这个 bug 会自己消失**，改了反而白改。

## 验收项

- [ ] 拍下 A 还是 B
- [ ] **实机把面板拖到最窄看一眼**——不能只在浏览器里测，
      演示模式外框固定 380，够不到阈值
- [ ] 阈值与 `minWidth` 在代码注释里互相引用，**下次改一个能立刻看到另一个**
- [ ] 确认改的是**最终活下来的那块面板**（见票 25）
