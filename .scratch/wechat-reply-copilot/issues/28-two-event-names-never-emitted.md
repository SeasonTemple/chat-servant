# 28: `debug_pane` 与 `telemetry` 两个事件名**从来没有 emit 过**

**What to fix:** 这两个事件名进了契约层的集中清单、前端也确实在 `listen`，
但 Rust 侧**一处 emit 都没有**。要么补上 emit，要么把两处死代码删干净。

**Blocked by:** None

**Status:** done · **2026-10-14 选「删干净」并做完**（旧面板已先在 `5031ab3` 删除，
本票的前提随之变化，见下）

## 事实（2026-10-13 实测，`rg -n "TELEMETRY|DEBUG_PANE"`）

| 事件名 | Rust 侧 emit | 前端 listen | 结论 |
|---|---|---|---|
| `readout` | ✅ `commands.rs` 观察循环 | ✅ | 活的 |
| `armed` | ✅ `dispatch` 装填后 | ✅ | 活的 |
| `menu:settings` / `menu:relock` | ✅ `main.rs` 托盘 | ✅ | 活的 |
| **`debug_pane`** | ❌ **一处都没有** | `routes/debug/+page.svelte:67` | **死监听** |
| **`telemetry`** | ❌ **一处都没有** | `(panel)/+layout.svelte`、`routes/debug/` | **死监听** |

后果，两条：

1. **调试画布只在挂载时拉一次。** `debug/+page.svelte` 里 `await pull()`
   之后没有定时器、没有刷新按钮，唯一的刷新来源就是这个不会触发的监听。
   想看下一帧只能重开调试窗口。
2. **一条注释是假的。** `(panel)/+layout.svelte` 写着订阅 `telemetry` 是为了
   「让 Rust 侧的 emit 有接收方，才算一条真的链路」——
   **emit 根本不存在**，这条链路从头到尾没有过。

⚠ 2026-10-14 复核：票里写的「`debug_pane` 只在 debug 窗口订阅，主面板不收」
仍然成立，但**票里对 `debug_pane` 的定性要更新**——它是**死监听**，
不是「只在 debug 窗口订阅」。

## 为什么单独开票而不在票 26 里顺手做掉

补 emit 是**行为改动**：观察循环每轮要多推一份数据。
而这一轮已经在动 `dispatch` 的安全关键路径（硬约束第 5 条），
两件事混在一起，出问题时分不清是哪一件引起的。

## 选定：**删干净**（2026-10-14）

选**删干净**，不补 emit。三条理由：

1. **`debug_pane` 那份数据本来就不适合每轮推。** 它是整个识别框列表
   （每个框一条），每轮序列化一次的开销要先量；而调试画布是**人工排障
   工具**，用不着一直跟着观察循环跑。
2. **`telemetry` 根本没有帧计数可推。** 它的注释写着「用来证明不是轮询」，
   而「不轮询」已经由 `commands.rs` 里 `latest_readout` 那句
   「不轮询——用户手动触发」在**代码里**证明了，不需要一条事件来作证。
3. **旧面板已删**（`5031ab3`），当初那条「为了补上最后一块」的上下文没了。

⇒ 调试画布改成**明摆着的「重新拉取」按钮**。刻意**不做自动轮询**，
理由同第 1 条。

### ⚠ 一处不能顺手删掉的功能：离线横幅

`(panel)/+layout.svelte` 那条死监听**唯一真实的作用**是：
`listen` 在没有 IPC 时会抛，用那个抛错点亮页面底部的
「这个页面连不上后台」横幅。删掉监听就等于删掉这个提示，
而那是一个**真 affordance**——一个永远空着的面板比一句说清楚的错误危险得多。

⇒ 所以把**理由换掉、不是把功能删掉**：横幅改由一次真实的
`invoke('latest_readout')` 触发（载荷丢掉）。`latest_readout` 只读缓存，
命令自己的注释就写着「不轮询」。

**判据也换了**：原来证明的是「我成功订阅了一条没人发的事件」，
那证明的是订阅成功，不是「连得上 Rust」。现在证明的是后者。

### 补一条测试，堵住同一个坑的另一半

新测试 `every_listed_event_is_actually_emitted`：清单里每个事件名，
Rust 侧必须真有 `emit(` 调用点。

⚠ **原来的 `event_names_are_stable` 把这件事做反了**：它断言
`DEBUG_PANE == "debug_pane"`、`TELEMETRY == "telemetry"` 且 `ALL.len() == 6`
——**声明一个死事件名反而让测试更绿**。清单的职责是「前端只认这几个」，
一个不 emit 的名字进了清单，它就是在替一条不存在的链路背书。

⚠ 这条测试第一版写错过一次：常量名不是 `to_uppercase()`——
`"menu:relock".to_uppercase()` 是 `MENU:RELOCK`，而常量是 `MENU_RELOCK`。
测试立刻报「菜单两条没 emit」，**那正是测试自己写错**，
而它报出来的样子与真缺 emit **一模一样**。已改成
`to_uppercase().replace(':', "_")`，并在注释里记下这个坑。

⇒ **该测试自证过会响**：临时把 `"telemetry"` 塞回 `ALL`，
它报「清单里有从来没有 emit 过的事件名：telemetry」并失败；撤掉即绿。

### 顺带修掉的两处漂移

- `contract.rs` 的模块注释写着「前端镜像在 `ui/src/lib/types.ts` 的 `EVENTS`」
  ——**`types.ts` 里从来没有 `EVENTS`**，只有 serde 类型镜像。
  事件名在前端是裸字面量（`listen('readout', …)`），两边靠本文件约束，
  **靠的类型检查是没有的**。已改成如实描述，并写明「想补类型安全，
  先把前端事件名收进一个 const 清单再从契约生成」。
- `debug/+page.svelte` 头部写「六种颜色」——实际是**七种**
  （`Header` 与 `Gray` 必须分开）。少算一个正是「把时间戳认成会话名」
  那次事故的同一片区域。
