# 29: 应用图标从未设计过（用的是 Tauri 脚手架默认绿气泡）

**What to build:** 一枚属于本项目的应用图标：撕边纸 + 一道横跨它的红勾。
托盘、任务栏、安装包、窗口标题栏图标全部一致。

**Blocked by:** None

**Status:** done · **2026-10-14 分离度已修，纸压到 brightness 0.52**（票不再需要拍板）

## ✅ 已定案：纸压到 brightness **0.52**（2026-10-14）

**没有便宜的修法**，但**有唯一有效的那个**——量具量的是不透明像素的
中位色，而那个中位色**就是纸**，所以只有纸本身的调子能动这个数。

### 为什么不能靠加边 / 投影（这点原来就量对了）

`iconsep.py` 只统计 **alpha ≥ 128 的不透明像素**，再取中位与背景比对比度。
纸占不透明像素的大头 ⇒ **加一道暗边或投影只是多了少数深色像素，
中位数几乎不动**。实测投影 1.11 → 1.12 就是这个道理，
它在 16px 上还是**亚像素**的（1024 开窗的 6px 缩到 16px 只剩 0.09px）。

### 定值过程（不是拍脑袋，是扫出来的）

| brightness | 浅 `#F3F3F3` 中位 / p05 | 深 `#1F1F1F` 中位 / p05 |
|---|---|---|
| 1.00（现状） | **1.11** / 1.01 | 13.39 / 7.17 |
| 0.60 | 3.09 / 2.64 | 4.81 / 3.63 |
| 0.58 | 3.30 / 2.82 | 4.50 / 3.50 |
| **0.55** | 3.59 / 3.10 | 4.14 / 3.32 |
| **0.52（取它）** | **3.91 / 3.37** | **3.80 / 3.15** |

取 0.52 的理由：**它让两侧中位数最平衡**（3.91 / 3.80，最小的那一项最大），
且 **p05 两边也都过 3**——p05 量的是「纸有多大比例已经读不出来」，
0.55 的浅侧 p05 只有 3.10，压边太紧，而我们修的**恰恰就是浅色那一侧**。

⚠ 试过**同时提饱和**（saturate 1.35/1.45）想让压暗后的纸还是暖的：
实测 `rgb(151,138,115)` → `rgb(154,138,107)`，**几乎没变**——
纸纹本身饱和度就低，提不动。开关留在 `icongen.py`（`--saturate`）但默认 1.0。

### 代价（如实记下）

**奶白纸没有了。** 现在是一张 `rgb(132,121,100)` 的深牛皮纸。
深色任务栏那一侧从 13.39 : 1 降到 3.80 : 1——仍过 3:1，但确实不再「跳出来」。
这是「两种主题都读得出」必须付的钱：一个资产、两个背景，
不可能同时是奶白又与近白背景分开。

**但「撕边纸 + 一道横跨的红勾」这个设计本身没变**，改的是纸的调子，不是载体。

## 设计定稿

画布 512。**纸 286（占 56%）居中，勾宽 350、重心压到 (256, 262)**，
勾的两端恰好探出纸外——全缩进纸里会退化成普通 app icon，两端探出才有
「一笔横跨过去」的手感。

判据是 **16px 的托盘真实像素**（放大 10 倍看），不是大尺寸好看。
比例扫过的四组：

| 纸 / 勾 | 16px 上的读数 |
|---|---|
| 226 / 400 | 勾两臂横甩出纸外，剪影变宽，读着散 |
| **286 / 350** | **本稿。纸立得住、勾立得住** |
| 286 / 400 | 两臂甩得更远，更散 |
| 348 / 330 | 干净，但退化成圆角方块，没性格 |

## ⚠ 本轮踩到并已修掉的量具陷阱

出图时把 512 的设计画布放进 **1024×1024 的视口**，master 的 alpha bbox
实测是 `(83, 85, 512, 424)`——图标只占了左上角一格。再拿它 resize 到 16px，
图标就只剩 **8×8 像素**，另外 8px 全透明，而 **PNG 尺寸照样是标称的 16×16**。

据此得出的「纸在 16px 上会消失」是个**假结论**，一度把纸一路缩小、
把设计带偏。`icongen.py` 现在自带自检（`assert_fills_canvas`，
内容占画布不足 25% 直接 abort），并在 docstring 里记了这次翻车。

## 浅色任务栏分离度：量完了，**没有便宜的修法**（2026-10-14）

新量具 `ui/scripts/iconsep.py`，判据是 **16px 真实像素 × 两种任务栏底色**
（浅 `#F3F3F3` / 深 `#1F1F1F`）的**对比度**。

⚠ 这台机器的任务栏是**深色**（注册表 `AppsUseLightTheme=0`），
所以真机托盘**验不了浅色那一侧**，只能靠实底色算——这也是必须量、
不能靠眼睛的原因：浅色那一侧的问题在这台机器上根本看不见。

### 基线

| 背景 | 中位对比度 | p05 |
|---|---|---|
| 浅 `#F3F3F3` | **1.11 : 1** | 1.01 : 1 |
| 深 `#1F1F1F` | 13.39 : 1 | 7.17 : 1 |

判据取 **3:1**（WCAG 非文本图形）。⇒ 浅色侧差了近三倍，与「糊成一团淡斑」
的描述一致。

### 四个候选的实测（本票原来建议的那个被否掉了）

| 候选 | 浅色 | 深色 | 结论 |
|---|---|---|---|
| a 现状 | 1.11 : 1 | 13.39 : 1 | 不足 |
| **b 纸压暗到 brightness 0.60** | **3.09 : 1 ✓** | **4.81 : 1** | 够，但**把深色腰斩** |
| c 加投影 `drop-shadow(0 6px 10px rgba(70,52,24,.45))` | **1.12 : 1** | 13.39 : 1 | **等于没加** |
| d 压暗 0.78 + 投影 | 1.86 : 1 | 8.01 : 1 | 两边都不够 |

⚠⚠ **本票原先写的「便宜的修法是给纸加一道极淡的暖色暗边／投影」，
实测下来是错的**：1.11 → 1.12，等于零。原因是投影在 16px 上是**亚像素**
的（1024 开窗的 6px 缩到 16px 只剩 0.09px），而 16px 上立得住的只有
**纸本身的调子**。

⚠ 压暗到 0.60 那条虽然够 3:1，但它是**拿深色那一侧换来的**：
13.39 → 4.81，腰斩；而且那块奶白纸会变成一张**灰卡**，
不再是「纸 + 红勾」。

### 这是设计决定，不是实现细节

三条路各有明确代价，**不该由 agent 替他选**：

- **保持现状**：深色任务栏（本机默认）很好，浅色主题用户看到糊斑。
- **压暗纸**：两种主题都读得出，但纸不再是奶白，深色侧的勾也变弱。
- **换掉载体**：给图标加一圈实心描边或改成实心剪影——
  这已经不是「撕边纸」了，是**另一次设计回合**。

⇒ 票里只记事实与代价，等拍板。三个候选都已能一条命令复现：
`python ui/scripts/icongen.py --out <dir> [--brightness k] [--shadow css]`
之后用 `python ui/scripts/iconsep.py <dir>/32x32.png` 量。

⚠ `icongen.py` 加这两个开关时**默认值等于原行为**，已验六个产物
（`32x32` / `64x64` / `128x128` / `128x128@2x` / `icon.png` / `icon.ico`）
与改动前**逐字节相同**——托盘正在用的那张没有被这次实验动过。

### ⚠ 量具自己踩过的坑（记下来，别再犯）

第一版 `iconsep.py` 量的判据是 **`|L(像素) − L(背景)|` 的 p95**，
给出 `p95 ΔL = 0.49`，看着像「分离得很好」；同一份数据算出的对比度
却是 **1.28 : 1**。两个颜色都落在 L≈0.9 的近白区，**绝对亮度差在近白
与近黑两端会骗人**，只有相对对比度能跨量级比较。
⇒ 这是「指标名与它量到的东西对不上 ⇒ 结论整个反了」的第二次，
已把判据换成对比度，并把这段写进脚本 docstring。

## ✅ 补测：「红勾偏粉」量了，**过线，不改**（2026-10-14 晚）

上一节按「先定判据再量」的要求补上了勾自己的量具 `ui/scripts/ticksep.py`
（纸的判据归 `iconsep.py`，两者**刻意分开**：纸量的是不透明像素中位色，
勾是半透明红叠在纸上，合成色既不是纯红也不是纸，判据不能混）。

判据两条：① 勾对任务栏 ≥ **3:1**（同 WCAG 非文本图形）；② **勾不得比它
所在的那张纸更弱**——否则它读作一块糊斑，而不是一道勾。

| 底色 | 勾中位对比度 | 纸/底 | 判定 |
|---|---|---|---|
| 浅 `#F3F3F3` | **4.71 : 1** | 3.84 : 1 | 过线，且**比纸更可分** |
| 深 `#1F1F1F` | **3.15 : 1** | 3.87 : 1 | 过线，但余量明显更紧 |

⇒ **「偏粉」是真的**（合成色实测 `rgb(157,93,74)`，纯红是 `rgb(192,57,43)`，
被压暗后的纸又把它拉灰），**但没有到不可辨识**——两种底色都过 3:1，
且浅色侧勾比纸更可分。观感里「像淡砖色」的来源更可能是**深色侧余量小**
（3.15 vs 纸 3.87），不是完全读不出来。

⚠ 量具自检：勾像素占不透明像素 **9%（6/65）**，落在预设区间 3%~35% 内。
样本偏少所以这条结论**保守**地只用来判断「过没过 3:1」，不用来微调。
⇒ **不改笔迹**：`TICK_NESTED_BIG` 是与界面正文共用的笔迹（`marks.js`），
为了托盘上多 0.3:1 去动它，代价大于收益。留作已知余量写在这里。
