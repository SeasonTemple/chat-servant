# 30: 真机上 OCR 认不准，结构对但字不对；会话名压根认不出

**What to build:** 让「认会话」与「读正文」在真实微信帧上成立——
现在结构对、字不准，归属行整行不显示。

**Blocked by:** 需要本机微信在场（本票的证据就是这么来的）

**Status:** ready-for-human · **2026-10-14 根因定案并修完；闸的取样带与
会话名那条路都已改**，但**只有测试验过，真机还没跑**（见「根因」与「待验」）

## ✅ 根因定案（2026-10-14，代码级证据，不是推理）

**闸与会话名取的一直是消息区顶部，而标题栏在 `chat.y0` 之上、裁剪时已被丢掉。**

`anchor::derive` 构造锚点时是这么写的（`crates/capture/src/anchor.rs:166`）：

```rust
chat: Rect::new(x0, header_top, x1, input_top),
```

⇒ **`chat.y0 == header_top` 是定义**，不是巧合。而旧代码的头带取样是

```rust
let top = (anchor.header_top - chat.y0).max(0);   // 恒等于 0
```

⇒ 带子**永远**落在消息区顶部 40px。观察循环里传给闸的又是
`frame.crop(anchor.chat)` 之后那块，标题栏**根本不在输入里**。

### 后果与第一处坐标坑一模一样

2026-10-11 修过一次坐标空间（拿帧坐标去裁消息区画面，裁出右半边中部），
改法是「统一换算到消息区坐标」——**方向反了**：应该往上够到标题栏，
却换算成了消息区内部。于是：

- 闸认的是「这段消息的开头长什么样」，不是「这是谁的对话」
  （两个会话若开头像素相近就认不出切换 ⇒ 硬约束第 1 条被削弱）；
- 会话名**恒读不出来**（`peer=""`），票 30 前面三轮取证都在这件事上打转。

### ⚠ 为什么测试一直是绿的——**夹具把 bug 编码进去了**

`conversation_frame` 一直把标题栏字块画在**整帧 y 12..25**，
而 `test_anchor()` 给的是 `header_top: 0`（于是 `chat.y0` 也是 0）。
字块因此落进**消息区内部**，生产取错地方反而取得到。
**夹具与生产一起错，所以整套闸的测试全绿。**

⇒ 这与 `docs/HANDOFF.md` §4.10「测试文件也可能是死的」是同一类，
只是这次不是没被 `mod` 声明，而是**夹具的假设与生产的 bug 互相印证**。

## 改了什么

| 位置 | 改动 |
|---|---|
| `header_band_rect` | 由「消息区坐标系、带子上边 = `header_top - chat.y0`」改为「**整帧**坐标系、带子**下边贴着 `chat.y0`**，往上取 `HEAD_BAND_H`」 |
| `header_print` | 参数从**消息区**改为**整帧** |
| `peer_name_from_header` | 改为往 `chat.y0` **之上**取，高度被 `chat.y0` 夹住（免得标题栏比 72px 矮时越界） |
| `refresh_peer` | 跟着传整帧 |
| 观察循环 | `header_print(&full, …)` → `header_print(&frame, …)`（`full` 这名字骗人，它是裁过的） |
| `test_anchor()` | 改成真实几何：`chat.y0 == header_top == 40` |

⚠ **`header_print` 与 `PaneWatcher::observe` 现在要的是不同坐标系**：
前者收整帧，后者收消息区。以前两者喂同一块，是这个 bug 能藏住的另一半原因。

### 失败方向是安全的

`chat.y0 == 0`（没有标题栏可取）⇒ 带子高度 0 ⇒ `crop` 给 `None`
⇒ 闸按「认不出」处理 ⇒ **关闸、不起草**。宁可不开工，不认错人。

## 新增判据（两条，都自证过会响）

- `the_gate_distinguishes_conversations_that_open_the_same_way`
  —— 消息行**逐字节相同**、只有标题字形不同的两个会话，必须被判成两个。
  这正是修复前失效的那种情形（两个都从「好的」开头的对话）。
- `the_header_band_sits_above_the_message_area_not_inside_it`
  —— 守几何本身：带子下边必须正好等于 `chat.y0`、非空、且真取得到墨。

**自证**：把 `header_band_rect` 临时退回旧语义（`top = chat.y0`），
**5 条红**（含这两条新判据）；恢复后 73 条全过。

## ⛔ 待验（本票仍 `ready-for-human`）

代码级证据只证明**取样带现在落在标题栏上**。真机上：

1. `header_top` 实测 31 ⇒ 带子只有 **400×31**，够不够 `HeaderPrint::of`
   的 `MIN_PIXELS`？够不到就是**建不起锁**（fail-closed，但面板会一直空）。
2. 那 31px 里**到底有没有会话名**——票 30 第 2 轮量整帧 y 0..`header_top`
   得 0 行。若仍读不出，`peer` 还是空串，界面继续显示「没认出这是谁的对话」
   （这一态现在已有人话，不再是破折号）。
3. 两个会话的标题栏像素**实际差多少**——闸能不能分开，要真切一次会话才算数。

⇒ **上面三条一条都没验过。** 文档里写「闸认的是会话身份」在真机复验前
只能算**代码上成立**。

## 结论先写

**闸是好的，坏的是它旁边的两件事。**

`peer=""` 看着像安全闸出问题，其实不是。观察循环的闸认的是
**头部像素指纹**（`HeaderPrint::is_same`），不依赖 OCR。真机日志里
指纹区域 **16000 px（400×40，阈值 0.90）** 取得到，闸是开着的——
证据就是同一段时间里 `messages=5 candidates=3`，候选都产出来了，
闸关着的话一个字都不会起草。

会话名是**另一条路**（`watch.rs::refresh_peer` → `peer_name_from_header`）：
裁头带 → 放大 → OCR → 取第一条非空行。**任何一步失败就一直保持空串**，
而空串的初始值就是空。所以归属行整行不显示，是「一直没能读出来」，
不是「读出来是空的」。

## 证据（`cargo xtask perceive`，现场抓帧）

OCR 读到的会话名：（没读出标题行）
闸用的像素指纹：16000 px（区域 400x40，阈值 0.90）
```

  共 3 条：

```

## 根因（2026-10-14 定位完成）：**会话名不在捕获到的像素里**

### 三轮采样，逐轮推翻前一轮

给 `xtask perceive` 加了「y 范围」列、判据边界打印、以及三轮采样对照。
**结论是被自己的测量推翻了两次才定下来的**，过程留着，因为每一轮都像结论。

**第 1 轮**：怀疑坐标空间错（`head_band_rect` 里
`header_top - chat.y0` 恒为 0，带子塌成消息区顶部 40px）。
量到 `header_h = 80` 而所有 Header 行都在 y=125 以上，**80px 内一条 Header 都没有**
⇒ 「压根没扫到标题栏」。⚠ 那三条被误判成 Header 的被正确挡住了，
2026-10-07「把时间戳认成会话名」的事故修复**依然有效**，没被碰坏。

**第 2 轮**：改查窗口标题栏（整帧 y 0..header_top）——
`读到：（空）——OCR 返回了 0 行`。
⇒ 「名字不在窗口标题栏里」这条也被否了。

**第 3 轮**：量**生产代码真正采样的那块**（消息区顶部 40px）——
同样 **0 行**；再把它**反色**（深底浅字 → 浅底深字，对照「Windows OCR 在
深色主题上读不出来」这条假设）——**仍然 0 行**。

### 结论

**那块 40px 里根本没有会话名，OCR 精度不是原因。**
窗口标题栏按 `anchor.rs` 的定义整个在 `anchor.chat` 之外，而它在 WGC
帧里也读不到（0 行）；聊天区顶部同样没有字；反色也不产生字。

⇒ **不是「采样位置错了」，是「信息不在数据里」。** 换坐标、改预处理都救不回来。

### ⚠ 但它暴露了一件更要紧的事：闸认的**不是会话身份**

闸用的是 `HeaderPrint` 像素指纹，而那个带子取的是**消息区顶部 40px**
（`header_top - chat.y0` 恒为 0）。也就是说——

**闸现在认的是「这段消息的开头长什么样」，不是「这是谁的对话」。**

后果：两个会话若开头像素相近（比如都从「好的」「收到」这类短消息开头），
**指纹几乎一样，闸认不出切换**。这是硬约束第 1 条
（「只对锁定会话动手」）的一处真实削弱。

⚠ 不是说闸现在就在认错人——真机上 2481 个 tick 一直是开着的，
而它锁的就是第一帧那个会话，没有出错。**说的是这层保证比设计意图弱**：
它防不住「两个会话开头长得一样」这一种情况。

### 要修它得先回答一个设计问题

现有捕获里**没有任何一个像素信号能可靠代表「这是谁的对话」**。
所以修法不是调坐标，而是要选一个替代身份信号，例如：

- 把带子挪到某个**真与会话一一对应**的像素上（如果微信有的话）；
- 或承认「指纹 = 开头几个像素」，把它降级描述为**弱身份**，
  并在两个会话指纹过近时**主动关闸**而不是放行；
- 或接受「只支持一个固定会话」，把切换场景明确排除。

⇒ **这是设计决定，本票不擅自选。** 票里先记事实与代价。

## OCR 精度：是真问题，但不是本票的根因

真机帧上 11 px 高的小字几乎全是乱码：

| 类别 | 实测 |
|---|---|
| 灰色时间戳行 | 11px，读成 `8用5日 《〕巧:33` 一类 |
| 被判为「标题」的行 | 高 9，读成单个字符 `0` |
| 正文（中文） | 逐字替换 |
| 正文（拉丁 / URL） | **基本正确** |

⚠ 注意「基本正确」那一行全是**深底浅字**的绿色气泡里读出来的
（自己发的），而**浅底深字**（对方气泡、深色面板上的字）几乎全废。
第 3 轮的反色对照说明**不是「反色一下就好」能解决的**——
反色后那块 40px 依然 0 行。

⚠ 另一条要分清，否则会修错方向：**结构是对的，字是错的。**
说话人归类正确、消息边界正确、换行的 URL 正确并成一条。
链路是通的，精度不够——两者修法完全不同。

## 归属行说人话（2026-10-14 已做）

`PaperPanel.svelte` 的归属行原先写死 `{peer || '—'}`。真机上 `peer` **恒为
空串**（根因见上：那块像素里没有会话名），所以这块一直是个破折号——
而破折号没回答用户唯一需要知道的那件事：**面板正拿着一句起草好的话，
却不知道自己替谁在写。**

⇒ 改成 `{#if peer}` 分支：认出来照旧显示名字，认不出来明说
**「没认出这是谁的对话」**。墨色加粗（`--cs-ink`，18.05 : 1），
⚠ **刻意不用红**——红在本项目只给不可逆，而「认不出」是可恢复的提醒。

**离线验证**：`?demo=1&state=noprep` 那一具夹具本来就是「没认出会话」
（`peer: ""`、`reason: "没认出会话"`），所以这一态**不需要真机就能验**。
七态全部重出图，`stateink.ps1` 三项自检全过（`drafted` 取景窗有墨、
尺寸 1040×1520、采样 42940），`noprep` 归属行已显示那句人话。

### 顺带撞出并修掉的一处：空态文案与上一行直接打架

出图时看到 `noprep` 的正文写着**「对方说完话，这里才落笔。」**，
而它**上一行**就是对方最后一句「行，不急」——**对方已经说完了**。
两句在同一张纸上互相否定。

⚠ 这不是夹具的问题：`noprep` 与 `silent` 两具**都是 8 条消息**
（对方确实说过话），所以原来的空态文案在这两具上都是假的。

⇒ 空态拆成两支：对方**没**说话时仍是「对方说完话，这里才落笔。」，
对方说过却没起草时改成「**对方说完了，这轮没起草。**」——
只陈述事实，不猜原因（为什么没起草由归属行那句「没认出这是谁的对话」说）。

### ⚠ 由此暴露的三个缺口（缺口 2 已补，见下）

1. **那句空态文案是界面写死的，而 `status_hint()` 对 `read` 态返回 `None`。**
   `types.ts` 写明「`status_hint` 是 Rust 的口径，**界面不许自己写死这句**」，
   而起草中那句确实走了 `status_hint`——**空态这一句没有**。
   按同一条纪律，它也该由 Rust 出。⚠ 这要动契约层，故不在本轮顺手做。
2. ✅ **七个夹具没有一个覆盖「对方还没说话」。** 已于 2026-10-14 补 `fresh.json`
   （`read` + `messages: []` + `peer` 有值），见下面「补上第八具夹具」。
3. ✅ **「没认出」那一态的版式少一个层级手段。** 七态图并排看出来：
   `.cs-peer-unknown` 是独立选择器，不吃 `tracked` 那条规则的 `letter-spacing`，
   于是「没认出这是谁的对话」**没有疏排**，而正常会话名有。层级既然已不再靠字重，
   疏排就得两边都在。已修（`letter-spacing: 0.18em`）。

## 补上第八具夹具（`fresh.json`，2026-10-14）

原来七具的 `read` 态（`silent` / `noprep`）`messages` 都塞了 8 条，
`lastFromThem` 永远有值 ⇒ 面板里「对方**没**说话时才显示」的那一支
**在 demo 里不可达**。判据工具一路全绿，而**它绿得没覆盖到**——
正是「`?demo` 八态绿 ≠ 真机通」的又一例。

补的夹具：`phase: "read"` + `messages: []` + `peer: "示例联系人"`（有名字）。
出图（`?demo=1&state=fresh`）确认正好命中目标分支：

| 态 | 对方说话？ | 归属行引文 | 正文 |
|---|---|---|---|
| `fresh`（新） | **没有** | **无** | 「对方说完话，这里才落笔。」 |
| `noprep` | 说过（「行，不急」） | 有 | 「对方说完了，这轮没起草。」 |

⇒ 两支空态各走各的、**不打架**。顺带补上了「有名字 + 对方没说话」这个
原先没有任何夹具覆盖的格子。

⚠ `stateink.ps1` 的表里 `fresh` 占比 **0.00%** 是**对的**，脚本注释里写明了
原因（取景窗只取正文区，而那具的正文是占位文案，落在窗外）——
别让后人把「0」误读成「这具没渲染出来」。
