# 32: 停泊在别的会话时，面板正文说的是假话

**What to build:** 闸关上（用户切到了别的会话）时，正文不许再说
「对方说完话，这里才落笔。」——那句话在停泊这条路径上是**假的**。

**Blocked by:** 票 31（真机往返验完才撞见这条路径）

**Status:** done · 2026-10-14 改完、九步门禁全绿、
`?demo=1&state=parked` 与 `state=fresh` 两态并排看过，说法不同且都诚实

## 症状（2026-10-14 真机往返验票 31 时撞见）

在微信里切到另一个会话，闸关上、面板清空，面板正文显示：

```text
对方说完话，这里才落笔。
```

**而那个会话对方明明说过话**——微信里看得很清楚。面板实际处在
「已停泊、没在读这个会话」，不是「对方没说话」。

## 为什么界面分不出来

界面挑文案靠 `lastFromThem`（对方最后一句）：

| 状态 | `messages` | `lastFromThem` | 界面说的话 |
|---|---|---|---|
| 对方真没说话 | `[]` | `null` | 「对方说完话，这里才落笔。」 |
| **已停泊在别的会话** | `[]` | `null` | 「对方说完话，这里才落笔。」← **假** |

两者给界面的形状**完全一样**。⚠ 这与票 30 的 `noprep` 是同一族问题，
但方向相反：那次是「对方说完了」被判成「还没轮到」，这次是
「我停泊了」被判成「对方没说话」。**都是 `messages=[]` 撑不起一个区分。**

## 判据：闸的状态必须显式带过来，不能靠界面推断

`Readout` **早就有** `gate_open: bool`，而它的文档注释写着一句正中要害的话：

> 这是一个**显式字段**，不是让界面去 `reason` 里找关键词。
> 2026-10-11 实机：闸关上时 `reason` 写着「本轮不动手」，而前端的理由栏
> 只放行含「失败/错误/抓不到/收不到/异常」的那几条，于是**闸关了但界面
> 一个字都不说**。

⇒ 这次不新增字段、不让界面去 `reason` 里找关键词，沿用已有的 `gate_open`
所确立的形状。

### 优先级：闸关着要压过「正在起草」

闸一关，`apply_gate_closed` 就把候选清空了 ⇒ 那一轮不会有任何产出。
此时若还显示「正在起草，通常几秒」，是在**骗用户等**。
⇒ 判据里专门钉了这一条优先级。

### 文案为什么带一个动作

判据 12：空状态必须给一个明确的下一步动作。
光说「不动手」用户不知道该干嘛 ⇒「锁着别的对话，切回来才继续。」
后半句是动作。

## 判据（已自证会响）

`watch.rs` 的 `a_closed_gate_replaces_the_waiting_line_with_an_honest_one`
断言三件事：

1. 闸关着 ⇒ 带 `GATE_CLOSED_HINT`，且**不含「落笔」**（不许骗人等）
2. 闸开着 ⇒ **不带**那句（否则正常态全被污染）
3. 闸关着 + `phase=Drafting` ⇒ **压过**「正在起草，通常几秒」

**自证**：把 `snapshot` 退回 `phase.status_hint()` ⇒ 本条立刻红。

## ⚠ 这轮撞见的坑：**我挑着跑判据，然后跑去看浏览器**

首次写的分支是 `{:else if readout.status_hint}`——漏了问号，
而 `readout` 初值是 `null`（这一支排在 `readout?.phase === 'failed'` **之后**）。
真浏览器里**整个面板崩成白屏**：

```text
TypeError: Cannot read properties of null (reading 'status_hint')
```

### ⚠⚠ 第一版这里写错了：「判据工具全绿」

当时我写的是「`pnpm build` ✅ / `svelte-autofixer` 零告警 ✅ / `cargo test` ✅
⇒ 判据工具全绿」。

**这三项确实都绿，但那句话是误导的**，因为门禁里本来就有能抓住它的检查。
2026-10-14 复验（把 bug 放回去再跑）：

```text
$ pnpm check
Error: 'readout' is possibly 'null'. (ts)      ← 第 741 行（条件）
Error: 'readout' is possibly 'null'. (ts)      ← 第 762 行（取值）
svelte-check found 2 errors and 0 warnings in 1 file
```

`tsconfig.json` 的 `strict` 是开的，**`ui svelte-check` 这一步就能抓住**。

⇒ **真实原因是：我在跑去看浏览器之前只跑了 build + autofixer + cargo test，
没有跑全套门禁。** 这跟「判据抓不住」是两回事。

### 教训

**判据要跑就跑全套，挑着跑等于没有。** 当时「build 过了、autofixer 过了、
测试过了」三条绿的印象，比「我压根没跑类型检查」这个事实更容易被记住。

⚠ 顺带说明：`autofixer` **不是**类型检查器，它零告警不说明任何类型问题。
`svelte-check` 才是。

⇒ 由此**不必**新增浏览器 pageerror 那道门禁步骤：类型检查已经覆盖这一类，
再叠一道只会让门禁更重而不多抓问题。（这正是先做实验再决定要不要加检查。）

### 与上一节配套的另一半：**对照实验**

上面那个白屏，我差一点归咎成「出图管线坏了」（Chrome headless 在这台机器上
连出空白、换 `--headless=old` 也空白、`--virtual-time-budget` 去掉也空白）。

⇒ 是**对照实验**救的：先拿一个**肯定能渲染**的旧态（`drafted`）出图，
发现它也空白 ⇒ 空白不是量具的毛病，是**应用崩了**。

⚠ 两个坑是配套的：**判据没跑全**让我直到开浏览器才发现问题；
**没有对照实验**让我差点归错责、然后把一个真缺陷当成工具故障放过。

### 二、`?demo` 的装载器会**把要验的那一支裁掉**

`loadDemo` 原来只给 `drafting` 那支带 `status_hint`，`read` 那支写成
`{ phase: 'read', messages: msgs }` 就完了。

⇒ 而 `status_hint` 在真实 `Readout` 里是**与 phase 正交**的
（闸关时 Rust 改用它，phase 可能还是 `read` 甚至 `drafting`）。
**夹具装载器按 phase 挑字段 = 在夹具里把「闸关着」那一支裁掉了**，
那条路径在 `?demo` 下**永远验不到**，而夹具工具照样全绿。

⇒ 与票 30「`?demo` 八态绿 ≠ 真机通」同族：这回绿得更隐蔽，
因为连**新加的第九具夹具**都渲染不出来那句文案。
