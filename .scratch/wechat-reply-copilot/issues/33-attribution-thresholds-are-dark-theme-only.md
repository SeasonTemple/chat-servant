# 33: 归类层的阈值全是深色主题量出来的，浅色主题下对方气泡认不出来

**What to build:** 让「这句话是谁说的」在**浅色主题**下也判对。

**Blocked by:** 无（票 31 已把坐标推导做完，这条不是坐标问题）

**Status:** ready-for-agent · 2026-10-14 真机浅色主题实测发现 · 根因已定位到具体数值

## 现象

2026-10-14 上午切到浅色主题后重跑 `xtask perceive`，对方的气泡被判成**标题**：

```text
#   y 范围      说话人   归类    依据
2   154-166    -       标题    bg=rgb(238,238,240) ink=rgb(25,25,26) 对比=213.1 在面板上 高=12 怎么说
```

同一帧里我方气泡全部判对（`chroma=85`，`在气泡里`）。

**后果不是"分类标签不好看"**：判成 `Speaker::System` + `NoiseClass::Header` 之后，
**它根本不会变成一条消息**。也就是说系统认为**对方没说过话**——
这正是「静默期零调用」那条硬约束赖以成立的前提，也是起草回复的输入。

## 根因：一个恰好落在边界上的容差

`attribute::classify` 的第一步是 `let on_panel = near(probe.bg, palette.panel_bg);`
（`crates/perceive/src/attribute.rs:207`）。`near` 是**逐通道**比较，容差
`COLOR_TOL = 12`（`crates/perceive/src/pixels.rs:12`）：

```rust
pub fn near(a: Rgb, b: Rgb) -> bool {
    let d = |x: u8, y: u8| (x as i32 - y as i32).abs();
    d(a[0], b[0]) <= tol && d(a[1], b[1]) <= tol && d(a[2], b[2]) <= tol
}
```

两个主题的实测值：

| | 对方气泡 | 面板底色 | 逐通道差 | `near()` | 结果 |
|---|---|---|---|---|---|
| 深色（票 02 时期实测） | `rgb(47,47,48)` | `rgb(30,30,31)` | 17, 17, 17 | **false** | ✅ 在气泡里 |
| **浅色（2026-10-14 实测）** | `rgb(238,238,240)` | `rgb(250,250,250)` | **12, 12, 10** | **true** | ❌ 在面板上 |

浅色主题下两个底色的差是 **12, 12, 10**，而容差是 `12` ——
`12 <= 12` 成立，于是"对方气泡"被判成"面板底色"。

⚠ 这是**踩在线上**，不是差得远。差一个通道的一格就翻盘，所以
"把容差调大一点"这种改法必须先想清楚会不会把深色主题那边一起带崩。

## 为什么一直没发现：所有阈值都只在深色下量过

`attribute.rs` 里每个常量的注释都写着"实测"，实测值全部来自深色帧：

- `SATURATED_MIN_CHROMA = 30` —— 注释引「我方 rgb(114,205,144) 彩度 91」
- `HEADER_MIN_CONTRAST = 140` —— 注释引「灰字 93.5、标题 195.4」
- 「对方 rgb(47,47,48) 与面板 rgb(30,30,31) 彩度都是 1」

浅色主题下这些数**一个都没重新量过**。我方气泡侥幸没受影响，
因为 `rgb(157,242,159)` 与面板差 93/8/91，差得够开。

## 顺带发现：浅色主题下**布局锚点与头部推导都是好的**

这条是排除项，不是缺陷——怕后人以为整条感知层在浅色下都不成立：

```text
锚点 (316,31)-(1256,668)  配色 rgb(250,250,250)
推导出的头部行  y 49 .. 61（高 12，相对 chat.y0 +18）
OCR 读到的会话名：G8W（原色 / 反色都是 G8W）
闸用的像素指纹：4800 px
```

⇒ 票 31 做的 `HeaderPrint::discover` **与主题无关**，浅色下照样数得准。
深色下推导出的头部行也是 `y 49..61`，**两个主题一致**。

## ⚠ 量具教训（这一轮又踩了一次）

我先用像素扫描量出「OCR 报的 y 与我量的文字 y 差 18~31px」，
差点当成坐标错位缺陷报出去。**是我把绝对坐标和相对坐标搞混了**——
`xtask perceive` 打印的 y 是**相对聊天区（chat.y0=31）**的，
我拿它跟帧内绝对像素比。

**最后是靠裁图看像素解决的**（把 `x316..1256, y31..250` 放大 2× 存成 PNG 亲眼看），
一眼就看到 G8W 和"怎么说"各在什么位置。

⇒ 两条都记下来：
1. **量到的偏移量恰好是 30/18 这种整数，且方向不一致**（有 +31 也有 −25），
   这本身就说明不是线性变换，**是坐标系搞混了**，不是算法漂移。
2. 数字对不上时，**先出图看**，别继续在数字上推导。
