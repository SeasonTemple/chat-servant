## 「x0: 0」到底是哪来的（确切那一行）

`crates/perceive/src/stream.rs`，`PaneWatcher::observe` 造 ROI 的那一句：

```rust
roi: Rect::new(0, top, pane.width() as i32, bottom)
```

`observe` 收的是 **`frame.crop(anchor.chat)` 裁出来的那块消息区**，
所以返回的 ROI 是**消息区局部坐标**，`x0` 恒为 0、`x1` 恒等于消息区宽度。
日志里的 `roi=Rect { x0: 0, ... }` 因此**不是**整帧坐标，**不是**锚点塌了。

⚠ 上一版本票把它当成整帧坐标，是**误读日志**。

## 量法与实测（2026-10-15）

把本票自己存的两帧喂回**生产同一条**推导链路（重放，不抓新帧）：

```bash
cargo xtask layout --file target\probe\wechat-before-autosend.png   # 退化前
cargo xtask layout --file target\probe\wechat-parked.png           # 退化后
```

两张**逐字相同**：

```text
消息区     = (316, 31) - (1256, 668)   940x637
面板左右   = (316, 1256)
帧 = 1267x930
全图主色   rgb(17,17,17) 65.2%（消息区底色）  rgb(34,34,51) 13.3%（会话列表底色）
```

三处互相印证：

| 证据 | 说明 |
|---|---|
| `chat.x0 = 316` | 会话列表实测宽度 ≈307~316px，侧栏整条在框**外** |
| `roi.x1 = 940`、`roi.y1 = 637` | 正是这张 **940×637** 消息区的宽高 ⇒ `roi` 是它的局部坐标 |
| 两帧锚点逐字相同 | ⇒ 退化前后左边界没变，**退化与左边界无关** |

⚠ `1267x930` 是含 14px 边框的窗口截图，运行时 WGC 抓的是客户区
`1253x923`。由日志 `roi.x1 = 940` 反推运行时 `chat.x0 = 1253 - 940 = 313`
（**这一条是反推，不是直接量到**），仍与 ≈307px 一致。

⇒ **今后判据**：`x0` 塌了的话变的是 `x1`（宽到接近帧宽），不是 `x0`。
换 `anchor.chat.x0` 到位、但 `roi.x1 ≈ 帧宽`，才是真塌了。

## 已落的守卫（两条，都在本次提交里）

1. `crates/capture` `anchor::tests::anchor_lands_on_the_sidebar_edge_on_measured_wechat_geometry`
   —— 按实测几何（1267×930 / 侧栏 316 / 底色 17,17,17 与 34,34,51）复刻一帧，
   断言 `chat.x0 == 316`、`x1 == 1256`、宽高 940×637，并**逐像素**验裁出来那块里
   没有侧栏底色。**只复刻几何与配色，不含聊天内容**，所以能进仓库。
2. `crates/perceive` `stream::tests::the_roi_is_in_pane_coordinates_not_frame_coordinates`
   —— 钉死 ROI 横轴是消息区局部坐标（`x0 == 0`、`x1 == 消息区宽`）。
   此前只钉了纵轴（`y1 == 消息区高`），**横轴无人钉**，本票就是这么误读进去的。

两条都做过**反向自证**：分别把锚点改成 `x0 = 0`、把 ROI 改成整帧坐标
（`x1 = 宽 + 313`），两条测试当场变红（`left: 0` / `left: 713, right: 400`），
改回后绿。
