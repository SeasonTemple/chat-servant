# 分段控件的指示药丸在窄视口下比激活项窄，最后一个字挂到框外

- **状态**: ready-for-agent
- **标签**: ui, bug
- **发现时间**: 2026-10-15

## 现象

`ui/src/lib/SegSlider.svelte` 的选中指示药丸（`.cs-pill`）画得比激活按钮窄，
于是选中项的最后一个字压在框线上、半个字挂到框外。

`ui/?demo=1&state=drafted&settings=1` 出图（`scripts/shoturl.ps1 -Scale 1`，
520×760，1 px = 1 CSS px）实测：

| 控件 | 药丸（量得） | 症状 |
|---|---|---|
| 发送档位「只填入」 | `x=122..157`，**36 px** | 「入」挂在框外 |
| 外观「圈」 | 同上量级 | 「圈」一半在框内一半在框外 |
| 窗口「退出」 | 同上量级 | 正常 |

短横（`.cs-pill::after`，left/right 28%）量到 `x=130..149`，与 36px 的药丸自洽
⇒ 不是药丸内部画歪，是**药丸整体宽度就不对**。

## 已排除（有据）

- **不是 flex 收缩**：给 `.cs-seg-btn` 加 `flex: none` 前后出的图
  **字节数完全相同**（22926 B），按钮没有被压过。
- **不是字体就绪时机**：`document.fonts.ready` 后重量一次，字节数不变。
- **不是动画中途帧**：`--virtual-time-budget` 从 4000 加到 15000，字节数不变。

## 关键线索：随视口宽度变

在**应用内浏览器**（真实 Chromium，视口 671 px）量同一个页面：

| 控件 | 药丸 rect | 激活项 rect | 相等？ |
|---|---|---|---|
| 发送档位 | `x=194 w=61`（内联 `width:61px; left:2px`） | `x=195 w=61` | ✅ |
| 标记形状 | `x=231 w=36` | `x=231 w=36` | ✅ |
| 关闭窗口 | `x=195 w=49` | `x=195 w=49` | ✅ |

⇒ **671 宽下药丸与按钮逐像素相等，520 宽下不等**。差异随视口宽度变，
不随字体、不随 flex、不随动画时长变。

## 下一手该查什么

不是继续在 `SegSlider` 里加钩子。方向是「什么在窄视口下把 seg 那一行排窄了」：

1. 在 520 视口下量 `.cs-seg` 容器的 `offsetWidth` 与两个按钮的
   `offsetLeft/offsetWidth`，看药丸写进去的 `27px`（`--dump-dom` 读到的内联值）
   到底等于谁的宽度。**注意 `shoturl.ps1` 默认 `-Scale 2`，像素不是 CSS px，
   量之前先统一到 `-Scale 1`**，否则会得出 2 倍差的假结论（本票第一版就踩了）。
2. `cs-demo-frame` 的 `style="width: 380px"` 是内联的，确认它在窄视口下
   有没有被 `max-width` 之类的规则改掉。
3. `slideTo` 用的是 `offsetLeft/offsetWidth`（整数像素），如果目标是
   分数像素布局，取整本身就可能差 1px——但差 25px 不是这个原因。

## 已落地的部分（不要重复做）

2026-10-15 已在 `SegSlider.svelte` 里留下：

- `reflow` attachment：`ResizeObserver` 同时盯容器与**每个按钮自身**，
  尺寸变了就重量。**它没有修掉本票的偏差**（字节数不变），但药丸
  「是量出来的覆盖层」这件事本来就该有这两条重量时机。
- `document.fonts.ready` 后补一次重量。
- `.cs-seg-btn { flex: none }`。
- 选中态从**实墨黑药丸**改成**墨线 + 底部短横**（与 §4.2c 墨线按钮族统一）。
  这是同一轮里另一件事，与本票无关，但同在这个组件里。

⚠ 上面三条钩子的注释里都写了「没有修掉本偏差」，**别把它们当成本票的解**。
