# 40: 未配置时设置页根本没有输入框——全新安装无法通过界面配 key

**What to build:** 让「在这个页面填 key」这句话**是真的**。
现在那一页**没有任何办法填**，这是产品的第一步。

**Status:** done · **2026-10-20 最后一项（真 key 走一遍「填 → 保存 → 写入凭据管理器 → 测连通」）在真机跑通；中途撞上票 70 的死路（没 key 时连厂商都切不了），已修**

## 现象

真机打开设置页滚到「模型 key」段，三家供应商各一张卡片，卡片上只有：

```text
openai                                      未配置
未配置。在这个页面填，或设环境变量 OPENAI_API_KEY（存进 Windows 凭据管理器，不落文件）。
```

**没有输入框、没有「填入」按钮、没有任何可点的东西。**

无障碍树里那一段只有 `Text` 节点，`Edit`（输入框）一个都没有。

## 根因：两道门互相把路堵死了

`ui/src/lib/PanelSettings.svelte`：

```svelte
{#if p.configured}
  <button onclick={() => (drafts[p.id] = REVEAL)}>换一把</button>
{:else}
  <p class="cs-hint">{p.hint}</p>       ← 只剩这一句提示
{/if}

{#if drafts[p.id] === REVEAL}           ← 输入框在这里
  <input class="cs-input" … />
{/if}
```

- `drafts` 初值是 `{}`，所以 `drafts[p.id]` 是 `undefined`，**永远不等于 `REVEAL`**
- 而**唯一**会把 `drafts[p.id]` 设成 `REVEAL` 的「换一把」按钮，**在 `{#if p.configured}` 分支里**

⇒ **`p.configured === false` 时没有任何代码路径能让输入框出现。**
⇒ 已配置的用户点「换一把」能改 key；**没配过的用户什么都做不了**。

## 为什么这严重

1. **产品的第一步就走不通。** 用户装完、打开设置、看到「在这个页面填」，
   然后发现这一页没法填。
2. **提示与界面不一致比没有提示更糟**：用户照着做，发现做不到，
   只会以为是自己弄错了，而不是产品缺个控件。
3. **它把验收也堵死了**：2026-10-15 想跑通 `Auto` 档真机验收（`cargo deny`
   之外的最后一个缺口），需要模型侧出候选，而模型侧需要 key——
   本机凭据管理器**确实没有** `chat-servant/*` 条目，也没有任何 `*_API_KEY`
   环境变量。这不是巧合，就是这条死路的结果。

## 修法

未配置时**直接显示**输入框，不套 `REVEAL` 那道门。

理由：那道门本来只为「已配置时不把明文 key 摆在界面上」而设。
**未配置时界面上根本没有 key，没有需要藏的东西**，所以直接显示最合理，
也最小改动——已配置的行为一个字没动（「换一把」仍然是唯一的入口）。

同时把 `secret::missing_hint` 里的「在这个页面填」删掉：
输入框就在提示下面一行，这半句是废话；而在输入框被锁着的那些版本里，
它是**假话**。

## 量具与流程上的两个坑（本轮）

1. **先用读代码下结论、事后才发现死路**。我在会话里说过「本机没配 API key」，
   顺带暗示「得配环境变量」——那是**看门禁日志得出的**：
   `secret scan SKIPPED（CHATSERVANT_PROBE_KEY 未设置）` 是**防 key 泄漏的 CI 闸**，
   跟产品配 key **毫无关系**。两个 `CHATSERVANT_PROBE_KEY` 与
   `<PROVIDER>_API_KEY` 长得像，被我混成了一件事。
   ⇒ 断言「用户没配 X」之前，先确认 X 到底指什么。
2. **grep 用词不对就等于「没有」**。我用 `apiKey|key_input|secret` 搜
   `PanelSettings.svelte`，零命中，差点报「设置页没有 key 输入口」。
   代码里实际叫 `drafts` / `save_setting` / `p.configured`。
   ⇒ **窄查询的零命中不是不存在**（与本仓「别把『我没搜到』当事实」同族）。
