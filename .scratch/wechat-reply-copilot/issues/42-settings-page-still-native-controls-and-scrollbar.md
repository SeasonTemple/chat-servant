# 42: 设置页还是原生框、白底、原生滚动条——上一轮「并入墨线语言」没做到

**What to build:** 让设置页的控件全部落进纸面语言。现在它是**整个面板里
唯一一块 Web 默认样式**的区域。

**Status:** ready-for-agent · **2026-10-15 用户截图指出，待做**

## 现象

2026-10-15 真机截图，用户原话：「设置页还是原生框、白底？还有这个原生滚动条样式？」

三处：

1. **原生框**：`粘贴 key` 输入框是 Web 默认外观（圆角、灰白底、系统字体）
2. **白底**：`.cs-sheet[data-settings='true']` 那层中性底 `#EDF0F1`
   本身是**有意材质切换**（设计规范 §1，2026-10-15 已核过并写进
   `docs/前端设计进度.md` §3b），**这条不用改**。
   ⚠ 但**框里的控件仍是白的**，于是白底上又压一层白框，观感上仍是「一块网页表单」。
3. **原生滚动条**：设置页内容比面板高，滚动条是系统默认那条。

⚠ 别把第 2 条当成罪魁：底色是有意切的，**问题出在控件没有跟着切**。

## 上一次为什么没做到

2026-10-14/15 那一轮改的是 `SegSlider`（`.cs-seg` 槽）、选中态药丸、
说明文字、以及 `PaperPanel.svelte` 里的动作行。
**票面写的是「设置页控件并入墨线语言」，实际只做了分段控件那一处。**

⇒ 也就是说：上一轮的 commit message 与票面都声称做了，
**实际覆盖不全**。这条要写清楚，别让它再被当成已完成。

## 要改的清单

| 元素 | 现在 | 目标 |
|---|---|---|
| `.cs-input`（key 输入框） | Web 默认框 + 白底 | 1px 墨描边 + 纸色底，无系统圆角/阴影 |
| range 滑块 | 已自绘（2026-10-15） | 保持 |
| `.cs-seg` 分段控件 | 已改墨线（2026-10-15） | 保持 |
| 「保存 / 测连通 / 删除 / 换一把」 | 1px 墨描边轮廓 | 与 `.cs-act` 同一族几何（§4.2c） |
| 滚动条 | 系统默认 | 墨色细条，`scrollbar-width` / `::-webkit-scrollbar` |
| 聚焦环 | — | 🔒 §5.4：**用墨不用红** |

⚠ `::-webkit-scrollbar` 在 WebView2 里可用，但**必须实测**——
CSS 里写了不等于渲染了，这条已在本仓吃过亏（描边 `filter` 被 CSS `style` 静默盖掉）。
