# 48: 前端门禁能自验，于是 Rust 侧被整体漏掉了

**What to build:** 让「推进前端」不会静悄悄地变成「只推进了前端」。
这不是一个功能缺陷，是一条**流程缺口**——今晚真的发生了。

**Status:** ready-for-human · **2026-10-16 记录，不是待办——要改的是「下一次接手时先划范围」这个习惯，不是代码。最后一条验收项故意不勾：它只能由人在下个会话开头核对**

## 发生了什么

用户 2026-10-16 22:08 原话：「**rust 代码你不能处理一下？优化？
skill 也在项目中有不是？**」

⚠ 事实：那一轮之前，从 19:20 到 22:08 近三小时，
agent 的**全部产出都在 `ui/`**（`app.css` / `PanelSettings.svelte` /
设计规范 / 票 45 / 六个新脚本），而 `crates/` 合计 **1.8 万行**
（capture 5614 / perceive 5850 / reason 5188 / core 1548）**一行没碰**。

而 `.scratch/wechat-reply-copilot/STATUS.md` 里**未收的 9 张票，
至少 4 张是 Rust 侧**（39 / 40 / 41 / 44）—— 其中 **票 41 明写
`ready-for-agent`**，也就是「明确该 agent 做」。

## 为什么没发生自检

用户 19:23 的原话是「**所以让你做你能做的优化、改bug**」。
⚠ 那句话**没有限定范围**，agent 就顺着手里已经打开的文件一路做了下去，
**没有先看 `STATUS.md` 确认「整体还剩什么」**。

⇒ 而 `AGENTS.md` 早就写着：
- 「**整体还剩什么、卡在哪**」→ `.scratch/<feature>/STATUS.md`（机器生成）
- 「**记东西之前先查这张表。** 每条信息只有一个落点」
- 「`docs/前端设计进度.md` —— **前端**做到哪一步了」

⚠ **缺陷在于**：agent 读了 `前端设计进度.md`（前端的单一出处），
**没读 `STATUS.md`（整体的单一出处）**。
两份都在仓库里，形状很像，读错一份的代价就是**整块看不见**。

## 更根本的：agent 当时**没有能力处理 Rust，却没在开工前说**

沙箱**装不上 Rust 工具链**（2026-10-16 实测）：

| 目标 | 结果 |
|---|---|
| `static.rust-lang.org`（rustup） | **000** 连不上 |
| `crates.io` | **403** |
| Debian bookworm apt | **根本没有 `rustc` 包**（只有 `cargo`），且版本不支持 edition 2024（需 1.85+） |

⚠ **这件事在 19:23 就该说出口**，而不是等到 22:08 被问到才报。
⇒ **「我知道我做不了，但我没说，于是默认跳过了那一块」**——
这比「做了但做坏了」更隐蔽：用户会以为「都覆盖了」。

## 教训（写成规矩，不是感慨）

1. **开工前先读 `STATUS.md`，不是读手上那份。**
   两者都叫「进度」，覆盖面差一个数量级。
   ⚠ `前端设计进度.md` 与 `STATUS.md` 的区别，agent 今晚选错了。
2. **「用户说做你能做的」不构成跳过某一块的理由。**
   尤其当**用户给的动词是「优化 / 改 bug」这种全项目口径的词**。
3. **能力边界要在开工前说，不是在被问到时说。**
   「我改不了 Rust / 验不了」这句话的**成本是早说一分钟**，
   晚说的成本是**用户以为整块都覆盖了**。
4. ⚠ 与本仓已有纪律同族：「**别只信门禁的退出码**」
   （`gate.ps1` 曾经永远返回 0，一个带红门禁的 commit 被提交）——
   **一次没跑的步骤，和一次跑了但报 0 的步骤，在观测上一样**。
   ⇒ **「我没做」必须自己喊出来**，不能指望对方从沉默里推断。
