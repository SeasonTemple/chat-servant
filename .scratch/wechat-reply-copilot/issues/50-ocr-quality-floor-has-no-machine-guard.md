# 50: OCR 认字准不准，只存在于票里的文字里——改坏了没有任何东西会红

**What to build:** 让「正文认字准」变成会红的东西。
现在它是一张表，不是检查：换引擎、改预处理、调阈值、动后处理，
`cargo test` 都不会响。

**Blocked by:** None（验收项 1、2 可立即做；验收项 4 的实测部分需要真帧在手）

**Status:** ready-for-agent

## 现象（票据级证据，不是推测）

票 30 在「定线」那一节钉了三个数，并注明「低于这些就算回归」：

| 指标 | 下限 | 当时的实测（2026-10-14，WinRT） |
|---|---|---|
| 消息召回率 | ≥ 80% | 85.7% |
| 整条全对率 | ≥ 50% | 57.1% |
| 字符准确率 | ≥ 75% | 77.3% |

⚠ `cargo test` **不检查这三个数**——它们只写在 `.scratch/` 的正文里。

2026-10-18 这一轮在这条链上做了：换引擎（WinRT → PP-OCRv6 small）、
修掉三个 det/rec 后处理 bug、默认后端翻成 ort、默认值翻成 PP-OCR。
**每一格按上面的线都算「回归或持平」，而门禁从头到尾一声没吭。**

⚠ 这不是「当时恰好没退化」。同一轮里已经出现过一次真实退化：
修后处理之前 Rust 侧 CER 是 **18.60%**，而参照实现是 **0.79%**——
**18 倍的差距，没有任何一个测试报出来**，是靠人肉 diff 读数才发现的
（ADR-0006 第（四）节记了整段）。

## ⚠ 先承认能力边界：便宜的守卫守不住真帧字准

**没有任何一种便宜方法能在 CI 里守住「真机微信帧上的字准」**：

| 办法 | 为什么不够 |
|---|---|
| 合成图 + 答案键 | 字的渲染、抗锯齿、字距、颜色对比都不是微信的；测不到 det 漏检，也测不到气泡布局 |
| 真帧脱敏后入库 | 打码会毁掉字形本身；不打码则是真人会话内容（本项目纪律禁止入库） |
| 只守结构（行数、几何、归类） | 这类已有夹具在做，但**结构对而字错**正是票 30 的原始症状——结构全绿而字是乱码 |

⇒ 所以这票**不承诺**「CI 守住真帧字准」。它承诺两件能真做到的事：
**(a) 把能守的那一类守住**（算法级回归），**(b) 把守不住的那一类变成流程要求**。

## 验收项

- [ ] 一条 `cargo test` 跑完整 OCR 链路（det → rec → 后处理），
      用**入库的合成图 + 答案键**断言字符错误率上限。
      守的是后处理那一类：等比输入宽度、det 重采样、unclip 各向均匀、
      rec 归一化与插值——2026-10-18 修的三个 bug 都在这一类里，
      它们各自已经有守卫，但守卫断的是**单个函数**，
      这一条要断的是**整条链路的输出**。
      ⚠⚠ **权重在 `target/models/`、是 gitignored 的 31 MB，CI 上没有**
      ⇒ 这条测试在 CI 上**必然跳过**，与 `crates/perceive/tests/golden.rs`
      「缺件即跳过」是同一个模式。
      ⇒ 所以它的定位是「**本地每次改 OCR 都该跑**」，**不是**「CI 守线」。
      ⚠ 这一条必须写在测试旁边：否则下一个读 CI 的人会把绿读成「验过了」。
      票 30 末尾已经踩过「别把『CI 全绿』读成『真机路径验过了』」这个坑。
- [ ] **该守卫自证过会响**：把上限调到当前实测值以下当场红，贴出输出；
      恢复后全绿。⚠ 判据用**退出码**，不用输出文本匹配
      （PS 5.1 的 `-match` 默认不区分大小写，见 ADR-0006）。
      ⚠ 同样受「CI 缺权重」限制 ⇒ 自证在**本地**做。
- [ ] 夹具旁边写明它的**覆盖边界**：合成图 ≠ 真帧，这一条绿**不等于**
      「真机验过了」。⚠ 别让下一个读 CI 的人把它读成后者——
      这与票 30 末尾「别把一个主题的结论当另一个的」是同一个坑。
- [ ] **流程补齐**：把「换引擎 / 改预处理 / 调 det 阈值之后，
      必须跑一次 `scripts/ocrbench/cer_real_frame.py`」写成硬要求
      （ADR-0006 或 CONTRIBUTING）。
      ⚠ 真帧与答案键在 `target/` 下、gitignored，所以这一步**只能人工跑**，
      这不是缺陷，是隐私约束的必然结果——但它必须被写下来，
      否则「没人跑」和「跑过了」在 git 里长得一模一样。
- [ ] 台架脚本的 `--tol` / `--drop-line` / `--explain` 三个开关
      在文档里各有一行说明（它们目前只存在于脚本 docstring 里）。
      ⚠ 理由：这三个开关是 2026-10-18 定位那三个 bug 的工具，
      而 ADR 第（四）节反复出现的错误是「拿两把不同的尺子比」——
      会用 `--tol` 扫稳定区，正是避免那类错误的手段。

## 顺带记一条（本轮实测，不属于本票范围）

2026-10-18 装包验证时发现：**回落类失败不体现为非零退出码**——
PP-OCR 不可用时会打 `WARN` 但退出码仍是 0。
⇒ 任何以退出码判成败的批量脚本，在这套工具上都会**全绿**。
详见 ADR-0006 那一节的「量具自检」。
