## 发送档的安全模型（不碰发送的验法）

`cargo test -p chatservant-core dispatch` ⇒ **13/13 通过**，逐条对应硬约束：

| 硬约束那一条 | 守卫测试 |
|---|---|
| 只有两档且命名 | `the_tier_set_is_exactly_two_and_named` |
| 默认档最低 | `the_default_tier_is_the_lowest_one` |
| 程序自己不升档 | `the_program_never_raises_its_own_tier` |
| `Auto` 不二次确认 | `auto_is_the_one_tier_that_sends_without_asking` |

| 可回退 | `changing_tier_disarms`（改档清空防重记录） |

剩下唯一没验的是「按下去真的发出去了」，那需要往 G8W 真发一条，**未获授权**。

## 这一轮踩到的三条量具坑

- **`#32768` 原生菜单在 UIA 下返回 0 个后代元素** ⇒ 菜单内容只能截图读像素。
- **菜单弹出后另起子进程去读会被抢焦点收掉**，读回来是空。
  「菜单没建起来」与「菜单被抢掉了」**在输出上完全同形**
  ⇒ 点与读必须同一进程（`traymenu_shot.ps1`）。
- **`Alt+F4` 的判据不能只看进程还在**：托盘常驻时「面板关了但进程留着」
  与「完全拦住了」在进程层面同形 ⇒ 必须**再看面板窗口在不在**。
