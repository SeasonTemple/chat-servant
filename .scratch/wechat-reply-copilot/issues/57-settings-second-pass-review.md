# 57: 设置页二次评审——红勾盖住小字、同屏四种控件高度、注释里的对比度数字是假的

**What to fix:** 用户 2026-10-18 第二轮说「还有一堆弱智的设计……你自己去优化」。
本轮用 playwright 量了真实布局，查出四个问题。**已修的见「本轮已改」，
未修的三条各自需要先取证或先拍板，理由逐条写在下面。**

**Status:** open · 2026-10-18。四条查出，一条已修（Markdown 外泄），三条待处理。

## 评审工具本身的两个坑（本轮踩到，先记下来）

1. ⚠ **`fullPage` 截图对内部滚动容器无效。** `.cs-set` 是 `overflow-y: auto`，
   `fullPage` 只截到视口那 560px，后面六节（发送档位/外观/窗口/上下文/图片/代理）
   **全丢**——而「fullPage 没报错」这件事本身就会让人以为已经看全。
   出图前必须把滚动容器展开（`height:auto` + `overflow:visible`），
   宽度不动（380 取景框是定稿）。
2. ⚠ **内置浏览器这轮「渲染正常但 DOM 通路是空的」**：`query(kind:'dom')`
   返回 body 里只有一个空 div、`inspect` 报 0 元素，而截图完全正常。
   ⇒ 量几何只能走 `playwright-core` + 本机 Chrome 取 `getBoundingClientRect`
   （`target/probe/measure-settings.mjs`）。
   ⚠ 主机名必须写 `localhost` 而不是 `127.0.0.1`：vite dev 只绑前者，
     写后者会 `ERR_CONNECTION_REFUSED`，而同一时刻内置浏览器访问完全正常，
     于是看起来像「服务挂了」。
3. ⚠ **不能拿不同容器的控件比高度。** 我一度据「输入框 62 / 按钮 55.5」
   判「等高不成立」，而 `.cs-form` 是 flex + 默认 stretch，
   输入框高度本就由同行按钮决定 ⇒ 等高成立，是我的量法跨了容器。

## 未修 ① ⛔ 手绘红勾盖住小字（最严重，待用户拍板）

`SegSlider` 的选中态是一枚 **29×30 的红铅笔勾**（`TICK_NESTED`，自然尺寸
56×34 不缩，§4.2c 定案，为 21px 大字盖章而量），
而分段控件的选项文字是 **11.5px**。实测出图上「只填入」「勾」「退出」
三个选项的**文字被勾盖住**，几乎读不出来。

**病根是同一枚勾被用在两种字号上** —— 大字那侧是定案尺寸，小字那侧必然盖字。
这与 §4.2c-bis「标记是**从纸上撕下来的一片**、盖章式覆盖」的定案直接冲突，
所以**不能单方面改**：要么给小字那侧单独一枚更小的勾（但注释明写
「不许缩放，五层羽化是按 56 宽调的，缩了笔性就变」），要么把勾移出文字。

⚠ 需要用户拍板。

## 未修 ② 同屏四种控件高度（实测，非目测）

playwright 量 `getBoundingClientRect`：

| 控件 | 高度 |
|---|---|
| 输入框 `.cs-input` 与同行「保存」 | **62**（撕边 `16px×2` + 内容盒 30） |
| chips 与动作按钮 `.cs-btn-mini` | **55.5** |
| 「打开」 | **46** |
| 「重试」 | **44** |

⚠ **62 那个不只是「高」，它就是「长宽明显不合理」的成因**：
输入框 205×62 ⇒ 高宽比 1:3.3，单行输入框不该是这个比例。
⚠ 而在 `.cs-form`（flex + stretch）里**改输入框边框降不了它的高度**，
  高度是被同行撕边按钮撑的 ⇒ 要治就得动撕边控件族的整体尺寸，
  而那一族是全项目定案（28 个按钮 + 主面板）。
⚠ 46 / 44 那两个与 55.5 不一致，属内部不一致，与定案无关，可直接查。

## 未修 ③ ⚠ `app.css` 里 11 支色 token 有 9 支的行内注释对比度与实测不符

子代理用 `target/bench-venv` 实算（含 `color-mix` 先混再取整再算对比度）：

| token | 注释自称 | 实测 | 后果 |
|---|---|---|---|
| `--cs-live` | 5.95 : 1「越过 AA 正文」 | **4.28 : 1** | **达不到 AA 正文**，而它用在 11.5px 正文上（`.cs-warn` / `.primary` / `.cs-warn-on`） |
| `--cs-live-dim` | 7.18 : 1 | 5.15 : 1 | — |
| `--cs-tier-ink` | 17.71 : 1 | 12.48 : 1 | — |
| `--cs-pencil-red` | 5.90 : 1 | **4.56 : 1** | 方向相反（这条仍 ≥4.5，勉强过） |
| `--cs-ink` | 18.05 : 1 | 14.11 : 1 | `app.css` 内部自相矛盾（224 行 vs 158 行） |
| `--cs-mark` | 3.00 : 1 | 3.51 : 1 | 偏保守，无害 |

⚠⚠ **`--cs-live` 那条最严重**：`app.css:32` 的文件头明写
「它在暖黄纸上 5.95 : 1，越过 AA 正文——但刻意不当装饰色用」，
**这句错误正是它立论的依据**。⚠ 成因未定位：实测它们都不是对旧冷灰 /
`--cs-surface` / 纯白算出来的。⇒ 先查成因再改数，不要直接改数字。

## 未修 ④ `.cs-btn-mini.primary` 用警报红承载「选中态」

`.primary` 与 `.danger`（删除，不可逆）**走的是同一条声明**（`color: var(--cs-live)`，
相差 4 行）。而 `.primary` 承载的是供应商 chip、保存 key、写端点、设代理
——**全部可逆**，撞 §1 第 3 条「红只给不可逆 —— 退出与发送两件事，别的都不许红」。

⚠ 改法没定：直接换成墨色会与未选中那颗**完全一样**（实测未选中就是
`rgb(20,26,31)` 墨色），失去选中辨识度。⚠ 需要另想一种选中表达
（墨底？加重字重？）。⚠ 本轮**没动** —— 涉及辨识方式，不擅自改。
