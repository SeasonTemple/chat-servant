# 58: 设置页第三轮——分节层级实测失效、demo 与真实不同构、红字不达 AA

**What to fix:** 票 57 收尾后继续往下滚，发现下半屏（上下文 / 图片 / 模型）
从来没被逐屏看过。这一轮只用了两个新量具：`target/probe/roll-settings.mjs`
（逐屏滚 `getBoundingClientRect` + 截图）与 `target/probe/rhythm.mjs`
（纵向节奏：每个标题 / 字段名 / 控件的 y、字号、字重、上边距、相邻间距）。

**Status:** done · 2026-10-18 · **验收项 10/10**

## 量具本身的一处订正（先记，因为它推翻了上一轮的一个结论）

⚠⚠ **`measure-settings.mjs` 那种「展开滚动容器 + `fullPage`」的拍法会骗人。**
把 `.cs-set` 设成 `height:auto; overflow:visible` 再整页截图，纸面位图会在
**大约 y=1400 处断掉**——看起来像「下面的内容被纸切掉了 / 没渲染」。
逐屏滚动截图（`roll-settings.mjs`）拍出来完全正常。

⇒ 票 57 记的「`fullPage` 对内部滚动容器无效」只说了**一半**：
另一半是**它会让你以为内容被裁了**，而真正的原因是量具把布局掰坏了。
**出图前先问「这段空白是产品的还是量具的」**，判据是同一棵树换一种拍法再拍一次。

## ① ⛔ 分节层级**实测是空转的**（`rhythm.mjs` 实测，不是观感）

代码里有一条定案：「分组全靠**留白和字号**，不画分隔线」（与主面板同一条
排版语言）。实测这两个机制**都没有生效**：

| 量 | `.cs-h2`（分组标题） | `.cs-label`（字段名） | 差 |
|---|---|---|---|
| font-size | 12.8px | 12.5px | **0.3px** |
| font-weight | 600 | 600 | 0 |
| letter-spacing | normal | normal | 0 |
| 上方相邻间距 | 20.8 ~ 22.8 | 19.7 | **1.1 ~ 3.1px** |

⚠ 0.3px 的字号差**正是本文件开头批评过的那种病**（「11.5 与 11.52 差
0.02px——肉眼绝无分别，却各自写着」）。收敛字体阶梯时把分组标题和字段名
**收进了同一档相邻的两档**，差 0.3px，层级就没了。

⚠ 更糟的是**方向反了**：标题到**标签**的间距 19.7px，到**控件**只有 7.2px
——标题与它下面第一个字段名之间的缝**最宽**，读起来像「标题属于上一块，
标签才是这一块的开头」。

**改法**（「不画分隔线」这条**不动**——它的由来是分节曾被套上描边卡片，
一条平规则不是那回事；改的是让它依赖的量真的分得开）：

- 分组标题单独一档 **13.6px + `letter-spacing: 0.08em`**。
  字距是第二重信号：中文没有词间空格，标题靠**加宽**比靠加大字号更容易认出来。
- 上边距 `0.85rem → 1.35rem`、下边距给 `0.28rem`（原来下边距是 0）。
- `.cs-h2 + .cs-label { margin-top: 0 }` 修掉方向反了的那一格。

改后实测：标题上方 30.8 ~ 52，标题到控件 / 到标签**都是 11.6 ~ 11.7**。

⚠ 连带：`.cs-group-name`（「主模型」「备用模型」）原本注释写着
「与 `.cs-h2` 同值」的 12.8px——标题一改这句就假了，同屏出现两种分节标题。
已同步为 13.6px + 同一字距。

## ② 「重试」是横贯整屏的整宽块，「打开」是内容宽度

两者都是 `.cs-btn-mini`，一个 **288×46**、一个 **97×46**。
原因：`.cs-set` 是列向 flex 且 `align-items` 拉伸，而「重试」是它的直接子元素
（`.cs-btn-ink` 有 `align-self: flex-start`，`.cs-btn-mini` 没有）。

改法：错误文案与它的按钮包进同一个 `.cs-retry` flex 行。
⚠ 顺带解决**归属**：原来红字一条、按钮一条，两条之间没有结构关系，
并排之后按钮贴着自己解释的那句话。

## ③ demo 夹具里同一个设置出现两次（夹具与真实不同构）

`{#if DEMO}` 块里另加了一份「送进模型的最近原文条数」滑块，
而真实分支的「上下文」小节里也有同一个 ⇒ demo 上**第 1 屏顶部一颗无标题的
滑块、第 3 屏「上下文」下一颗**。夹具自己的注释写着「形状与真实分支同构」。

⚠⚠ 它当初为什么被搬到第一屏：「出图只到那个标签就被纸底切掉」。
**那是上面那条量具 artifact**——逐屏滚动拍出来好好的，在第 3 屏中部。
⇒ 删掉夹具那份副本。「看不见等于没改」这条教训没错，
错在它把量法的锅算到了布局头上。

## ④ 红字在暖黄纸上不达 AA（`--cs-live` 4.28 : 1）

| 类 | 用在哪 | 改前 | 改后 |
|---|---|---|---|
| `.cs-warn` | 4 处：预算无解 / 没单独 key / 没在本机验证过 / 旧存档两组共用 | `--cs-live` 4.28 | **`--cs-ink` 14.11** |
| `.cs-warn-on` | 1 处：「截图可能认错」 | `--cs-live` 4.28 | **`--cs-live-dim` 5.15** |

- `.cs-warn` 改墨色的**语义**理由：本文件那条定案是「红色只留给那句
  『在你没预期的时候它会这么做』」。这四句讲的全是**配置的事实**
  （这个值不起作用 / 这两组共用一格 / 这家没验证过），不符合那句话的形状。
  符合的是 `.cs-warn-on`。
- `.cs-warn-on` **保留红**（它就是那一句），只换成更深一档的红去过 AA：
  11.5px/600 够不上「大字」豁免（要 ≥18.66px 粗体），差 0.22。
- ⚠ **`.cs-error` 不在这笔账里**（上一轮把它算进去了，是错的）：
  那是**红底白字**，白字对 `--cs-live` 是 5.32 : 1，过 AA。
  ⇒ 「红不达 AA」这件事的边界是**红字红在纸上**，不是「用了红」。

## ⑤ ⚠ 自己改出来的回归：厂商芯片的选中态没了

`.cs-btn-mini.primary` 从红改回墨（票 57 ④）之后，**厂商芯片也变墨**了——
而 `.primary` 的 8 处里只有这一处表达的是**状态**（当前路由是哪一家），
其余 7 处都是**动作**。出图确认：「anthropic」与「openai」字重相同、颜色相同，
**读不出选了哪家**。

⇒ 补 `.cs-chips .cs-btn-mini.primary` 的墨洗底（12% tier-ink 混纸），
与 `SegSlider` 的药丸同一条语言。

⚠ **票 57 ④ 里我写过一句错话**：「未选中那颗本来就是墨色，所以改回墨色
不损失辨识度」。对**动作按钮**成立，对**芯片**不成立——那一句当时没有
逐个用出图复核。

## ⑥ 右上齿轮的灰底**不是** bug，但激活态与悬停态分不开

第一反应是「☀ 带一块灰底、✕ 没有 = 状态残留」。**读代码之后这个判断是错的**：
`.cs-glyph` 有 `class:on={settingsOpen}`，设置屏开着时它就该亮；
`.cs-glyph.on` 的底是 `rgb(20 26 31 / 12%)`。**行为是对的。**

⚠ 但顺手量出一个真的问题：`:hover` 是 **7%**、`.on` 是 **12%**——
**只差 5% 的黑（实测 1.145 : 1 vs 1.265 : 1）**，肉眼分不出
「我现在悬停着」与「这一屏正开着」。

⇒ 底不动，**加 1px `--cs-edge` 内描边**（3.04 : 1，全色板唯一够 3 : 1 的边界色）：
「开着」= 有底**有边**，「悬停」= 只有底。
⚠ 于是「12% 墨洗 + `--cs-edge` 描边」这条载体语言在同一屏出现了三处
（`SegSlider` 药丸 / 厂商芯片选中 / 齿轮激活）——**是有意的，不是巧合**。

## ⑦ `.cs-fail` 那层红底只有 1.18 : 1，读不出「这一块是坏的」

`color-mix(live 12%, transparent)` 叠到纸上实测 **1.184 : 1**，只比纸亮一点点。

| 混比 | 底 vs 纸 | ink 字 vs 底 |
|---|---|---|
| 12%（原值） | 1.184 : 1 | 11.92 : 1 |
| **20%** | **1.326 : 1** | **10.64 : 1** |
| 30% | 1.536 : 1 | 9.18 : 1 |

⇒ 取 **20%**。⚠ 正文色是 `--cs-ink`（不红），它只是分区信号，所以宁可弱。
⚠ 语义边界记一笔：demo 模式那句「演示模式：这里显示的是排版」也走这一格
（同一个 `fail` 字段），而它**不是错误**；真机上那格渲染的是 Rust 传来的内容。

## ⑧ range 滑块没有量程，两端是什么看不出来

「12 条」的滑块范围是 4~40，界面上只给了一个数。拇指位置只说得出
「大概在中间」，说不出「调到 30 会怎样」「已经到顶了吗」。

⇒ 轨道下方补一行量程：`4 条` / `40 条`。

- 10.4px 字号 + **`--cs-pencil`（5.73 : 1）**，不用 `--cs-mark`——
  那支只有 3.51 : 1，且标的是**状态**不是句子；这里读的是数字，
  10.4px 也够不上大字豁免。**字号小不等于对比度可以不要。**
- ⚠ 顺带给 `input` 补了 `aria-valuetext` 与 `aria-describedby`：
  读屏用户拿到的是「12」而不是「12 条，可调 4 到 40 条」。
- ⚠ 对齐那个 `2px` **不是玄数**：`input[type=range]` 的 UA 样式自带
  `margin: 0 2px`，所以它的盒子比 flex 行窄 4px（实测行 46..334、
  轨道 48..237.6）。不补就差 2px。复测：量程行 48..237.6，逐项相等。
