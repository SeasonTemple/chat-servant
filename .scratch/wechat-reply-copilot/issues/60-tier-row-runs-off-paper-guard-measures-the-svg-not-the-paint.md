# 60: 主面板档位行在真机上出纸——而台架在浏览器里判它「没出纸」

**What to fix:** 2026-10-18 起真机 Tauri 窗口（`pnpm tauri dev`，
`hwnd=0xBD0BA4` 「副驾」380×560）实拍到：档位行「只填入」的**下半截在纸外**，
红铅笔勾的**尾笔整段画在纸外**（壁纸透上来）。
而仓库自带的 `ui/static/budget.html` 台架此刻报的是
`PASS drafted: 档位格不出纸 — 底 500 vs 纸底 512`。
⇒ **判据过了，产物是坏的。**

**Status:** open · 2026-10-18 · 验收项 0/5。**其中两条要人拍板**（见「三选一」）。

## 实拍证据（本轮抓的，只出像素统计与裁图，没有把帧灌进会话）

| 量 | 值 |
|---|---|
| 纸的**实心**下沿（沿中线，要求连续 ≥6 行是纸色） | 窗口本地 y ≈ **500** |
| SVG 的**标称**纸底（`512/560`，台架用的参照） | y = **512** |
| 差 | **撕口吃掉约 12px** |
| 档位行文字墨 | 到 y ≈ 502 ~ 510 ⇒ **越出实心纸 2~10px** |
| 纸下沿以下的像素 | y 507~517 只有红像素、**零墨像素** ⇒ 出去的是**勾的尾笔**，不是字 |

裁图：`target/probe/panel-bottom-zoom.png`（面板底部 3× 放大）——
「只填」两字被勾穿过、下半截在纸外；勾的左下笔画画到黄色壁纸上。

## 两个根因（都不在「排版没调好」那一层）

### 根因一：台架的纸底参照**比产物宽 12px**

`budget.html:196` 用 `PAPER_BOTTOM = 512 / 560`，即 **SVG 源图里那张纸的矩形**。
但 `probe-sheet.svg` 的纸**下沿是撕口**，实测实心只到 500 ——
`PaperPanel.svelte` 自己写着「**纸底破口实测 7~11px**」。

⇒ 凡是落在「500 ~ 512」这 12px 带里的东西，台架**一律判过**，
而实际上它们已经在纸上画不动了（底下是透明，能透出桌面）。

⚠ 这是「**判据的参照物必须是产物，不是它的容器**」的第三次：
前两次是「量具压坏布局」「纸底参照物错」，这次是**参照物取自源文件而非画出来的那张纸**。

### 根因二：台架只在「**有候选**」的四个状态下量 `.cs-pick`

真机当时是 `tick=1 peer="" candidates=0 phase=failed`（抓不到会话 / 没 key）。
而台架的 `STATES` 是 `drafted / auto / sent / settings / many` ——
**没有空态**。空态下档位行被 `margin-top: auto` 推的位置与有候选时不同，
而台架一个都没量。

⚠ `settings` 状态下 `pick_clipped = null`（那一屏没有 `.cs-pick`），
断言 `if (s.pick_clipped)` 直接跳过——**「没量到」与「量到没超」在输出上同形**。

## 这不是新问题：票 44 记过一次，没修干净

`PaperPanel.svelte:2091-2096`：

> 纸底破口实测 7~11px，所以留 26px。给文字留的那点不够：
> **实测出图里「只填入」骑在破口上。** ⚠⚠ **26 → 8**（票 44，2026-10-16 真撕边后）。

⇒ 当时只把 `padding-bottom` 从 26 降到 8 就收了工，
**而台架的参照物没跟着改**，于是「降完之后到底出没出纸」这件事**谁也没再量过**。

## 附带发现：台架此刻有两格红，**不是本轮改出来的**

```
FAIL settings: 候选区滚动条 — 槽宽 0
FAIL settings: 设置区滚动条 — 槽宽 0
```

- 「候选区」那一格：settings 状态下**根本没有 `.cs-actions`**，量到 0 是对的，
  但判据把「不存在」报成红。
- 「设置区」那一格：`.cs-set` 的槽宽是 **2026-10-16 票 44 主动归零的**
  （`PaperPanel.svelte:1532` 明写「6 → 10 → 6 → 0」）。
  真实 Windows WebView2 上是经典滚动条、会占 6px；
  **无头 Chrome 的滚动条是 overlay、不占布局** ⇒ 量到 0。
  实测两个视口（380×560 / 378×558）都是 `gutter=0`，与内容高度无关。
⇒ **台架在无头环境里会稳定误报这两格**，而它又不进门禁
（`CONTRIBUTING.md` 第 6 条那一族），所以没人看见。

## 三选一（其中两条要拍板）

| | 做法 | 代价 / 风险 |
|---|---|---|
| **A** | `.cs-pick { padding-bottom: 8 → 20 }`，把整行抬出撕口带 | 候选多时少 12px。**票 44 当年正是为了这个从 26 降到 8** ⇒ 等于翻案，要拍 |
| **B** | 台架把纸画进 `<canvas>`，取**最后一行纸色像素**当纸底 | 只改判据不改版式。**无论选不选 A 都该做**——否则这个洞会再开一次 |
| **C** | 撕口那一带局部加厚纸 | 动 `probe-sheet.svg` 生成器，影响整张纸的观感 |

⇒ **B 是必须的（判据量错了参照物），A / C 需要拍板。**
本轮**没有动版式**：A 等于推翻票 44 的一个已定结论，C 要重跑生成器，
两者都不是能顺手做的事。
