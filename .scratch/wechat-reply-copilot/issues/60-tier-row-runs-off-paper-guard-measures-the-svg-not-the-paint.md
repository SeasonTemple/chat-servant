## 病根一句话

**布局的下边界用的是「纸的矩形」，不是「纸」。**

`probe-sheet.svg` 里那张纸的矩形标称底 = 512，而纸的下沿是**撕口**，
画出来的**实心底 = 496**（撕口吃掉 16px）。凡是拿 512 当纸底的推导，
都会少留 16px。

⚠ 这是「判据的参照物必须是产物，不是它的容器/源文件」的**第三次**。

## 判据一共改了四轮，每一轮都是「量错了对象」

| 轮 | 量的是什么 | 为什么不行 |
|---|---|---|
| 改前 | 写死 `512` | 那是 SVG 的标称矩形，不是画出来的纸 |
| 第 1 轮 | `.cs-set` 的 **border-box 底** | 滚动容器**自己不画东西**（无背景无边框） |
| 第 2 轮 | `scrollTop + clientHeight − paddingBottom` | 那是「滚到底时」的线；用户看的第一屏是 `scrollTop = 0` |
| 第 3 轮 | `.cs-hint` 的布局底 516.2 | 被祖先 `overflow-y: auto` 裁掉，但 498~511 **确实画出来了** |
| **第 4 轮（终）** | **`elementFromPoint` 沿中线逐像素打靶** | 躲得开裁剪、也躲得开「纸的边界不是矩形」 |

⇒ **只换限值、不换被测对象，换出来的是假阳性。**
换完参照物之后必须**重新审计每条判据量的是不是产物**。

### ⚠ 一条判据把「没量到」报成「量到了且合规」

`settings` 状态下 `pick_clipped = null`（那一屏没有 `.cs-pick`），
断言 `if (s.pick_clipped)` 直接跳过。真机那次恰恰是空态
（`tick=1 peer="" candidates=0`）⇒ **出问题的那一屏一次都没被量过**。
现在「没量到」自己报红。

### ⚠ 设置屏的档位行根本不叫 `.cs-pick`

它是 `.cs-tier`（`TierSwitch.svelte`），而 `SegSlider` 那枚勾在票 57 已被摘掉。
两条面板的档位行是**两个组件、两个选择器**，原判据只认前者。

## `.cs-set { margin-bottom }`：方向对、数错了（而且我走过一次弯路）

2026-10-16 已经为**同一个病**打过补丁，写的是
「`.cs-sheet` 内容盒底 540 − 纸底 512 = 28px」。

- `540` **是对的**（`.cs-sheet` 自己有 20px 下 padding，560 − 20）。
- 错的是把**标称矩形 512** 当成了纸底。
- ⇒ 正确的差是 **540 − 496 = 44px**。

⚠ **我一度把 28 改成 16**（以为「要减的只是撕口那 16px」），
结果可视区底从 512 **涨到 524**，比原来更糟。
⇒ **28 不是「多留了 12px」，它是「差值按错的参照物算小了 16」。**
同一个动作在两个方向上都动过，而两次都只验了「值变了」，
没验「可视区底落在哪」——**值变不等于落点变**。

## 对照实验：证明 A 方案真的动了东西（不是无效改动）

改 CSS 会引起连锁反应，只看最终绿不绿不算证据。把 `padding-bottom`
临时改回 8 跑一次台架：

| | 可见最低像素 | 纸实心底 |
|---|---|---|
| `padding-bottom: 8`（改前） | **499**（勾 499.2）⇒ 红 | 496 |
| `padding-bottom: 20`（改后） | **487**（勾 487.2）⇒ 绿 | 496 |

⇒ 改动落在它该落的地方，且幅度（12px）与抬升量一致。

## 滚动条那两格：不是本轮引入，判据改成「不等于 15」

`.cs-set` 的槽宽是 2026-10-16 票 44 **主动归零**的
（`PaperPanel.svelte:1532` 明写「6 → 10 → 6 → 0」）。
真实 Windows WebView2 上是经典滚动条、会占 6px；
**无头 Chrome 的滚动条是 overlay、不占布局** ⇒ 量到 0。
⇒ 判「漏接管」（≠15）比判「设计值」（=6）稳。
`settings` 状态下根本没有 `.cs-actions`，量到 0 是对的。

## 这不是新问题：票 44 记过一次，没修干净

`PaperPanel.svelte` 的 `.cs-pick` 注释（2026-10-16）：

> 纸底破口实测 7~11px，所以留 26px。给文字留的那点不够：
> **实测出图里「只填入」骑在破口上。** ⚠⚠ **26 → 8**（票 44，2026-10-16 真撕边后）。

⇒ 当时只把 padding 从 26 降到 8 就收了工，**而那个 8 的推导前提
（破口 6~13.5px）是 Chromium 出图里量的，出图里纸是完整矩形**，
真机上是撕口 ⇒ 前提不成立，8 不够。
现在按**实心纸边**（496）重推，20。

## 写 `measurePaper()` 踩的坑

把 `await measurePaper()` 放到普通 `<script>` 的顶层 ⇒
`await is only valid in async functions…`。
页面上的表现是 **`document.title` 停在 `budget`、输出区停在 `booting`**，
**看起来只是「还没跑完」，不是「坏了」** ⇒ 自动化探针若只等 title 会死等。
⇒ 包进 `(async () => { … })()`，自证脚本同时抓 `pageerror`。
