# 61: 厂商芯片的选中态违反一致性——墨洗底读成「阴影」，且标记缺失

**What to fix:** 用户 2026-10-18 指出三件事（原话）：
「说了很多次 符合统一、一致性的设计，你tm又把毛胚按钮改回来？
模型选中的阴影又是什么个意思？勾选/圈呢？」

**Status:** done · 2026-10-18 · 验收项 **9/9**

## 三条批评逐条核实（两条成立，一条是我上一轮自己造的）

| 批评 | 核实结果 |
|---|---|
| 「毛胚按钮」 | **成立**。`.cs-chips .cs-btn-mini.primary` 在我 2026-10-18 补回归时只加了一层 `12% tier-ink 混纸` 底色，**没有描边、没有标记**——四颗芯片里只有它是这个画法 |
| 「模型选中的阴影」 | **成立，但根因不是阴影**。`.cs-btn-mini` 全族本来就有 `drop-shadow(0 2px 4px …)`，那是**材质语言**（贴纸片落在纸上）。我加的淡墨洗底**把落影顶出来了** ⇒ 读成「这枚阴影更重」。**状态被材质盖住了** |
| 「勾选/圈呢？」 | **成立**。项目表达「被选中」的既有语言是红铅笔标记（主面板档位行，票 57 保留「盖章式」）。我在芯片上擅自换成淡底，把标记整个丢了 |

## 修法：撤掉墨洗底，改成与主面板同一条语言

- 选中那颗**左侧**画一枚红铅笔勾（`TICK_NESTED` / `TICK_VIEW`，`marks.js` 原样数据）。
- **不选的什么都不画**（主面板原话：「空着就是空着，标记的位置本身就是编码」）。
- 勾放在**左边**而不是右上角：右上角被同一行的「已配置 / 未配置」徽标占着，
  而勾压在字尾上会把 `anthropic` 的尾字母划花（两版出图都拍到了）。
- `.cs-chips .cs-btn-mini { padding-left: 30px }` 加在**整族**上：
  只给选中那颗加 ⇒ 用户点一下，四个标签的左对齐线就跳一下。

⚠ **落影一个字没动**——它是材质，不是状态。状态与材质混成一件，
这才是「那个阴影是什么意思」这条批评的要害。

## ⚠ 顺带挖出的真隐患：`id="pencil"` 有**三份逐字相同的副本**

`PaperPanel.svelte` / `routes/studio/+page.svelte` / `routes/studio/actrow/+page.svelte`
各写了一份红铅笔滤镜，而 `PaperPanel` 自己的注释就写着
「与 studio 那份**逐字相同**——两处各写一份的话，改一边另一边就会悄悄退回单层平涂」。

⚠ **注释写了这件事，但没有任何东西保证它们一致**：
改 `feFuncA` 的 tableValues 时编译器不报、门禁不报、
界面上只表现为「另一处忽然变淡」——**单张截图里根本看不出来**。

⇒ 抽成 `$lib/PencilDefs.svelte`，全仓库 `id="pencil"` 只剩一处
（判据：`rg 'id="pencil"' ui/src` 命中数 = 1）。
这同时让设置屏第一次有了这枚滤镜——它原来**根本没有**。

### ⚠ 漏挂的后果是「元素整个消失」，不是「没效果」

`filter="url(#pencil)"` 引用的是**同一文档**里的 id。
`url(#id)` 找不到目标时，SVG 规范是**整个元素不渲染**。
所以设置屏若直接引用而没挂定义，症状会是「勾整个不见了」，
而且**不报错**——这也是当初没人发现的原因。
⇒ 每个用到红铅笔的界面都必须挂 `<PencilDefs />`。
