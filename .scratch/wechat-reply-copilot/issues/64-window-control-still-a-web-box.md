# 64: 窗口控制那一支还挂在「灰底 + 描边」上，是撕边世界里唯一的方块

**What to fix:** 用户 2026-10-18 贴第四张真机裁图，指顶栏齿轮：
「这么突兀你没有任何想法？」

**Status:** done · 2026-10-18 · 验收项 **10/10**

## ⚠ 真机返工两轮（下面两节是 Chromium 出图之后才发生的）

出图看着对了，**真机实拍又打回两次**。

### 返工① 圈压在纸的**撕口**上

第一版把圈钉在 `top: -3px; right: -4px`。真机出图：红色的圈被撕开的纸边
切成两半，读成「纸边上一道红痕」。

⚠ 而窗口控制本来就贴着纸的上沿——**上面本来就没有位置**。
⇒ 改成**圈心与齿轮同心**。「圈」本来就是圈东西，
   把记号圈进去比挂个角标更贴切。

### ⚠⚠ 顺带量出：`RING_MARK` 在它 84 × 52 的取景框里**本身不居中**

`shot-cpanel.mjs` 量 `RING_MARK` 的墨迹 bbox 中心相对齿轮盒中心：
**−3.7px（横）/ −3.2px（纵）**（36px 宽那档）。
⇒ 校正值写进 CSS 时**换成占自身的百分比**（10.3% / 12.5%），
   改 `width` 不用重量。⚠ 两个百分比分母不同：`translate` 的 X 按宽、Y 按高。
⚠ 它是**笔迹的属性**：换 `RING_MARK` 的生成参数就得重���一次。

### 返工② hover 态是三块 Web 控件（用户真机裁图「这是什么狗屎？」）

同一族的 **hover** 一直没动过：

| | 改前 | 真机读成 |
|---|---|---|
| 齿轮 hover | `墨 7%` **灰圆角块** | 一个网页按钮 |
| 退出 hover | **`--cs-live` 红底 + 白叉** | 一个危险按钮 |
| 旁边 | 撕边纸片 | 纸 |

⚠⚠ **这不是「块不够明显」的问题，是「多了一个形状」。**
把块调淡只让它从刺眼变成像一块脏东西。

⇒ **hover 一律不用底色**。这一族**身上没有纸条**，
`§4.2c` 那个「拿起来」（`translateY(-2px) + 影加深`）无处可拿。
落在纸上的动作只剩两个：**把记号写重** 与 **把记号写红**。

- 齿轮：`--cs-tier-ink → --cs-ink` + **放大 12%**（笔按重了，不是加边框）
- 退出：记号本身**变红**（`--cs-live`），不是红底白叉

⇒ 红从**填充**挪到**墨**，块就没有了。「红只给不可逆」没破
（退出确实不可逆），而「红块 = 危险按钮」这条 Web 惯例不再出现在纸上。

## 症状：它是同一族里**最后一个没换载体**的

票 62 / 63 把 `SegSlider` 的药丸与厂商芯片的选中态都换成了**红铅笔标记**，
而 `.cs-glyph.on` 当时的注释还写着「与那两处是**同一条载体语言**」——
**那句话当天下午就过期了**，只剩齿轮还挂在 `12% 墨洗底 + inset 1px --cs-edge`
上，在一片撕边纸片之间成了唯一的方块。

⚠ 这正是「同一事实有多份副本」的典型：那条注释是**第三份**对载体语言的描述，
前两份被改了，第三份没跟上 ⇒ 它自己成了不一致的**证据**。

## 三轮演变值得逐条留档

每一轮都是「同一族里换一个载体」改出来的，而**前两次只换了载体、没换形状**：

| 轮次 | 做法 | 为什么不够 |
|---|---|---|
| ① 2026-10-14 | 只有 `font-weight` / `color` | 「开着」与「没开」读不出差别 |
| ② 2026-10-16 | 加 `rgb(20 26 31 / 12%)` 底 | hover 是 7%、`.on` 是 12%，**只差 5% 的黑** |
| ③ 2026-10-18 上午 | 再加 `inset 1px --cs-edge` 描边 | 仍是**方块**——形状没变，只是多了一圈边 |
| ④ 2026-10-18 下午 | **底与描边整个撤掉**，改一枚红铅笔圈 | ✓ |

⇒ 关键在于 ③ 以为是「加个描边就能区分」，
可**这一族的其它成员已经被换掉了载体**，不是形状不够明显。

## 为什么是**圈**而不是勾

判据：**容器里有没有字**。

- 主面板 `.cs-pick-name`、药丸、厂商芯片 → **有字** ⇒ 走盖章（`TICK_*`，勾）
- 顶栏齿轮 28×32 → **无字**，而勾的宽是 `3.66em`（实测 54.4px @ 14.85px 字）
  ⇒ **放不下**

「圈住字」要字，「圈住记号」没有字 ⇒ 取 `marks.js` 里本来就为「小」准备的
`RING_MARK`（三道叠画），16×16，钉在记号右上角外沿（`top:-3px; right:-4px`）。

⚠ 票 61 在厂商芯片上**先用过圈、后来换成勾**——芯片有字，所以那次是往勾上换。
两处不是「谁好看」，是**同一判据落在两个容器上得出两个答案**。

## ⚠⚠ `position: relative` 不是可省的

`.cs-glyph` 这一族**从建起来就没有定位上下文** ⇒ `.cs-glyph-ring` 的
`absolute` 一路往上找到 `.cs-sheet { position: relative }`，
圈出现在**面板右上角**（出图里那枚孤零零的红圈），齿轮自己身上什么都没有。

⚠ **症状与「圈画丢了」几乎同形**，只差一个孤立的红点在那儿当证据。
第一版就是先看到「圈不见了」，以为是 SVG 引用问题。

## ⚠ 圈只设 `fill`，不设 `fill-opacity` 兜底

透明度是**笔迹数据**（`marks.js` 每层自带 `o`）。
CSS 兜底会把三道叠画压成单层平涂 ⇒ 圈立刻变成一个生硬的矢量圆环。
同款警告见 `.cs-tick`。
