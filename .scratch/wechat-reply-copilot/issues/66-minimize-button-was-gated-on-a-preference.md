# 66: 「收进托盘」不是缺的，是被挂在一个偏好上——默认档下用户收不起来

**What to fix:** 用户 2026-10-18 看着真机顶栏问：
「右侧顶部是否还差了一个最小化按钮？」

**Status:** done · 2026-10-18 · 验收项 **9/9**

## 结论先说

**按钮一直在**，`ui/src/lib/PaperPanel.svelte` 里写着「收进托盘 · 程序继续运行」，
Rust 侧 `hide_panel` 也是现成的。真机只有两枚，是因为它被包在

```svelte
{#if closeBehavior === 'tray'}
```

里，而**默认档是 `exit`**（`CloseBehavior::default()`，注释：「新装一个替你说话的程序，
用户不该一关窗口它就悄悄跑着」）。

`git log -S` 查到这道门是 `6f10f9f`（2026-10-13）随「窗口记号不再复用 lucide」
一起写的——**不是一次「否决最小化」的决策**，只是当时顺手写成了条件渲染。

## 为什么这是缺陷而不只是「少一颗按钮」

`decorations: false` + `skipTaskbar` ⇒ 这个窗口**不在任务栏上、也没有系统标题栏**。
于是默认档下：

- × = 退出 ⇒ 关掉就没了
- 托盘活着（`build_tray` 跑成了），但**面板回不来**
- 用户想「先收起来」的唯一办法是**去设置里把偏好永久改成 `tray`**

⇒ **拿一个持久偏好当临时动作的门票。** 这两件事根本不是一回事：

| | 是什么 | 该由什么决定 |
|---|---|---|
| 「收进托盘」这一枚 | **能力**（能不能把面板弄下屏而程序继续跑） | 托盘**能不能用** |
| 「关闭窗口时怎么办」 | **偏好**（按窗口控制键时退出还是收起来） | 用户设过一次 |

⚠ 这条与硬约束同源：面板**必须**有一个用户能自己关掉的出口。
`docs/设计规范.md` §「窗口控制」那节写的就是「没有『−/×』的面板关不掉——
关了等于一个看不见却还在替人说话的程序」。**那一节要的是 − 和 × 两颗，
当时只补了 ×。**

## 改法

1. **前端**：`{#if closeBehavior === 'tray'}` ⇒ `{#if trayReady}`。
   条件从**偏好**换成**能力**。
2. **Rust**：加 `tray_ready() -> bool`（判据是 `tray_usable()`，**不是**「图标在不在」——
   `Pending` 与 `Failed` 不是同一件事，只有**明确失败**才配降级）。
3. **`hide_panel` 补守卫**：托盘不可用时**主动拒绝**。
   ⚠ 这不是提示，是**前置条件**：那个窗口一旦隐藏，
   **没有任何系统途径能再叫回来**（无标题栏 + 不在任务栏）。
   托盘建不起来还让用户按它 = 造一个看不见、找不回、还在替人说话的进程。
4. **空 catch 换成 `console.error`**：原来 `.catch(() => {})` 会把上面那条拒绝
   连原因一起吞掉，表现成「按了没反应」。这正是 AGENTS.md 里
   「空的 `catch {}` 会把这类 bug 藏到看不见」那条。

### ⚠ 一处刻意不动

`trayReady` 默认 `true`，**问不到也不改**。
`hide_panel` 自己会再挡一道；两道都当成「托盘没了」的话，
**一次 IPC 抖动就会让「收进托盘」整枚消失**——而它消失的代价是用户再也收不起来。

## 真机实测

| 步骤 | 结果 |
|---|---|
| 起 dev，`closeBehavior = exit`（默认） | UIA 列出**三枚**：`设置` (370,112) `收进托盘` (400,112) `退出` (430,112) |
| 点「收进托盘」 | `winscan` 里**面板消失** |
| 同一时刻查进程 | `chat-servant-app` PID **19080 仍在** ⇒ 观察循环没停 |
| 门禁 | 14 步 ALL GREEN，`GATE_EXIT=0` |

⚠ **没有验的**：`show_panel` 的托盘回程没点（Win11 托盘溢出区坐标不可信，
点错会点到别的东西）。「托盘 → 显示面板」这条路径**本轮未实测**，
它与本次改动无关（`show_panel` 一行没动），但「能不能回来」这件事
我只在**代码层面**确认（托盘菜单项存在 + `show_panel` 未改）。
