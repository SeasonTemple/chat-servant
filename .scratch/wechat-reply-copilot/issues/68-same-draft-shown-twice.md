# 68: 面板把同一句话显示两遍 —— 正文行与首选候选是同一个 `candidates[0]`

**What to build:** 让「已经起草好的那一句」在面板上**只出现一次**，且**不丢掉它的可点入口**。

**Status:** ready-for-human · **2026-10-19 已改完并过门禁与实机 DOM 复核；
但**真机点一次**仍未做（要真实微信会话）。⚠ 拍板不是我做的，是查出来的——
见下方「根本不是取舍」。**

## ⚠⚠ 原稿把结论写错了（2026-10-19 订正）

原稿写「修法二选一，保留哪一处**需要用户拍板**」。**那是伪取舍**，
起因是我只读了 `:194` 与 `:204` 两个派生式，没往下读到布局注释。

`PaperPanel.svelte:983` 的布局注释写着：

> **正文写的是第一条候选**，按钮就排在这一组下面 —— 「看这句 → 按它」中间不插别的东西。

⇒ **「正文 = 第一条候选」是设计，不是 bug。** 真正多余的只有动作区那份，
而它存在的理由是「**可点**」——正文那条原本不可点，只是文字。

所以正解**不是砍掉任何一边**，而是**让正文行自己可点**，两边职责合并：

| | 原先 | 现在 |
|---|---|---|
| 正文行 | 纯文字，第一条候选 | **可点的第一条候选**（`cs-draft-lead`，复用 `dispatchCandidate`） |
| 动作区 | 渲染全部候选（含第一条） | 只列**备选**（第 2 条起） |

**没有丢任何可点入口**，也没有删任何设计。

⚠ **为什么不能反过来**（只砍动作区那条、不改正文）：
票 20 的两档发送是安全模型，动作行是它唯一的可点对象。
正文行不可点 ⇒ 首选就没有点击入口 ⇒ 票 20 验收无从做起。

## 改了什么

- `altCandidates`（`:204` 附近）：`slice(1)` 并在数据层带上**原始下标** `index`
- 模板：正文包成 `<button class="cs-draft-lead">`；`{#each}` 改遍历 `altCandidates`
- 新样式 `.cs-draft-lead`：`all: unset` + `text-align: inherit` + 极淡 hover
- 动作区容器条件**仍是 `allCandidates.length > 0`**（不是 `altCandidates`）

### ⚠⚠ 踩了两次同一个坑（都记在代码注释里）

`{#each ... as c, i}` 的 `i` **永远是过滤/切片后数组的序号**。
两条路都错：

1. `{#each allCandidates.filter((_, i) => i > 0) as c, i}`
2. `allCandidates.slice(1)` 配普通 `{#each ... as c, i}`

后果实测到：**第一条备选拿到 `i === 0`**，于是它被渲染成
`cs-act-lead cs-act-is-lead` + aria-label「按这个候选」+ 墨色手绘勾
⇒ **面板上出现两条自称首选的候选**，且票 44 验收项
「三变体分工仍然成立」当场失效。

⚠ autofixer 对此**零告警**、svelte-check **0 错**——
静态工具看不出「两条都自称首选」，是**查 DOM 才发现的**。

⇒ 修法：数据层就把原始下标带出来（`row.index`），模板里一律用它。

### ⚠⚠ `Auto` 档的不可逆警告差点被一起删掉

首选移进正文行后，它**在 `Auto` 档下同样是点一下就发出去**。
若把动作区容器条件改成 `altCandidates.length > 0`，
则「只有一条候选」时（`altCandidates` 为空）整条红字警告消失
⇒ 用户点正文行那条直接发出去，屏幕上**一个不可逆提示都没有**。
⇒ 容器看**全部候选**，纸条列表才看备选。

### ⚠⚠ `opaque backgrounds` 守卫拦下了 hover 底色（票 59 的价值）

`.cs-draft-lead:hover` 第一版写的是 `background: rgb(24 18 10 / 4%)`。
`check-opaque-bg.ps1` 直接红：

> Tauri 透明窗口 + WebView2 分层合成会把半透明底色**整层不绘制**，
> 而浏览器里它画得好好的 ⇒ 这类错只有真机窗口能看见。

⇒ 那处 hover 反馈在真机上会**完全消失**，而 autofixer / svelte-check /
eslint / prettier **全部是绿的** —— 静态工具一个都没报。
改法：`color-mix(in srgb, var(--cs-ink) 4%, var(--cs-paper))`。

⚠ 这是票 59 那条守卫建仓以来第一次拦到**我自己新写的**代码，
      之前它只在既有代码上防回归。记一笔：它抓的不是回归，是新增。

## ⚠⚠ 这**不是 demo 图例**，真机一样

用户原问是「这部分还有显示的价值？还是只是 demo 图例」。查下来：

**demo 与真机走的是同一条代码路径**，夹具与运行时喂给面板的是同一份
`ReadoutPayload`。根因在派生式上，与数据来源无关：

```svelte
// ui/src/lib/PaperPanel.svelte:194
const drafted = $derived(readout?.phase === 'drafted' ? (readout.candidates[0] ?? null) : null);

// :204
const allCandidates = $derived(readout?.phase === 'drafted' ? readout.candidates : []);
```

`:194` 的 `drafted` 喂给正文行（`cs-draft-text`，`:924`），
`:204` 的 `allCandidates` 喂给动作行 —— **两者第一个元素是同一条记录**。

⚠ `:196~203` 那段注释还写着「`drafted` 只给了第一条（正文行渲染的就是它）」，
即**这是被写进注释的已知事实**，不是偶发。

⇒ 只要 `phase === 'drafted'` 且候选非空，**面板必然重复显示一次**。

## 为什么这是缺陷而不只是「冗余」

1. **它吃掉最贵的空间。** 面板高 560、`padding-bottom: 20` ⇒ 内容底在 **540**，
   而档位格底 **530.6** ⇒ 可用纵向只剩 **9.4px**（`docs/设计规范.md` §4.2c-bis 实测）。
   重复一遍的首选候选占掉 3 行 × 31.5px ≈ **95px** ——
   这是「哪一条候选能放下」的**直接决定因素**（票 44 实测 3 条就要滚、5 条只露 2.2 条）。

2. **它让「首选」失去意义。** 首选已经写在正文里了，
   用户在候选区再看到一次，读成的是「同一件事列了两遍」，
   而不是一个待挑选的选项。

3. **两处字重/字体不同 ⇒ 读成两种东西，内容却相同。**
   正文是仿宋 21px 墨色、候选是纸条 + 手绘勾，
   于是同一句话以两种「身份」出现两次 —— 这比字面重复更让人怀疑是不是有 bug。

## ⚠ 附录：为什么不能简单「删掉 `cs-draft-text` 那一支」

它同时是「起草中」「没写成」「对方说完了，这轮没起草」
「对方说完话，这里才落笔」四个态的容器（`:923~971`），
外加面板唯一 `user-select: text` 的地方（正文要能选中复制）。
⇒ **正文行必须留着**；动的只有「它可不可点」。
