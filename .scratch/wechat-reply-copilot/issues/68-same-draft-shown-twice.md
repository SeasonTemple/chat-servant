# 68: 面板把同一句话显示两遍 —— 正文行与首选候选是同一个 `candidates[0]`

**What to build:** 让「已经起草好的那一句」在面板上**只出现一次**。

**Status:** needs-triage · **2026-10-19 用户截图发现，根因已定位到行，未改**

## 现象

2026-10-19 用户截图（`drafted` 态，`?demo=1&state=drafted`）：

```
示例联系人
行，不急
┌──────────────────────────────────┐
│ 30s 确实短了。我看了日志，请求在   │  ← 正文行（cs-draft-text，仿宋 21px）
│ 第 28 秒才进到下游。我改成 90s…    │
└──────────────────────────────────┘
┌──────────────────────────────┐ 70%│  ← 首选候选（cs-act-lead）
│ 30s 确实短了。我看了日志，请求在第 │ ✓│     **同一句话**
│ 28 秒才进到下游。我改成 90s…       │  │
└──────────────────────────────┘    │
```

**逐字相同的两句话，上下相邻。**上面用仿宋正文体，下面用候选纸条。

## ⚠⚠ 这**不是 demo 图例**，真机一样

用户原问是「这部分还有显示的价值？还是只是 demo 图例」。查下来：

**demo 与真机走的是同一条代码路径**，夹具与运行时喂给面板的是同一份
`ReadoutPayload`。根因在派生式上，与数据来源无关：

```svelte
// ui/src/lib/PaperPanel.svelte:194
const drafted = $derived(readout?.phase === 'drafted' ? (readout.candidates[0] ?? null) : null);

// :204
const allCandidates = $derived(readout?.phase === 'drafted' ? readout.candidates : []);
```

`:194` 的 `drafted` 喂给正文行（`cs-draft-text`，`:924`），
`:204` 的 `allCandidates` 喂给动作行 —— **两者第一个元素是同一条记录**。

⚠ `:196~203` 那段注释还写着「`drafted` 只给了第一条（正文行渲染的就是它）」，
即**这是被写进注释的已知事实**，不是偶发。

⇒ 只要 `phase === 'drafted'` 且候选非空，**面板必然重复显示一次**。

## 为什么这是缺陷而不只是「冗余」

1. **它吃掉最贵的空间。** 面板高 560、`padding-bottom: 20` ⇒ 内容底在 **540**，
   而档位格底 **530.6** ⇒ 可用纵向只剩 **9.4px**（`docs/设计规范.md` §4.2c-bis 实测）。
   重复一遍的首选候选占掉 3 行 × 31.5px ≈ **95px** ——
   这是「哪一条候选能放下」的**直接决定因素**（票 44 实测 3 条就要滚、5 条只露 2.2 条）。

2. **它让「首选」失去意义。** 首选已经写在正文里了，
   用户在候选区再看到一次，读成的是「同一件事列了两遍」，
   而不是一个待挑选的选项。

3. **两处字重/字体不同 ⇒ 读成两种东西，内容却相同。**
   正文是仿宋 21px 墨色、候选是纸条 + 手绘勾，
   于是同一句话以两种「身份」出现两次 —— 这比字面重复更让人怀疑是不是有 bug。

## 修法（不定，需要拍板保留哪一处）

| | 删正文行 | 删首选候选 |
|---|---|---|
| 面板纵向 | 省 3 行 | 省 3 行 |
| 少了什么 | 「起草好了」这件事**没有落点**——正文是它唯一的呈现 | 用户少一个「直接点它」的入口 |
| 现状是否依赖 | `cs-draft-text` 承载 6 个态（drafted/drafting/failed/idle/空…） | — |

⚠ **不能简单删掉 `cs-draft-text` 那一支**：它同时是
「起草中」「没写成」「对方说完了，这轮没起草」「对方说完话，这里才落笔」
四个态的容器（`:923~971`）。删掉首选候选行比删正文行影响面小，
但那会让「首选」失去可点对象，而票 20 的两档验收依赖动作行存在。

⇒ **我倾向**：正文行保留（它是「落笔」的落点，也是唯一能选中复制的整段），
动作区**不再重复首选那条**，只列第 2 条起（并保留 `aria-label` 里的顺序信息）。
但这属于产品取舍，**需要用户拍板**，不自行执行。
