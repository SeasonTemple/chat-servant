# 70: 配置动作被「有没有传输」挡住——全新安装走不完第一步，外加两处会泄 key 的错

**What to build:** 让「选厂商 → 填 key → 测连通」这条链**在没有 key 的时候也能走**，
并且保证 key 永远不会被送到别家、也不会在界面上露出明文。

**Status:** done · **2026-10-20 真机跑通「填 → 保存 → 写入凭据管理器 → 测连通」，四条缺陷全修，门禁十六步全绿**

## 起因：票 40 的最后一项跑不动

2026-10-20 为了把票 40 的最后一项（用真 key 走一遍）在真机上跑掉，
去点设置页的「MiniMax」——**点不动**。界面在那一节的末尾回了一句：

```text
还没接上真实传输（没有可用 key），所以现在没有模型可选
```

那句话是 Rust 侧的 `no_transport_note()`，它作为**错误**从 `set_route` 返回。

⇒ 于是票 40 剩下的那一项**根本走不到**：
key 只能存给默认那家（OpenAI），而本机的 key 是 MiniMax 的；
连「测连通」也点不出结果（`probe_key` 同样要那格）。

## 四条缺陷（同一个根：**配置被挂在传输上**）

| | 现象 | 后果 |
|---|---|---|
| **D1** | `set_route` / `set_model` / `probe_key` 都要求「已经有传输」，而传输要 key 才存在 | **全新安装选不了厂商、测不了连通**；key 只能存给默认的 OpenAI ⇒ **只有 OpenAI 用户能完成首次配置** |
| **D2** | key 烤进 `HttpReasoner`（没有 `set_key`），传输是启动时构造的 | 刚存下的 key **要重启才生效**，而界面写「下一次生成立即生效，不用重启」⇒ **那句是假话** |
| **D3** | `ask()` 每次从**活格子**里读路由，key 却是**固定**的那一把 | 换厂商后 **A 家的 key 被送到 B 家的服务器上** ⇒ **密钥泄漏**（症状只是 401） |
| **D4** | 模型名输入框（`type="text"`）与 key 输入框**绑同一个** `drafts[g.id]` | 填 key ⇒ **明文 key 躺在明文框里**（真机截图实拍）；填模型名 ⇒ **模型名被当 key 存进凭据管理器** |

D4 是**真机才暴露的**：读代码能看见，但只有把 key 填进去再截图，
才看得见「密码框掩着、旁边的文本框里却是 `sk-…`」。

## 修法

### D1：格子（配置）与传输（运行时）分开

- `AppState.models`：`Option<ModelGroups>` ⇒ **`ModelGroups`**（永远存在）。
  那两格是**配置**（走哪一家、哪个模型名），而「有没有传输」是运行时的事。
- `set_route` / `set_model` / `probe_key` 不再要求已有传输。
- 模型清单**仍然**按「这一路有没有 key」给（没有 key 就不列）——
  这一条保留了原设计的意图（「不列点了什么也不会发生的模型」），
  只是判据从「程序此刻有没有传输」改成「**这一路**有没有 key」。

### D2：传输按「当前格子 + 当前凭据」重建

- 循环每圈比一次**传输指纹**（两组各自的「厂商 + 那把 key」的哈希），
  变了就按当前格子重建传输 ⇒ 改了设置**下一圈就生效，不用重启**。
- 指纹**只哈希不留 key 本身**（它要进日志）。
- ⚠ 启动时的指纹**随传输一起交出去**：循环线程起来时全局状态可能还没建好，
  那时自己算会得到「没有」，第一圈就会误判成「传输变了」而白重建一次。

### D3：key 与厂商必须对上

- `HttpReasoner` 记下「这把 key 属于哪家」，发请求前核一次：
  对不上就**当场拒发**（不把 key 送出去再等一个 401）。
- 兜底之外还有一层：`build_reasoner` 按**当前这一格的厂商**去找 key，
  找不到就**没有传输**（退回预置），而不是拿旧 key 去问新厂商。

### D4：两个草稿变量

- 新增 `modelDrafts[g.id]` 给模型名，`drafts[g.id]` 只归 key。
- `commitModelName` 改用 `modelDrafts`。

## 顺带记下的一条量具坑

- **WebView2 的可访问性树会被合成按键弄掉**：用「Alt 解锁 + `SetForegroundWindow`」
  抢前台时，那一下合成 Alt 会让 Chromium **清空 AX 树**（查下去只剩 1 个元素）。
  而**真实鼠标点击**既能激活窗口、又不弄坏树。
  ⇒ 脚本里不要用 Alt 那招；树掉线后**点一下面板**就回来。
- 另有一次「树只剩 1 个元素」是在 `ValuePattern.SetValue` 之后；同样点一下就回来。
  ⚠ 树掉线时**读不到 ≠ 控件没了**：截图显示页面一直活着（面板照常渲染）。
