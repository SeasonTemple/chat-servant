# 73: 采集恢复了，界面还挂着「没写成：抓不到：窗口已最小化」

**What to build:** 采集失败之后，**恢复的那一轮必须把界面拉回正常态**；
界面上显示的必须是**当前状态**，不能是上一轮留下的过期错误。

**Status:** done · **2026-10-20 真机复验通过（最小化→还原，面板自动回到正常态）；
门禁十六步全绿**

## 起因：票 21 的 S6 要「制造一次采集层故障」

S6（出错态）造不出来——它要的是**采集层**故障（抓不到窗口 / 全黑帧 /
裁不出消息区 / 学不到配色），不是模型层失败。

⇒ 于是真机上把**微信窗口最小化**：那一帧抓不到 ⇒ 采集失败。

## 症状（真机，2026-10-20）

1. 最小化微信 ⇒ 应用日志 `emit readout tick=33 phase=failed peer="小号" messages=3 candidates=0`
   ⇒ 面板挂上错误（**S6 这一态在真机上可达** ✓）。
2. **把窗口还原** ⇒ `rect 896,2 - 2071,902`、`iconic=False`、
   日志回到「一轮 1062ms」且**不再有任何错误** ⇒ **采集已经恢复**。
3. **而面板一直挂着那句错误**：

   ```text
   没写成：抓不到：窗口已最小化——还原它才能抓到
   ```

   ⇒ 用户**明明已经还原了窗口**，界面还在催他还原。
   ⇒ 而且它不会自己好：直到对方再发一条新消息，界面才会动。

## 根因：界面显示的是**最后一帧**，不是**当前状态**

观察循环有三支：

| `step()` 的结果 | 推不推帧 | 说明 |
|---|---|---|
| `Ok(Some(..))` | **推** | 有新内容 |
| `Ok(None)` | **不推** | 「什么都没变」——静默期（硬约束第 6 条） |
| `Err(..)` | **推**（`Phase::Failed`） | 这一轮跑挂了 |

采集恢复后的**第一轮**恰好是 `Ok(None)`：画面与最小化前**逐字节相同**
⇒ 水位线不推进 ⇒「什么都没变」⇒ **不推**。

⇒ 于是**没有任何一帧**把界面从失败态拉回来。界面停在最后一帧（失败帧），
而机器已经好了。

⚠ 这不是「恢复得慢」，是**恢复这件事根本没有对应的推送**。

## 修法（方向唯一）

**失败之后的**第一轮成功**必须补一帧正常态。**

1. 循环里记一个 `last_failed`（上一轮推的是不是 `Failed`）。
2. 把「推不推帧、推什么」抽成**纯函数**，才能测：

   ```rust
   fn phase_to_push(s: &Scratch, changed: bool, last_failed: bool) -> Option<Phase>
   ```

   - `changed`（有内容变化）⇒ 推；
   - `last_failed`（上一轮是失败）⇒ **也推**，哪怕这一轮什么都没变；
   - 两者都不成立 ⇒ **不推**。

3. ⚠ **另一半必须同时成立**：`last_failed == false` 时**不许**推。
   那是「静默期零调用」（硬约束第 6 条）：每一圈都推一帧，
   前端就被白刷一遍，界面上的「安静」也没了。

⇒ 阶段本身仍由 Rust 判（`current_phase`：**有没有候选**决定 `Read` 还是 `Drafted`），
界面不猜。

## 守卫

`a_failure_is_followed_by_a_normal_frame_once_the_capture_recovers`
（`watch.rs` 的 `mod tests`），三条断言 + 一条接线断言：

| 断言 | 锁住哪一条 |
|---|---|
| `last_failed == false` 且没变化 ⇒ **不推** | 静默期零推送（硬约束第 6 条） |
| `last_failed == true` 且没变化 ⇒ **推**，且**推的不是 `Failed`** | 恢复后必须补一帧正常态 |
| `changed == true` ⇒ 推 | 有变化照旧推 |
| 源码里「什么都没变」那一支**真的调了** `phase_to_push` | **函数测了但忘了调 = 空守卫** |

### 自证（拆掉修复 ⇒ 对应测试红）

| 组 | 拆什么 | 结果 |
|---|---|---|
| S3 | `phase_to_push` 里的 `changed \|\| last_failed` 去掉 `\|\| last_failed` | 该守卫**红**（报「失败之后必须补一帧」） |

## 遗留与边界

- ⚠ **恢复帧推的是「当前已有」的状态**（候选还在），不是「重新起草」。
  用户如果已经手动处理过那几条候选，界面仍会显示它们——
  这是「不替用户决定」的选择：**程序不替人删掉已经生成的东西**。
- ⚠ 失败期间**读到的消息与候选都保留**（`Phase::Failed` 里带 `messages`），
  这一条本来就是设计（一个 OCR 抖动不该把整段对话清空）。
- ⚠ `Auto` 档在失败恢复后的行为**没单独验**（`AutoGate` 的自动发送路径）。
