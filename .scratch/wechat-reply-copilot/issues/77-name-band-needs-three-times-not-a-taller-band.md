# 77: 读会话名那条路读不到名字——真因是**放大倍数 2× 不够**，不是带高太窄

**What to build:** 查清「读会话名」那条路在 WinRT 回退路径下读不到名字的**真因**，
修掉它，并把**量错了变量的两张错表**一起订正。

**Status:** done · **2026-10-21 定位并修完（名字带子改 3×），并订正了本票上一版写下的错表**
· 遗留一条**本机专属**的端到端验证（生产那条路没在真机上跑过，见验收项最后一条）

## 起因：找「还有哪些地方自己拼 OCR 配方」时捞出来的第二条路

票 41 的 ③ 把重采样变成**引擎的属性**之后，生产里还有一处**手写配方**：
`ui/src-tauri/src/watch.rs::peer_name_from_header`（**读会话名**）自己裁一条带子、
自己放大、自己喂 OCR。它与消息那条路**不是同一套配方**。

## ⚠⚠ 这一轮我先后写下**两张错表**，两张都是**量错了变量**

**错表 ①（2026-10-07 就在代码注释里）**：「40px 0 行 / 60px 1 行 / 100px 1 行」。
今天复现不出来（原始带子已不可考），而且当时**只量了一个倍率**。

**错表 ②（本票第一版，我自己写的）**：「PP-OCR 40~200px 全稳、
WinRT 要 200px 才稳、140px 反而更差」——**那张表是在放大 2× 下去扫带高**，
于是把「**2× 读不到**」读成了「**这个带高读不到**」。

⇒ 教训（已写进 `docs/HANDOFF.md` §4.12 与 ADR-0006）：
**先问「我这次只动了哪个变量」**。
带高与倍率是**互相独立**的两个变量，只动一个去扫，结论就可能整条反过来。

## 口径（这次只动一个变量：倍率）

按**生产几何**复刻那条带子：真机帧 `chat.y0 = 31`、推导出的头部行 y49..61
⇒ 带子 = (308,31)-(708,91) = **400×60**（`target/probe/name/`，不入库）。
**只改放大倍数**：

| 倍率 | PP-OCR（默认） | WinRT（回退） |
|---|---|---|
| 1× | 1 行 / 2 字 ✓ | 0 行 ✗ |
| **2×** | 1 行 / 2 字 ✓ | **0 行 ✗** ← 原先这条路的倍数 |
| 3× | 1 行 / 2 字 ✓ | 1 行 / 2 字 ✓ |
| 4× | 1 行 / 2 字 ✓ | 1 行 / 2 字 ✓ |

两个**对照**（各自也只动一个变量）：

- **带高不是变量**：36px 与 60px 两种带子，在同一倍率下结果**完全一样**；
- **颜色也不是变量**：原色与反色结果一样。

## ⚠ 顺带纠正探针一处**标签骗人**的地方

`xtask perceive` 那段「原色 / 反色」对照里，**反色**那一遍其实是
把 2× 的视图**再放大一次**（**4×**）⇒ 它能读到是**倍率**的功劳，**不是反色**。

⇒ 不查清楚，就会把「反色有用」当结论写进生产代码——
这也是「**探针必须和产品走同一条路**」的一个实例：
探针打印的那行「OCR 读到的会话名」走的是**整帧 OCR 的归类结果**，
产品走的是**窄带 OCR**——**两条不同的路**。

## 修法

- `PEER_NAME_UPSCALE = 3`（**新常量，这条路自己的**）：
  倍数不再沿用消息那条路的 2×。
  ⚠ 窄带的倍率需求**与整帧相反**：消息路 2× 是拐点、4× 反而更差；
  这里 2× 不够、3× 才够。
- `peer_name_from_header` 的**重采样方式**改为跟引擎走
  （`ocr::engine().resample()`）⇒ 不再有第二份会漂的配方。
  实测**换重采样对读数零影响**（两个引擎在各自能读到的倍率上逐字相同，编辑距离 0）。

## 守卫

`the_watch_layer_does_not_hand_roll_the_ocr_recipe` 扩展到这条路上：
不许出现 `upscaled_nearest` / `upscaled_bilinear` / `Resample::`、
必须向引擎要配方、**不许沿用消息那条路的 `OCR_UPSCALE`**；
另加 `the_name_band_scale_is_three`（钉住倍数是 3）。

⚠ **四个方向都实测会红**：注入 `upscaled_nearest`、注入 `Resample::Nearest`、
注入 `OCR_UPSCALE`、把倍数退回 2 ⇒ 前三个红在接线那条守卫上，
最后一个红在倍数那条守卫上。

⚠⚠ 顺带踩了一个**门禁级**的坑，记在这里免得下一个人再写一次：
「把常数钉住」的守卫**不能**写成 `assert!(PEER_NAME_UPSCALE >= 3)`——
它的条件是**编译期常量** ⇒ clippy 的 `assertions_on_constants`
判它「这个断言的值是常量」而**报错** ⇒ `-D warnings` ⇒ **门禁红**。
⇒ 改成**扫源码里那行字面量**（`const PEER_NAME_UPSCALE: u32 = 3;`）：
倍数被改成 2 就立刻红，且 clippy 不管它。

## 影响面：闸不受影响

身份闸比的是**像素指纹**（`HeaderPrint::is_same` 比二值墨迹掩码的 Dice），
不是名字 ⇒ 读不到名字**不会锁错人、也不会不推理**，
只是面板标题空、提示词里没有对方名。
