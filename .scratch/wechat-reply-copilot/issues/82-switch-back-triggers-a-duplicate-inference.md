# 82: 切回锁定会话会重复推理——静默期零调用被绕过

**Status:** done（2026-10-23 定位、修复；四条守卫 + 四组反向自证；夹具帧真机复验通过）

## 一、现象（用户报出）

> 「还有切换会话的反应耗时 7s+？」

## 二、量化（2026-10-23 真机 + debug 日志）

| 项 | 值 |
|---|---|
| 切走一轮 | 1.00 s（tick）+ 1.79 s（窄带 OCR）+ 0.09 s ≈ **2.88 s** |
| 切回一轮 | 1.00 s + 1.79 s + 0.49 s ≈ **3.28 s** **+ 一次完整模型推理 6~9 s** |
| 静默期一轮 | 1.06 s（1 s tick + 60 ms 抓帧），**零 OCR** ✓ |

⇒ 7 秒里的大头不是 OCR，是**那次多出来的推理**。

## 三、根因：水位线被当成了「屏幕上那块读到哪了」

`PaneWatcher` 这个实例**整个生命周期只服务锁定会话**：`observe` 只在身份闸
开着的时候被调用，也就是只在锁定会话上。⇒ 水位线是**「这个会话读到哪了」**
的凭证，跟屏幕上此刻显示谁**毫无关系**。

可 `park_on_other_conversation` 在停泊（闸关着）时把水位线**退回顶部**。
于是切回来时整段重读 ⇒ `newest` 取的是**本轮 ROI 读到的**对方消息、
**完全不去重** ⇒ **早已看过的旧消息被当成新消息** ⇒ 触发一次完整推理。

三个后果：

1. **绕过硬约束第 6 条**（静默期零调用）——对方根本没说话；
2. 重复推理旧消息（`s.history` 也会被整段再追加一遍）；
3. `auto_gate.begin_new_round()` 被调用 ⇒ **有为旧消息自动发送的风险**。

真机形态：应用日志 `tick=1` 就进了 `phase=drafting`，而对方一条新消息都没发。

## 四、修法：**状态留着，显示清空**

- 停泊时**不再退水位线**，也**不再清空锁定会话的消息流**；
- 停泊期间推给界面的**消息列表恒为空**（面板不许显示别人的会话 ⇒ 票 32 的
  「停泊面板说假话」）；
- 闸从关变成开时**推一帧**，把锁定会话的历史原样恢复
  （否则切回来那一轮很可能什么都没变 ⇒ 不推帧 ⇒ 面板一直停在
  「锁着别的对话，切回来才继续」，而人已经切回来了）。

⇒ 切回来没有新消息时：**零 OCR、零推理**。

顺带：2026-10-11 那个「切走再切回只剩 6 条消息」（票 18 §五）的悬案
也不会再发生——它要的就是历史能恢复，而现在历史本来就在状态里，
不需要靠整段重读长出来。

## 五、复验（2026-10-23，真实 OCR + 生产接缝，零 GUI）

⚠ **这台机器禁止输入注入**（`SetCursorPos` 返回 False，UIA `Invoke` 在微信的
Qt 单元上是空操作）⇒ 改用**夹具帧源**：`CHATSERVANT_FIXTURE` 每轮重读那个
文件 ⇒ **把文件换掉 = 屏幕内容变了**。两张同尺寸的**真机帧**（两个不同会话）。

```text
切走  emit readout tick=8  phase=read peer="文件传输助手" messages=0 candidates=0
      一轮 2028ms（1 s tick + 窄带 OCR）
切回  emit readout tick=15 phase=read peer="小号"           messages=5 candidates=0
      一轮 1739ms
```

- `messages=0` ⇒ 停泊时面板**没有**显示锁定会话的内容 ✓
- `peer="文件传输助手"`（**6 字长名**）⇒ 窄带裁剪**没有把长名字切掉** ✓
- 切回是 `phase=read` 而不是 `phase=drafting` ⇒ **没有重复推理** ✓
- 整段「起草/推理」日志**只有启动那一次**（首帧锁定），切走切回全程为空 ✓
- 停泊期间**没有任何 `roi=` 行** ⇒ 没有 OCR 别人的会话 ✓

## 六、守卫与反向自证

| 守卫 | 钉住什么 |
|---|---|
| `parking_does_not_rewind_the_watermark` | 停泊不退水位线；切回来必须是静默（零 OCR） |
| `closing_the_gate_on_a_different_conversation_keeps_the_history_but_blanks_the_panel` | 状态里历史留着，而推给界面的那份是空的 |
| `returning_to_the_locked_conversation_pushes_a_frame` | 闸重新打开要推一帧，且面板不再是停泊态 |
| `the_gate_closes_and_reopens_over_a_frame_sequence_with_one_watcher` | 真实帧 → 指纹 → 闸，全程一个 watcher |

**反向自证（2026-10-23 实测，四组都红）**：

| 注入的缺陷 | 立刻变红的守卫 |
|---|---|
| 停泊时退回水位线 | 前两条 + 帧序列那条 |
| 关闸时清空消息 | 历史被清那条 |
| 停泊时不清空显示 | 停泊面板说假话那条 + 帧序列那条 |
| 闸重新打开时不推帧 | 切回来不推帧那条 |
