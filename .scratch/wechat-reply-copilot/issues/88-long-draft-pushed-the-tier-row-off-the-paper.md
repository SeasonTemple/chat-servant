# 88: 长草稿把档位行顶出纸外——面板上看着「短」，点一下却「长了」

**Status:** done（2026-10-23 用户报出 → 定位 → 修法 → 量具加一档 → 反向自证通过）

## 一、现象（用户原话）

> 「已发 候选已出 **为何默认长度这么短？点击后又拉长了？**」

⚠ 第一反应容易跑偏：以为是「模型起草得太短」。
**不是。** 是**面板把草稿的下半截裁掉了** ⇒ 看着短；点击填入的是**完整原文** ⇒ 看着长。

## 二、根因：`.cs-draft` 是 flex 项，而 flex 项默认 `min-height: auto`

`.cs-body-col` 是一条 flex 列：归属行 / **草稿** / 候选区 / 档位行。
`.cs-draft` 作为 flex 项**默认 `min-height: auto`** ⇒ **它不肯比自己内容更矮**
⇒ 草稿一长，它就把**候选区**与**档位行**一起顶下去
⇒ 而 `.cs-sheet` 是 `overflow: hidden` ⇒ **档位行被静默裁掉**。

实测（`ui/scripts/shoot-panel.mjs` + `ui/static/budget.html`）：

| 夹具 | 草稿区 | 候选区 | 档位行最低可见像素 |
|---|---|---|---|
| 正常（45 字） | 126px（4 行） | 142px | 487（纸底 496）✓ |
| **长草稿（122 字）** | 撑到 283px | 被挤到只剩 16px | **518 ⇒ 出纸 22px** ✗ |

⇒ 「默认长度短」= 纸的下沿把草稿裁了；
⇒ 「点击后拉长」= 填进输入框的是**完整原文**；
⇒ ⚠⚠ **同一原因还把档位行裁掉了** —— 那是「我现在在哪一档」的唯一显示，
而 **Auto 档不可逆** ⇒ 那是最不能看不见的一行。

## 三、这是票 44 的**漏网之鱼**

票 44 当时为「候选太多会把档位行挤出纸」做过同一件事：
`.cs-actions` 改成 `flex: 0 1 auto` + `min-height: 0` + `overflow-y: auto`
（滚动容器 ⇒ 候选变高**不推**档位行）。

⇒ **草稿区当时没跟着改** ⇒ 票 44 修的是「候选太多」，漏了「草稿太长」。

## 四、修法：草稿区与候选区同款

```css
  .cs-draft {
    flex: 0 1 auto;
    min-height: 0;
    overflow-y: auto;
  }
```

⇒ 草稿再长也只占它那块、**自己滚**（滚动条就是「下面还有」的信号，
与高对比度模式下那句「滚动条仍在、条数仍在」一致）⇒
**档位行永远在纸内**，且**没有内容被静默丢掉**。

## 五、守卫（量具那一档 + 反向自证）

- **真夹具**：`ui/static/demo/longdraft.json`（长草稿那一态，**不含真实聊天内容**）。
- **量具加一档**：`ui/static/budget.html` 的 `STATES` 加 `longdraft`
  ⇒ 复用它既有的判据 **`档位格不出纸`**（票 60 留下的「沿中线 `elementFromPoint`
  逐像素打靶」，量的是**真的画出来**的那条底边，不是布局框）。
- **可重复跑**：`node ui/scripts/run-budget.mjs`（新增，headless 跑量具并读判定）。

| 状态 | 档位格最低可见像素 | 纸底 | 判定 |
|---|---|---|---|
| 修后 | 487 | 496 | **PASS**（在纸内） |
| **反证：撤掉修法** | **518** | 496 | **FAIL**（出纸 22px） |

⇒ 守卫**能抓住这个回归**（不是「看着没问题」的那种）。

## 七、仍然没做的

- **草稿长了要滚**这件事本身没解决（纸就那么大：380×560）。
  ⇒ 真解是「纸更高」或「草稿区折叠成 N 行 + 展开」，
  那是**版面设计**的事，不在修这个缺陷的范围里。
  ⇒ 本票只保证「**不静默裁掉、档位行不被顶出纸外**」。
- 「下面还有」的渐隐信号**只给了候选区**（`.cs-actions[data-more]`），
  草稿区靠滚动条 ⇒ 两者不一致（可接受：滚动条也是信号）。
