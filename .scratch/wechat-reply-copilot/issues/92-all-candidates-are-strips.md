## 三、②：我们自己发出去的话，不能被当成对方的新消息

### 现象

`Auto` 档点一条候选 ⇒ 面板回执「可能已经发出去了」⇒ **紧接着又起草了一轮**。

### 日志证据（2026-10-24 真机，`target/probe/app-live-user.log`）

```
17:57:44 本轮新到=1 本轮记到y=Some(580) → drafting → drafted（3 候选）
17:57:58 本轮新到=2 本轮记到y=Some(427) → drafting → drafted（3 候选）
```

⇒ 两轮起草**相隔 14 秒**。

### 为什么不能只靠气泡颜色

归类器按**气泡底色的彩度**判说话人（饱和 = 我 / 近灰 = 对方）。
真机帧实测它**判对了**（绿色气泡 `彩度=91` ⇒ 「我」✔，见
`cargo xtask perceive --file target/probe/wechat-live2.png` 的输出）。

但那是**运气**：探针只要有一次采到气泡缝，彩度就掉到 0 ⇒ 判成「对方」
⇒ 那句话成了「对方的新消息」⇒ 触发一次完整推理
⇒ `Auto` 档下还可能**再发一条** ⇒ **自问自答**。

### 修法：判据用**事实**，不用**猜测**

- 装填 / 发送的那一刻，把正文记进「我们说过的话」（`commands::note_sent`，
  32 条 / 10 分钟）；
- 观察层读到的**同一句正文** ⇒ 一律改判成「我」
  （`watch::relabel_our_own`，**在 `absorb_round` 之前**⇒ 账本里也记成我方）；
- ⇒ 判据是**正文**，不是位置、不是颜色、不是时间。

### 日志也改成按说话人拆分

`本轮新到=2` 之后追加 `（对方=1 我方=1）` ⇒
**只要「对方=0」却起草了，就是判据坏了**，一眼能看出来。

### 守卫（两条，都做了反向自证）

| 守卫 | 反向自证 |
|---|---|
| `watch::tests::our_own_sent_line_is_not_counted_as_a_new_peer_message` | 把 `note_sent` 弄成空操作 ⇒ **红**，报「我们自己发出去的话被算成了对方说的」 |
| `watch::tests::a_peer_line_we_never_sent_is_left_alone` | 对方的话不许被误改判（否则对方的消息不再触发推理） |
| `commands::sent_registry_tests::only_what_we_actually_sent_is_recognised_as_ours` | 同上第一条 |
| `commands::sent_registry_tests::an_empty_line_is_never_recognised_as_ours` | 空句不认 |

### 残留（写清楚）

对方在 **10 分钟内说了与我们一模一样**的正文 ⇒ 那句被算成我方
⇒ 代价是**少起草一轮**（不是多发），方向是安全的。

## 四、③④：候选**全是纸条**（第一条也是）

### 改法

`.cs-draft-lead`（第一条候选所在的正文位）从 `all: unset` 的**纯文字**
改成**撕边纸条**：同一位图 `strip.png`、同一组边框参数、同一套影、
同一套悬停（「拿起来」）、同一套禁用（收掉投影）。

⇒ 「读」与「挑」的分工仍在，只是不再靠**材质**区分：
第一条**更大**（21px 仿宋）、**墨色**、带**手绘勾**。

### 顺带修掉票 91（正文被横切）

撕边让第一条高 32px ⇒ 长草稿更早被滚动容器切 ⇒
正文区也补上与候选区**同一套**的底部渐隐（`.cs-draft[data-more='true']`），
排版量具新增判据「**正文溢出渐隐**」。

**反向自证**：把那条规则改废 ⇒ 量具立刻红 **5 条** ⇒ 守卫真会响。

### 规范

`docs/设计规范.md` 新增 §4.2c-ter ⇒ 推翻我们自己写下的那句
「**两者材质不同是有意的**」。

## 七、2026-10-24 晚：**形制也统一**（票 92 续）

### 用户原话

> 为什么和下面的两个候选样式不同？百分比置信度没有、勾选的位置奇怪，长度不一致

⇒ 这条是第四节那句「候选都要是纸条」的**下半截**：

⇒ 用户这句话点的正是**剩下那三条**。

### 改法：正文位**不再渲染候选**

不是「把正文位那条也改成纸条」（那样它仍然少一列概率、勾还挂在角上），
而是**正文位退成一句状态句**，动作区列**全部**候选。

| | 全部候选（动作区 `.cs-act`） | 正文位（`.cs-draft`） |
|---|---|---|
| 是什么 | 候选**全部**（第 1 条 = 推荐那条） | **一句状态句**（「起草好了，挑一条用。」） |
| 材质 | 撕边纸条（同一位图、同一组边框参数、同一套影） | 无 |
| 字号 | 14px 雅黑 | 21px 仿宋（与另外几支状态句同族） |
| 墨色 | 第 1 条墨色、其余铅笔灰 | 铅笔灰（状态句一律灰） |
| 概率 | **每条都有** | 无 |
| 推荐记号 | 第 1 条多一枚手绘勾（`.cs-act-mark`，右侧一列、百分比之下） | 无 |

⇒ 推荐那条靠**墨色 + 那枚勾**认出来，其余靠**铅笔灰**退后
⇒ 「读」与「挑」的分工**不再靠材质，也不再靠字号**。

### ②⑥ 的根因：**列宽被内容撑开**（真机逐像素对照，2026-10-25）

两张真机截图（点候选前 / 点候选后）逐带对照：

| | A（点之前） | B（点之后） |
|---|---|---|
| 纸条外框 x | 74..300（宽 227） | 38..336（宽 299） |
| 候选正文墨迹 x | 95..246 | 59..210（左移 36） |
| 百分数墨迹 x | 254..278 | 290..315（右移 36） |
| 档位名 x | 106..230 | 88..291（外扩 79） |
| 纵向 | 11 条原有带 **y 逐行相同** | 同左 |

⇒ **纵向零位移、横向整体重排**，而且是**居中对称**地变宽 72px。

**根因**：`.cs-body-col` 是 `.cs-sheet`（flex 列）的 flex 项，
本该 `align-self: stretch` 撑满 316px，
**但它写了 `margin: 0 auto`** —— flexbox 规定**交叉轴上的 auto 边距会取消 stretch**
⇒ 这一列的宽度退化成**随内容变化**（`max-width: 316px` 只是上限）
⇒ 候选一出现 / 多一条回执 ⇒ **整列跟着变宽** ⇒ 全纸横向重排。

⇒ **⑥「整组阴影都变化」是同一件事**：纸条变宽 ⇒ 投影带变长
（逐像素实测：同一批像素亮度差 ≤ 0.9 lum ⇒ **影没变浓，只是变长**）。

**另有一个独立机制**（第六条的第二半）：`disabled={sending}` 挂在**每一条**候选上，
而 `.cs-act:disabled { filter: none }` 会**收掉投影**
⇒ 一次投递里**整组纸条的影子同时消失**。⇒ 现在只有**被点的那一条**收投影。

### ① 的根因：**两个模型调用回答同一道题**

- 起草段 `SYS_DRAFT`：「probability 是你认为用户会选哪条」；
- 第三段 `SYS_RANK`：「指出用户最可能选哪一条」。

⇒ **同一道题问了两次**，答案可以对不上。
真机实测（2026-10-25）：`第三段挑中了第 2 条 pick=2 total=3`，
而面板上三条的概率是 30% / 50% / 20% ⇒ **被挑中的那条只有 30%**。

⇒ 面板把「显示顺序 = 概率排序」当前提（`PaperPanel.svelte` 那条注释还写着
「Rust 侧 `sorted()` 按 probability 降序」——**2026-10-23 就过期了**）
⇒ 于是「第一条」同时被当成「概率最高」与「推荐」⇒ **自相矛盾**。

⇒ **修法**（票 94 §5 的方向）：**当前选中的那条不显示概率**（那一格放勾），
概率只留给**备选**做对比；并订正那条过期注释。

### ⑤ 的根因与修法

- 勾写死在 `{#if i === 0}` ⇒ **永远挂在第一条** ⇒ 点别的候选它不跟。
- 位置：`position: absolute; top: 100%` 挂在 `.cs-act-meta` 底下
  ⇒ **落在纸条下沿之外** —— 而那正是**会被裁的那一端**
  （票 94 §3 的硬要求）⇒ 真机实拍：勾压在撕口上、探进下一条的间隙。

⇒ **修法**：勾 = **「当前选中的那一条」**（`activeId`），点谁跟谁；
记号**进文档流**、坐在**正文那一行**的右端（进 `.cs-act-meta` 那个固定高度的槽）。

### ③ 的结论

「起草好了，挑一条用。」的**指令那句是多余的**（三张纸条就在下面）
⇒ 收成「**起草好了。**」，与另外三支状态句同一族（只说状态，不下指令）。
⇒ **槽位高度不动**（`.cs-draft` 的 `min-height: 47.5px`）⇒ 候选组不跳位。

### ② 的另一半：正文位高度三态不同

`.cs-draft` 是 flex 项且 `flex: 0 1 auto` ⇒ 候选一多它**被压缩**
⇒ 正文位高度三态 **47.5 / 41.9 / 39.1** ⇒ 候选组顶 **164.4 → 161.6** 漂移
⇒ 39.1px 的框装不下 31.5px 的行 + 16px padding ⇒ **状态句被裁掉一截**。
⇒ 修法：`min-height: 47.5px`（一行 21px 仿宋 + 上下各 8px）⇒ 三态恒定。

### 顺带修掉：回执看不见

回执原来在 `.cs-actions` **里面**（滚动容器）⇒ 候选一多就被推到折叠线以下

⇒ 现在它是候选组的**兄弟节点**（还在列里、档位行之上）⇒ **永远在纸上**。

### ① 排序 = 纯本地按 `probability` 降序（**第三段那个模型调用取消**）

⇒ 面板自相矛盾（主人原话：「为何 11% 的置信度会作为首选？」）。

**改法**（`crates/reason/src/transport.rs` 的 `rank()`）：

- 从「把候选列给模型、模型答一个编号」改成**纯本地** `sort_by`

⚠ **代价（写下来，别忘）**：起草段的自评概率若不准 ⇒ 首选就错

## 十三、2026-10-25：记号与百分数**在纸条里垂直居中**（用户反馈 ③）

### 反馈原文

> 「首选行要不要也显示百分数」现在这样没问题，唯一的问题是这个百分比、选中的显示位置如图，

⇒ 顺带确认：**首选行不显示百分数**这个口径**维持不变**（票 94 §5）。

### 根因：**不是槽内没居中，是槽被 baseline 对齐到了第一行**

实测（`target/probe/probe-slot-center.mjs`，headless Chrome）：

| | 槽内（内容中心 − 槽中心） | 相对正文块（槽中心 − 正文块中心） |
|---|---|---|
| 改前 | **0.0px**（横竖都是） | **−33 / −11 / −21.5px**（三条） |
| 改后 | 0.0px | **0.0px**（三条） |

⇒ 槽**自己内部**一直是居中的（`flex-direction: column` +
`align-items: center` + `justify-content: center`），
错的是 `.cs-act` 的 `align-items: baseline` 把**槽**也 baseline 对齐了
⇒ 槽落在**第一行**的基线上 ⇒ 两行的纸条上它浮在右上角，下面半张空着。
⚠ 判据纪律：**「量偏了多少」要分清「相对谁」**——同一个 0.0px
在「相对槽自己」与「相对正文块」两个参照下是**两个不同的结论**。

### 改法

`.cs-act-meta { align-self: center; }`
—— **只改这一个槽自己在那条 flex 行里的摆法**，
不动 `.cs-act` 的 `align-items: baseline`（正文与纸条之间仍靠基线）。

### 真机复验（WebView2，夹具帧）

### 代价

⚠ 记号不再与某一行正文**同基线** ⇒ 「这一句被批了」那层读法变弱
（变成「这张纸被批了」）。
⚠ 那条读法是 2026-10-25 专门定的（当时为了不被裁掉而进文档流），
现在**主人明确要居中优先** ⇒ 记下来，别再改回去。
