# 94: 推荐那条**没有「最优选」记号**——票 68 之后 `i === 0` 永远不成立

**Status:** done（2026-10-24 用户指出 ⇒ 定位 ⇒ 补勾 ⇒ 手动档墨色 / 自动档红铅笔 ⇒ 量具 49 条全绿）

## 一、用户原话

> 「不加（概率）凭什么看出其是最优选？而且选中项不应该有勾/圈吗？」

⚠ 上一轮我把这句读成「要不要显示概率」，**读窄了**：
后半句才是要害——**面板上根本没有任何一条候选带勾**。

## 二、根因：票 68 之后，`{#if i === 0}` 永不成立

- 票 68（2026-10-19）把**第一条候选挪进正文位**，动作区**从第 2 条起**列；
- 而**勾**的渲染条件写在动作区那几行里：`{#if i === 0}`
  （`.cs-act-mark`，票 44 时代「首选 = 墨色手绘勾」的落点）；
- ⇒ 动作区的 `i` **从 1 开始** ⇒ **`i === 0` 永远不成立**
  ⇒ **面板上任何一条候选都没有勾**
  ⇒ 「哪条是最优选」只能靠**字号 + 墨色**猜，而**墨色那一档还整组被 `.cs-act-red` 覆盖过**
  （票 44 自己记过这个坑：「`Auto` 档下首选正文是铅笔灰，与备选同色」⇒ 靠颜色认首选在 `Auto` 档本来就失效）。

⇒ 票 68 挪走了第一条，却**没把它那一枚勾一起挪走**。

## 三、修法

### 勾挂在**正文位的纸条**上（`.cs-draft-lead`）

- **同一支笔**：`TICK_NESTED` 五层嵌套 + `#pencil` 滤镜
  ⇒ 与档位行那枚红铅笔、与备选区曾经那枚勾，是**同一支笔**；
- **颜色**：手动档**墨色** / 自动档**红铅笔**
  ⇒ 与 `.cs-act-red .cs-act-mark` 同一口径：**红只落在记号上**；
- **绝对定位** ⇒ **不占横向**（正文宽度一点不变），只多 14px 高度。

### ⚠ 位置踩过一次坑（写下来免得再踩）

第一版把它挂在**正文最后一行的下方**（与备选那几行「百分比之下」同一侧）⇒
**长草稿那一档它正好落在被滚动容器裁掉/渐隐的位置** ⇒ **实拍根本看不见**。

⇒ 改挂**纸条的右上角**（贴在正文**上面**一行）⇒
**裁切裁的是下边** ⇒ 记号永远看得见 ✔（2026-10-24 实拍确认）。

⇒ 这条与「票 91 正文被横切」是同一个坑的两面：
**凡是要在长内容里当「提示」的装饰，都不能放在会被裁的那一端。**

### ⚠⚠ 2026-10-25：这条规则**又被违反了一次**（候选全搬进动作区之后）

票 92 续把候选**全部**搬进动作区（每条都是同一种 `.cs-act` 纸条）⇒
记号跟着搬进 `.cs-act-mark`，而它的 CSS 仍是 2026-10-17 那套
**「绝对定位在 `.cs-act-meta` 的 `top: 100%`」** ⇒
**挂在纸条下沿之外** —— 正是**会被裁的那一端**（票 94 §3 自己写的那条硬要求）。

真机实拍（2026-10-25）：那枚勾压在纸条的撕口上、探进下一条的间隙里
（用户原话：「而且这个位置你是觉得很正常嘛？」）。

⇒ **修法**：记号**进文档流**，坐在 `.cs-act-meta` 那个**固定高度的槽**里
⇒ 位置 = **正文那一行的右端** ⇒ ① 不会被裁 ② 与正文同一基线
③ 槽高 16px < 正文行高 21px ⇒ **不占额外高度**。

## 四、验收项

- [x] 根因定位到 `{#if i === 0}` 在动作区**永不成立**（票 68 只挪了候选、没挪勾）
- [x] 手动档：墨色手绘勾，挂在推荐那条的**右上角**
- [x] 自动档：红铅笔勾（与档位开关上那枚同口径）
- [x] 位置**可见性**实拍确认（长草稿那一档也在）
- [x] 不占横向（正文宽度不变）⇒ 排版量具 **49 条判据 ALL GREEN**（档位格 487 ≤ 纸底 496）
- [x] 规范 §4.2c-ter 同步记「推荐那条带勾」
- [ ] **真机复验**：人眼确认这枚勾读成「这是最优选」

## 五、仍然没做的

- **推荐那条要不要也显示概率**：用户 2026-10-24 判「**不加**」
  ⇒ 概率只留给备选做对比用；「最优选」由**这枚勾**说。
  ✅ **2026-10-25 已实现**（第六节）：选中那条的槽里是**勾**，备选的槽里是概率。
  ⚠ 实现的**理由比「挤窄正文栏」硬得多**：概率（起草段自评）与勾（第三段挑选）
  是**两个模型调用对同一道题的两个答案**，真机上它们**会对不上**
  （`pick=2 total=3`，而被挑中的那条只有 30%）⇒ 两个答案同时显示 = 面板自相矛盾。
- 票 90（悬停 0.5° 旋转变糊）：用户判「旋转不是重点」⇒ 降级。

## 六、2026-10-25：勾**跟着选中项走**（用户反馈 ⑤）

### 用户原话

> 点了候选后，再点其他候选为何勾没有切换到选中的候选？而且这个位置你是觉得很正常嘛？

### 根因

- 勾的渲染条件写死在 `{#if i === 0}` ⇒ **永远挂在第一条**；
  而「第一条」是**模型挑的那条**，不是**用户选的那条**。
- 位置那条见上面「位置踩过一次坑」里追加的 2026-10-25 那一段。

### 改法

| | 改前 | 改后 |
|---|---|---|
| 勾挂在哪 | 恒第 1 条（`i === 0`） | **当前选中的那一条**（`activeId`，点谁跟谁） |
| 墨色（`cs-act-is-lead`） | 恒第 1 条 | **跟着选中项**（与勾同一口径） |
| 勾在哪个位置 | 百分比**之下**（纸条下沿之外） | **正文那一行的右端**（`.cs-act-meta` 的固定槽，进文档流） |
| 选中那条的概率 | 有 | **没有**（那一格放勾） |
| 备选的概率 | 有 | 有（比较用） |

⚠ **`pickedId` 失效要回落**：新一轮候选的 id 与上一轮不同 ⇒
若 `pickedId` 不在当前列表里，指针必须落回第一条，否则面板上**一条勾都没有**。
