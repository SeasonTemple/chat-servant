# v0.1.1

在 v0.1.0 之后的第一个版本。**用户能看见的改动集中在三处**：面板换成撕边纸、
OCR 引擎换代、发送档位砍到两档。其余是让这三件事能真的发出去的工程。

## 中文

### 面板：从「一个圆角矩形」换成「一张纸」

- 主窗口切成**撕边纸面板**（`ui/static/probe-sheet.svg`），旧面板与**三处第二份真值**
  一并删除。纸的材质、撕口、红铅笔笔触全部有生成器在仓库里，可复现。
- 候选行动行、档位标记**改成从纸上撕下来的一片**，撕边取自面板自己的位图。
- **应用图标重做**：撕边纸 + 红勾，生成器入库。
- 排版：正文改仿宋，档位整格 1.35、归属行 15px 改疏排，配霞鹜文楷子集。
- **设置不再是另一个窗口**。原来点面板上的 `···` 会弹出第二个 640×520 的窗口——
  在 380px 窄面板里点一下就跳到宽一倍的另一个窗口，而面板内部毫无导航。
  现在它是**面板内的一屏**，与主区互斥，点同一个按钮来回切。

### OCR：默认引擎换代

- 默认翻成 **PP-OCRv6 small + ONNX Runtime**，代价是权重不再在仓库里
  （在 `target/models/`，`.gitignore` 覆盖），**发版时取权重打进安装包**，
  外壳会告知权重路径。
- ⚠ `Windows.Media.Ocr` **降为显式回退**（`CHATSERVANT_OCR=winrt`），
  不再是默认。评估与数字见 `docs/adr/0006-ocr-engine-evaluation.md`。
- 性能：`rec` 桶**跨帧复用**，稳态中位每帧省约 94ms。
  `cargo xtask ocr --repeat` 会把**冷启动档与稳态档分开报**——这两档分道扬镳，
  只报一个中位数会让人误判改动落在哪。

### 发送档位：砍到两档 ⚠ 安全模型的实质变更

- 现行只有 `Manual`（只填入，默认）→ `Auto`（点一下即填入并发送）。
  `Confirm`（二次确认后发送）已删除。
- ⚠⚠ **`Auto` 不二次确认**——点一下就发出去了。这**拆掉了「发送前必须再问一次」
  那道闸**，是安全模型的实质变更，不是排版调整。
  理由见 `docs/设计规范.md` §10 第 3b 条；守卫是
  `crates/core/src/dispatch.rs` 的 `the_tier_set_is_exactly_two_and_named`。
- ⚠ 这件事**改过一次又改回来**：2026-10-13 曾整档取消 `Auto`，
  2026-10-15 重新拍板砍的是 `Confirm`、`Auto` 回来。
  ⇒ 「三档变两档」成立过两次，**别把它当成单向收敛**。
- 升档必须是显式的、可回退的、会话结束自动回落 `Manual`；**程序自己不升档**，
  解析失败一律落到最低档。档位由 Rust 侧持有，界面只能请求改。

### 契约与工程

- 命令名进契约层，并查清 28 条命令里**前端实际只调 23 条**。
- 发版链路：新增**不出东西就能跑完整条链路**的 `dry_run` 入口（取权重 → 打包 →
  核对装包内有权重全跑，只跳过 `gh release create`）、`draft` 开关、
  以及 **tag ↔ `tauri.conf.json` 版本一致性闸**。
- 开发流程：门禁每轮打印分步耗时表、`dev.ps1` 内循环入口、`target/` 回收换判据。

### v0.1.1 收尾时修掉的几处

- **设置页重设计**：加了屏头与副标题（原先端详全局的那句话挂在「发送档位」
  下面，归属说错了）；输入框从「无边框」改成撕边纸材质（原来在真机上读出来
  是个洞）；两族按钮高度统一。
- **四处工具/守卫自己说谎**：`dev.ps1` 的四个动词**永远 exit 1**；
  `svelte-autofixer` 那一步**在结构上无法报告任何一条告警**（有告警时工具输出的
  不是 JSON，于是被判成「工具不可用」并叫人别改代码）；`mojibake` 扫描只查
  U+FFFD、管不到能编译的控制符；`shotpanel.ps1` 的默认输出路径写死了旧仓库位置。

## English

The first release after v0.1.0. **Three user-visible changes**: the panel became a
torn-edge sheet of paper, the OCR engine was replaced, and the send tier was cut to
two. The rest is the engineering that makes those three actually shippable.

### The panel is now a sheet of paper

- The main window is a **torn-edge paper panel**; the old panel and **three duplicated
  sources of truth** were removed with it. The paper material, its torn edge and the
  red-pencil stroke all have generators in the repo.
- Candidate action rows and tier markers are **torn from the same sheet**, with the
  tear taken from the panel's own bitmap.
- **App icon redone**: torn paper + red check, generator checked in.
- Settings are **no longer a second window**. They used to open a separate
  640×520 window from a narrow 380px panel; now they are **one screen inside the
  panel**, mutually exclusive with the main area, toggled by the same button.

### OCR engine replaced

- The default is now **PP-OCRv6 small + ONNX Runtime**. The weights are no longer in
  the repo — they are **fetched and bundled at release time**, and the shell reports
  where they landed.
- ⚠ `Windows.Media.Ocr` is now an **explicit fallback** (`CHATSERVANT_OCR=winrt`).
  See `docs/adr/0006-ocr-engine-evaluation.md`.
- Performance: the `rec` bucket is **reused across frames**, saving about 94ms per
  frame in steady state. `cargo xtask ocr --repeat` reports **cold-start and
  steady-state separately**, because only one median hides where a change landed.

### Send tier cut to two ⚠ a real change to the safety model

- There are now only `Manual` (fill in only, the default) → `Auto` (fill in and
  send). `Confirm` (send after a second confirmation) is gone.
- ⚠⚠ **`Auto` does not ask twice** — one click sends it. That **removes the
  "always confirm before sending" gate**. This is a substantive change to the safety
  model. See `docs/设计规范.md` §10 item 3b; the guard is
  `the_tier_set_is_exactly_two_and_named` in `crates/core/src/dispatch.rs`.
- ⚠ This changed once and then changed back: `Auto` was removed entirely on
  2026-10-13, and on 2026-10-15 the decision was reversed — `Confirm` went instead.
  ⇒ **Do not read "three tiers became two" as a one-way convergence.**
- Escalating a tier must be explicit, reversible, and falls back to `Manual` at the
  end of a session. The program never raises its own tier, and an unparsable value
  always lands on the lowest one. The tier is owned by Rust; the UI can only ask.

### Contract and tooling

- Command names moved into the contract layer; we found the front end actually calls
  23 of the 28 commands.
- Release: a `dry_run` input that runs the whole chain **without producing anything**
  (fetch weights → build → verify the bundle contains the weights, skipping only
  `gh release create`), a `draft` switch, and a **tag ↔ `tauri.conf.json` version
  gate**.
- Dev flow: per-step timings printed by every gate run, a `dev.ps1` inner-loop entry
  point, and a new criterion for reclaiming `target/`.

### Fixed while wrapping up v0.1.1

- **Settings page redesign**: a header and subtitle (the "takes effect immediately,
  no restart" line used to sit under "Send tier", describing the wrong scope); input
  fields changed from borderless to the same torn-paper material (they read as a
  hole on a real machine); two button families unified to one height.
- **Four tools/guards that were lying**: `dev.ps1`'s four verbs always exited 1;
  the `svelte-autofixer` gate **could not report any warning at all** (with a warning
  the tool emits non-JSON, so it was classified as "tool unavailable" and told you
  not to touch the code); the mojibake scan only looked for U+FFFD and missed control
  characters that compile fine; `shotpanel.ps1` wrote to the repository's old location.
