# v0.1.2

在 v0.1.1 之后的版本。**用户能看见的改动只有两处，都在「认字」这件事上**：
面板现在读得出并显示会话名；WinRT 回退路径不再把整行小字读成乱码。
其余是让这两件事能真的发出去的工程。

⚠ **本版不含发送档位变更**：仍是 `Manual`（只填入，默认）→ `Auto`（点一下即发）两档，
`Auto` 依然**不二次确认**。安全模型与 v0.1.1 一致，理由见 `docs/设计规范.md` §10 第 3b 条。

## 中文

### 面板：能显示出会话名了

- 之前面板顶部**读不出对方的会话名**（那一条一直空着）。查出来的真因是
  **名字带子放大 2× 不够**——不是带高太窄，也不是颜色问题。
  ⇒ 名字带子改用 **3×**，重采样跟着所用引擎走。
- 读会话名那条路**搬进 `chatservant-perceive::peer::read_peer_name`**，
  产品与探针**共用一份**（以前两边各写一套，容易分叉）。
  探针输出会标明来源：整帧归类 / 生产路径。
- ⚠ 这条修法是**承重**的，不是碰巧：把倍数退回 2× 时，
  中文名那一格 **WinRT 读不到、3× 读得到** ⇒ 反向对照可复现。

### WinRT 回退路径：整行乱码没了

- 回退到 `Windows.Media.Ocr` 时，小字那一行曾被读成**一长串乱码**。
  成因是**最近邻放大把小字边缘留成锯齿块**，识别器把字形结构整个读崩。
  ⇒ 生产 OCR 视图**换成双线性**（不是调参，也不是加一道闸）。
- 同一帧同一行的前后对照：最近邻读成 106 字的乱码 → 双线性 50 字、编辑距离 4。
- 守卫：`the_winrt_recipe_is_bilinear`、`the_ocr_view_follows_the_plans_resampler`、
  `the_view_plan_constants_match_the_engines`、
  `the_classification_measures_the_raw_pixels_not_the_ocr_view`。

### 工程（用户看不见，但影响你拿到的包靠不靠谱）

- **门禁的「全绿」现在是真的**：此前有三处会让门禁在**工具缺失**时照样报
  `GATE: ALL GREEN`（串行步只打印不置红标志、父进程把**空**退出码当 0、
  并行组在命令不存在时 `exit 0`）⇒ 已修，并做了两向自证：
  工具缺失 ⇒ 必须红；工具在 ⇒ 必须绿。
- **`-Skip` / `-Only` 真正生效**：此前这两个参数**从未传进 lane 子进程**，
  「只跑一步」实际跑的是**完整门禁**；顺带修掉计时回传把秒数硬写成 0、
  跳过名单混进假步名、步秒之和虚高等三处。
- **发布链路幂等**：tag 被重推时不再撞名失败——此前会**烧完 24~25 分钟构建**
  才在最后一步炸掉（release 已存在 ⇒ `gh release create` 报错）。
  现在改为覆盖资产与说明。
- 依赖升级 `rustls-webpki` / `webpki-root-certs`（修两条新公告）；
  Python 侧依赖钉版本并开 pip 缓存（不再每次重装）。

## English

### Panel: the conversation name now shows up

- The peer name at the top of the panel used to stay **empty**. The real cause
  was that the name band was upscaled by only **2×** — not a too-narrow band,
  not a colour problem. ⇒ The name band is now upscaled by **3×**, and the
  resampling follows whichever OCR engine is in use.
- Reading the name moved into `chatservant-perceive::peer::read_peer_name`, so
  the product and the probe now **share one implementation** (they used to
  drift apart). Probe output states its source: whole-frame classification vs.
  production path.
- ⚠ The 3× factor is **load-bearing**, not a lucky fix: reverting to 2× makes
  the CJK-name case unreadable on WinRT while 3× reads it fine.

### WinRT fallback path: no more garbled lines

- On the `Windows.Media.Ocr` fallback, one line of small text used to be read as
  a long run of garbage. The cause was **nearest-neighbour upscaling leaving
  jagged edges**, which broke the glyph structure for the recogniser.
  ⇒ The production OCR view now uses **bilinear** resampling (not a parameter
  tweak, not another guard).
- Same frame, same line: nearest-neighbour produced 106 characters of garbage →
  bilinear produced 50 characters with an edit distance of 4.
- Guards: `the_winrt_recipe_is_bilinear`, `the_ocr_view_follows_the_plans_resampler`,
  `the_view_plan_constants_match_the_engines`,
  `the_classification_measures_the_raw_pixels_not_the_ocr_view`.

### Engineering (invisible to users, but it decides how trustworthy the build is)

- **"All green" from the gate now means something.** Three separate breaks used
  to let the gate report `GATE: ALL GREEN` **while a tool was missing**
  (a serial step printed the failure without raising the red flag, the parent
  treated an **empty** exit code as 0, and the parallel group exited 0 when the
  command was not found). All three are fixed, with a two-way self-proof:
  tool missing ⇒ must be red; tool present ⇒ must be green.
- **`-Skip` / `-Only` actually work now.** They were never passed into the lane
  child processes, so "run just one step" actually ran the **whole gate**.
  Also fixed: timings hard-written as 0, a fake step name in the skipped list,
  and inflated step-time totals.
- **The release pipeline is idempotent.** Re-pushing a tag no longer fails on a
  name clash — previously that burned **24–25 minutes of build** before failing
  at the very last step. It now replaces the assets and notes instead.
- Bumped `rustls-webpki` / `webpki-root-certs` (fixes two advisories) and
  pinned the Python dependencies with pip caching (no more reinstalling them
  on every run).
