## 7. 四条容易重犯的错

1. **`?demo` 八态绿 ≠ 真机通。** 夹具字段是手写的——2026-10-13 就发生过
   真实链路少发 `phase`、S3/S4/S6 真机不可达，而 demo 照样全渲染。
   ⚠ **2026-10-14 又添一条同类的**：夹具里写了 `tier` 字段，
   而 `loadDemo()` **压根没读它**——于是 `confirm.json` 与 `drafted.json`
   渲染出来**逐字节相同**。「七个夹具都渲染了」与「七个夹具都渲成一样」
   在截图上是同一件事。已修（`tier` 现在生效，`confirm` 的勾真的挪到
   「确认后发」）。判据是 `ui/scripts/stateink.ps1`，**别用眼睛比**。
   ⚠ 修完仍只有**六张不同的图**：`armed` 与 `confirm` 同图，
   因为 `armed` 想表达的那个界面（装填后的按钮态）**还不存在**——
   它要等动作行。
2. **被否决的做法不要重新发明。** 先查设计规范 §9 与 `面板设计.md`
   ——后者已作废但保留着，每一条否决都连着理由。
3. **量具的自检要能因为「量具偏了」而失败。** `stateink.ps1` 原来自检
   是「采样数必须等于硬编码的 57000」——而正文区整体位移之后**它照样通过**，
   整张表只是安静地全变成 0.00%。判据已换成「`drafted` 的取景窗里
   必须有墨」。教训同第 1 条：**看起来跑通了**是最常见的假信号。
4. ⚠ **写死的空态文案会和它上一行的事实打架，而且当时的夹具全都盖不到。**
   2026-10-14 出图撞见 `noprep` 的正文写着「对方说完话，这里才落笔。」，
   而**上一行**就是对方最后一句「行，不急」——同一张纸上互相否定。
   根因是那句**前端写死**：Rust 的 `status_hint()` 对 `read` 态返回 `None`
   （只有 `drafting` 有），而 `types.ts` 明写「界面不许自己写死这句」。
   修法是拆两支（对方没说话 / 对方说了没起草），但拆完**新的一支在 demo
   里不可达**——两具 `read` 态夹具都是 8 条消息，`stateink.ps1` 全绿，
   **绿得没有覆盖**。⇒ 判据全绿 ≠ 覆盖到了，两个问题要分开问。
   ✅ 已补 `fresh.json`（`read` + `messages: []`），八具覆盖两支空态。
