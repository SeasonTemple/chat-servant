### 3b. 设置页底色：曾经反转过一次，2026-10-16 又反转回来（**本节已被推翻过一次**）

**先记结论：现在设置屏与主面板是同一族**（同一张撕口纸、同一套墨与红铅笔）。
下面这段历史之所以留着，是因为**它被反过来过一次**，
而当时三处代码注释都写着「这是有意的材质切换」——下次再有人看到相关代码，
需要知道那句话已经被推翻过。

**当时的说法（2026-10-15，已作废）**：`.cs-sheet[data-settings='true']`
把纸纹整张撤掉换成中性灰 `--cs-paper`（`#EDF0F1`），依据是设计规范 §1
「纸面是配置界面唯一的敌人」，**是一次有意的材质切换**——
撕口消失、方角出现，这个跳变本身就是「你现在不在抄写，在配置」这句提示。

**为什么被推翻（2026-10-16，票 45）**：用户直接指出「设置页居然还是原生的边框、白底」，
并追问「反复提示了遵循统一设计风格，但一直无视要求」。查下来规范 §1 第 2 条
与 §5.1 两条**明文**允许分家，所以「无视规范」这半句不成立——
但**「设置屏是另一个材质」这个前提本身已被用户否掉**。

⇒ 现在：三支 `--cs-paper*` 全部指向纸族，`.cs-sheet[data-settings='true']`
的冷灰覆盖删除，设计规范 §1 / §5.1 已标注作废并写明新约束。
独立设置窗口时代的 `--cs-surface`（中性白 `#FAFAF9`）仍然禁掉：
在同一窗口里铺一块白底会留下一道接缝，而接缝正是这项目一直在删的。

**教训**：规范里「允许分家」的那两条，写的动机是「配置界面不该像抄写界面」；
但**用户要的是同族**，不是「有区别的同族」。这落差在规范里是合法的，
在产品上不成立 ⇒ 规范里凡是「允许不统一」的条款，都该当成**待验证**而不是**已授权**。

### 3c. 设置页字号阶梯（2026-10-16 定 5 档；⚠ 2026-11-01 实测已是 **6 档**）

用户原话：「设置页的字体不统一？」——实测确认不统一。
收敛前 9 个 font-size / 3 个 font-weight / 4 个 line-height。
⚠ **2026-10-18 `f16b349`（设置页重设计）加了 `.cs-set-title` 14px，2026-11-03 `d346b3f` 为完整容纳代理 URL 占位符将 `.cs-input` 压至小字下限 11px**，
所以「5 档」这个数已经过期——`rg -n 'font-size' ui/src/lib/PanelSettings.svelte`
现在数得出 7 个不同的值：**10.4 / 11 / 11.5 / 12 / 12.5 / 13.6 / 14**。

不统一的真因不是「差得多」，是**没有一档是共用的**：
11.5 与 11.52 差 **0.02px**、12.48 与 12.5 差 **0.02px** ——
肉眼绝无分别，却各自写着。行高里还有 14 个选择器**根本没写**，
吃的是 `normal`，而 `normal` 是「按字体算的」，
于是每个选择器的实际行高都不同，而且**没人知道是多少**。

收敛后：

| 正文 | 11.5 | 说明、错误、`.cs-btn-mini`、选择器标签 `.cs-picker-tag` |

### 3a. 动作行怎么映射到三变体（2026-10-15 定案，⚠ 当日又改了一次）

「可逆吗」和「这是首选吗」本来是**两个正交维度**，而 §4.2c 给的是三个**平级**
变体，不是二维。于是定了一个上位：**不可逆优先于推荐**。

| 档位 | 首选 | 备选 |
|---|---|---|
| `Manual`（仅填入） | **竖笔·墨**（墨线 + 墨色竖笔） | **墨线** |
| `Auto`（自动发送） | **红批**（墨线 + 红色竖笔） | **红批** |

判定写在 `actVariant()`，且 `Auto` 档会在按钮**上方**多一行红字前置说明
（「按下去就发出去了，收不回来」，§4.2b 要求它在按钮上方）。

⚠ **「首选」最初做成了「实墨」（墨底 + 纸色字），当天就被用户否掉**：
一个纯黑长条压在撕边纸上比整张纸任何东西都重，而它代表的只是一次
「填进输入框」的建议。**量级和它表示的风险严重不匹配。**
那一档本是给「S5 的先不发 / 发送」那组双按钮写的，§4.2b v2 早就否决过
「拿现成色块当零件」——搬错了语境。已改成竖笔·墨，理由见 §4.2c。

⚠ **其余三件事**：

1. **首选按钮不重复正文**——它就在正上方的正文行里；备选才自带正文
   （不写就没法比、没法选）。
2. **只有一条候选时不显示概率**——预置起草器恒给 `100%`，那是
   「没有第二个选择」的算术结果，不是置信度。
3. **旧实现被推翻的三条**：① `.cs-actions` 那道 `border-left` +
   `padding-left` 是**装饰改了容器几何**（§4.2c 明禁），且一道永远墨色的
   竖条会和红竖笔抢同一位置的语义；② 禁用态 `opacity: 0.55` 正是
   2026-10-14 被实测推翻的那条，现为 `border-style: dashed`；
   ③ 「按钮不描边框」让竖笔变体在静止态缺少界定框。

⇒ 新增 `DeliveryReceipt::Filled` 修掉，见 `CONTEXT.md`。

⚠ **`armed.json` 表达的那个界面仍然不存在，而且不会再去实现它。**
`Arming` 于 2026-10-15 从「已装填」改成「本轮已发过」的纯防重，
`ARMED` 事件也**不再 emit**（前端至今没有监听者）。
所以「装填后的按钮态」不是一个还没做的功能，而是一个**被砍掉的形态**——
那张夹具留着只为让 `?demo=1&state=<名字>` 的取值不断（**别在这里写死个数**——`git ls-files ui/static/demo` 才是权威，2026-11-01 实测 13 个）。

⚠ **真机验收整体欠着**：两档发送、phase 事件、外观 IPC 往返三项，
自 2026-10-09 那次「真的发出去一条」之后**一次都没在真机上跑过**。
新面板、新图标、改过的档位幅面都还没上过真机。这三项是
`ready-for-human`（要开真实微信会话动手点），不是 agent 能勾掉的。

⚠⚠ **2026-10-16 补一条与上面同等重要的流程坑**：`scripts/run-app.ps1`
用 `Start-Process -PassThru` 起 `pnpm tauri dev` 后**立刻返回**，
于是它**不适合跨轮次保持应用存活** —— 启动它的后台任务一结束，
同作业对象里的 `chat-servant-app.exe` 就被连带回收（实测：第二次截图时进程已不在）。
⇒ 要让应用跨轮次活着，得让 **`pnpm tauri dev` 本身就是那个长驻后台任务**，
不要用 `run-app.ps1`。同理，`pnpm dev` 单独起 vite 也是同理。

⚠ **「出图看不出问题」不等于真机没问题**：2026-10-16 第一次上真机，
当场撞出一个五轮 headless 全绿的缺陷（`.cs-input` 描边是全面板唯一冷色）。
凡是「颜色/材质类」的判断，headless 只能当预检，不能当验收。

## 7. 四条容易重犯的错

1. **`?demo` 全绿 ≠ 真机通。** 夹具字段是手写的——2026-10-13 就发生过
   真实链路少发 `phase`、S3/S4/S6 真机不可达，而 demo 照样全渲染。
   ⚠ **2026-10-14 又添一条同类的**：夹具里写了 `tier` 字段，
   而 `loadDemo()` **压根没读它**——于是高档夹具（原 `confirm.json`，
   **2026-10-15 已改名 `auto.json`**）与 `drafted.json`
   渲染出来**逐字节相同**。「七个夹具都渲染了」与「七个夹具都渲成一样」
   在截图上是同一件事。已修（`tier` 现在生效，高档夹具的勾真的挪到
   「自动发送」）。判据是 `ui/scripts/stateink.ps1`，**别用眼睛比**。
   ⚠ 修完仍只有**六张不同的图**：`armed` 与 `auto` 同图，
   因为 `armed` 想表达的那个界面（装填后的按钮态）**不会存在**——
   `Arming` 2026-10-15 改成纯防重、`ARMED` 不再 emit，见 §6。
   ⚠ **2026-10-15 踩到的反作用**：既然 `loadDemo()` 现在读 `tier` 了，
   **夹具里的 `tier` 会盖掉 `?tier=` 探针口**。想出 `Auto` 档的图，
   `?demo=1&state=drafted&tier=Auto` **静默失效**（回落到夹具自己的
   `Manual`），两张图只差纸纹噪点、字节数却不同——
   「字节数不同」在这里**不是**「内容不同」的证据。
   ⇒ 出高档图要**选对夹具**（`state=auto`），别指望 `?tier=` 覆盖它。
2. **被否决的做法不要重新发明。** 先查设计规范 §9 与 `面板设计.md`
   ——后者已作废但保留着，每一条否决都连着理由。
3. **量具的自检要能因为「量具偏了」而失败。** `stateink.ps1` 原来自检
   是「采样数必须等于硬编码的 57000」——而正文区整体位移之后**它照样通过**，
   整张表只是安静地全变成 0.00%。判据已换成「`drafted` 的取景窗里
   必须有墨」。教训同第 1 条：**看起来跑通了**是最常见的假信号。
4. ⚠ **写死的空态文案会和它上一行的事实打架，而且当时的夹具全都盖不到。**
   2026-10-14 出图撞见 `noprep` 的正文写着「对方说完话，这里才落笔。」，
   而**上一行**就是对方最后一句「行，不急」——同一张纸上互相否定。
   根因是那句**前端写死**：Rust 的 `status_hint()` 对 `read` 态返回 `None`
   （只有 `drafting` 有），而 `types.ts` 明写「界面不许自己写死这句」。
   修法是拆两支（对方没说话 / 对方说了没起草），但拆完**新的一支在 demo
   里不可达**——两具 `read` 态夹具都是 8 条消息，`stateink.ps1` 全绿，
   **绿得没有覆盖**。⇒ 判据全绿 ≠ 覆盖到了，两个问题要分开问。
   ✅ 已补 `fresh.json`（`read` + `messages: []`），覆盖「对方还没说话」那一支。
   ✅ 2026-10-14 再补 `parked.json`（闸关着 / `status_hint` 有值），覆盖
   **「已停泊在别的会话」**那一支——它原先落进 `fresh` 那一支，显示
   「对方说完话，这里才落笔。」，而那个会话对方明明说过话。
   ⇒ 现在（2026-11-01）13 个夹具覆盖了那两支空态（`fresh` / `parked`）。
   ⚠ 顺带发现的 `loadDemo` 只给 `drafting` 那支带 `status_hint` **已修**：
   `PaperPanel.svelte:919-937` 四支（`drafting` / `failed` / `drafted` / `read`）现在都带，
   注释里记着原因——`status_hint` 在真实 `Readout` 里**与 phase 正交**，按 phase 挑字段
   等于在夹具里把「闸关着」那一支裁掉。
