# 本机验收清单

云端这台机器**没有 Rust 工具链**（`cargo` 不存在），所以下面标🔴 的全部
没编译过。标🟡 的是云端验过静态部分、但**实机行为没验**。

按顺序走。**每一步都记下「实际看到什么」**，不一样的地方截图。

## 🔴 第一步：编译（不过就先停在这一步）

```bash
cargo check --workspace
```

预期可能有几处报错 —— 我在云端写这些 Rust 时**无法编译**，只做了静态复查
（命令注册齐全、`invoke` 参数名对上、`AppState` 字段对齐）。

**最可能出问题的三处**（按我写它们时的不确定程度排序）：

| 位置 | 为什么可能错 |
|---|---|
| `main.rs` 的 `build_tray` | `TrayIconBuilder::with_id()` / `.menu()` / `on_tray_icon_event` 的签名我凭 Tauri 2 记忆写的 |
| `commands.rs` 的 `build_tray_menu` | `PredefinedMenuItem::Separator(app).into()` 转成 `MenuItem` 的路径；`MenuBuilder::new(app)` 的参数 |
| `commands.rs` 的 `refresh_tray` | `app.tray_by_id(TRAY_ID)` 在 Tauri 2 里是否是这个名字 |

报错发我，我改。

```bash
cargo check -p chat-servant-app      # 先只查 app 这一层
cargo clippy --workspace --all-targets -- -D warnings
```

> ⚠ **crates/*/Cargo.toml 里的 `[lints]` 段也是没编译过的**（我早期加的）。
> 如果它报错，直接整段删掉——那是我加的偏好，不是原有代码。

## 🔴 第二步：窗口出口（这次改动的核心）

**这是改动的起因**：改之前这个程序**启动之后没有任何办法停掉**。

按顺序点，每一步都该看到：

| 做什么 | 预期 | 不对就是 bug |
|---|---|---|
| 启动 | 面板出现，右上角三颗记号 `···` `×` | 只剩一颗、或没有 |
| 点 `×` | **程序退出**（托盘图标也消失） | 只是面板关了，进程还在 |
| 重新启动，点设置页 →「窗口」→「收进托盘」 | 面板上**多出一颗 `−`** | 按钮数没变 |
| 启动，点 `−` | 面板消失，**托盘图标还在** | 进程退出了 |
| 右键托盘图标 | 菜单出现，首行是灰的**状态行**（如「小周 · 确认后发」） | 首行能点 / 没有首行 |
| 托盘菜单 →「显示面板」 | 面板回来 | |
| 托盘菜单 →「退出」 | 程序退出 | |
| **点 × 之前** 设成「自动发送」，再看托盘图标 | 首行写「小周 · **自动发送**」 | 没有档位信息 |
| 主面板选 `Alt+F4` | **面板关不掉**（被 `CloseRequested` 拦了），只能从托盘退 | 能关掉→托盘也一起没了，找不回来 |
| 面板**左缘空白处拖动** | 窗口跟着动 | 拖不动 |
| 点 `···` → 点面板外面 | 浮层收起 | 收不起来 / 一开就关 |

## 🟡 第三步：主面板六态

`?demo=1&state=<名字>`，名字 ∈ `noprep silent drafting drafted armed failed auto confirm`

| 状态 | 看什么 | 云端已验 |
|---|---|---|
| `noprep` | 「面板不认人，就不动手」+ 墨底「锁定当前会话」在正文里 | 渲染✓ |
| `silent` | 「在等 X 的新消息」—— 面板 90% 时间的样子，必须**安静** | 渲染✓ |
| `drafting` | 灰字「正在成形…」 | 渲染✓ 对比度✓ |
| `drafted` | 衬线台词 + 把握 + 备选 + 墨底「填入」 | 渲染✓ |
| `armed` | **顶边整条红** + 「在小周的输入框里」+「先不发」/「发送」**同尺寸** | 渲染✓ |
| `failed` | 错误原文 + 墨底「再试一次」在正文里 | 渲染✓ |
| `auto` | 顶边满 + 红；档位名也红 | 渲染✓ |
| `confirm` | 顶边 1/3，**不是红** | 渲染✓ |

**云端验不了、要你在真机上看的**：

- [ ] **「先不发」按下去会怎样？** 我只清掉了本地的 armed 状态，
      **没有调后端去清微信输入框** —— 那一行字应该**仍然留在**微信里。
      如果不是这样，说明我对这个按钮的理解错了。
- [ ] **档位能不能在面板上改？** 现在档位只在设置页（`TierSwitch`），
      面板上只显示、不切换。这是我的设计决定（档位搬到了顶边），
      但你不一定同意。**这条要你拍。**
- [ ] 顶边 3px 在真实窗口宽度下看不看得见？我标了「得把窗口拉宽才看得出档位差」
      —— 你实际用 400px 时会不会觉得**分不清当前在哪一档**？
      （档位名在旁边有文字，但它 3.81:1，是标注档。）
- [ ] 拖到 **320px** 以下：档位名隐藏、衬线降到 17px。会不会太挤？

## 🟡 第五步：视觉与无障碍

- [ ] **衬线生效了吗？** 我在字体栈末尾加了 `SimSun`/`宋体` 兜底
      （原来只有 macOS 的 `Songti SC`）。你机器上那句台词是衬线还是黑体？

## 🟐 我知道还没做的

按我认为该做的顺序：

1. **主面板上加一个改档位的入口。** 现在档位只能去设置页改 —— 顶边
   显示档位却不能点，是这一版最明显的缺口。
2. **「先不发」要不要真的清掉微信输入框里的字？** 现在只清了本地状态。
   如果不清，那颗按钮该改名叫「不自动发送了」之类，语义完全不同。
3. **`PossiblySent` 单独一屏。** `types.ts:30` 写着「禁止自动重放」——
   这是唯一不能自动恢复的 Outcome，现在它跟别的回执一样混在 `reason` 里。
4. **设置页的键字失败后要能重试。** 现在读不到设置就显示默认。
