## 0. 怎么用

逐步点，**每一步都该看到预期里的东西**。对不上就是 bug，

## 1. 编译与门禁

```bash
cargo check --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cd ui && pnpm check && pnpm lint
```

**最可能出问题的地方**（历史上真的在这几处挂过）：

| 位置 | 为什么容易错 |
|---|---|
| `main.rs` 的 `build_tray` | `TrayIconBuilder::with_id()` / `.menu()` / `on_tray_icon_event` 的签名容易凭 Tauri 2 记忆写错 |
| `commands.rs` 的 `build_tray_menu` | `PredefinedMenuItem::Separator(app)` 转 `MenuItem` 的路径；`MenuBuilder::new(app)` 的参数 |
| `commands.rs` 的 `refresh_tray` | `app.tray_by_id(TRAY_ID)` 在 Tauri 2 里是否是这个名字 |

⚠ **别只看退出码**，要读 `scripts/gate.ps1` 打印的那两行
（`GATE: ALL GREEN` / `GATE: FAILED`）。2026-10-11 实测：它当时只打印
没有 `exit`，于是 `pwsh -File` 永远返回 0，一个带红门禁的 commit 被提交了。
现在补了 `exit $fail`，但判断时仍以打印的那两行为准。

## 2. 窗口出口

**这是硬约束**：改之前这个程序**启动之后没有任何办法停掉**。

| 做什么 | 预期 | 不对就是 bug |
|---|---|---|
| 启动 | 面板出现，右上角 `⚙` `···` `−` `×` | 只剩一颗、或没有 |
| 点 `×` | **程序退出**（托盘图标也消失） | 只是面板关了，进程还在 |
| 设置 →「窗口」→「收进托盘」，**重启** | 面板上**多出一颗 `−`** | 按钮数没变 |
| 启动，点 `−` | 面板消失，**托盘图标还在** | 进程退出了 |
| 右键托盘图标 | 菜单出现，首行灰字状态行（如「小周 · 自动发送」） | 首行能点 / 没有首行 |
| 托盘菜单 →「显示面板」 | 面板回来 | |
| 托盘菜单 →「退出」 | 程序退出 | |
| 切到**「自动发送」**档，看托盘图标 | 右下角多一颗**红点** | 没有档位信号 |
| 主面板选 `Alt+F4` | **面板关不掉**（被 `CloseRequested` 拦了），只能从托盘退 | 能关掉→托盘也一起没了，找不回来 |
| 面板**左缘空白处拖动** | 窗口跟着动 | 拖不动 |
| 点 `···` → 点面板外面 | 浮层收起 | 收不起来 / 一开就关 |

> ⚠ 「拖动」那一行历史上写的是「预期窗口跟着动 / 不对就是 bug」——
> 实测确实就是 bug，根因是 ACL 缺 `core:window:allow-start-dragging`。
> **这类「控件点不动 / 拖不动」不会在控制台冒泡**，clippy、svelte-check、
> 测试一个都不报，详见 `AGENTS.md` 的踩坑区。

**它们不是残留文件，别当垃圾清掉**——只是下面这张验收表没覆盖它们。

⚠ **八具**：2026-10-13 取消 `Auto` 档时删掉了 `auto.json`
（它与当时的 `confirm.json` 只差档位名，是纯重复），
**2026-10-15 砍掉 `Confirm`、`Auto` 回来后，`confirm.json` 改名为
`auto.json`**，`?state=auto` 又是独立一态；
**2026-10-14 补回 `fresh.json`**（对方**还没说话**那一支，
原先七具的 `read` 态都塞了 8 条消息，压根盖不到它）。

|---|---|---|
| `noprep` | 归属行说**「没认出这是谁的对话」**（墨色，**不是红**）+ 对方最后一句 + 正文「对方说完了，这轮没起草。」 | |
| `fresh` | 归属行只有名字、**没有引文行**，正文「对方说完话，这里才落笔。」—— 与 `noprep` 分属两支空态 | |
| `silent` | 面板 90% 时间的样子，必须**安静**。正文同样是「对方说完了，这轮没起草。」，**与 `noprep` 只差归属行认没认出**（`silent` 有名字）——⚠ 它**不写**「在等新消息」，那是旧面板的说法 |
| `drafting` | 灰字「正在成形…」 | |

## 4. 设置页

- [ ] 设置页控件高度。⚠ 曾经声称「33 = 33 = 33」，2026-10-10 实测推翻：

## 7. 我知道还没做的

按该做的顺序。前两条要你给方向再动。

1. **主面板上加一个改档位的入口。** 现在档位只能去设置页改。
2. **「先不发」要不要真的清掉微信输入框里的字？** 现在只清了本地状态。
   如果不清，那颗按钮该改名叫「不自动发送了」之类——语义完全不同。
3. **`PossiblySent` 单独一屏。** 它是唯一不能自动恢复的 Outcome，
   现在跟别的回执一样混在 `reason` 里。
   ⚠ **2026-10-18：我的判断是「先别做」，并把触发条件写死**——
   不是搁置不管，而是**它和票 20/21 是同一次到访**：
   · `CONTEXT.md:177` 定义了它的**语义**（禁止自动重放），**没定怎么呈现**；
     「单独一屏」是 UI 决定，属于要有依据才动的那类。
   · 它**只在 `Auto` 档（真的会发出去）出现** ⇒ 验收必须走真机发送路径，
     而那要人授权（票 20/21）。
   · 现在写一屏没人看过的界面 = **发出去未验收的 chrome**，正是本仓反复记的坑。
   ⇒ **触发条件**：票 20/21 的真机发送验收做完、且你在那一屏上看过现状之后，
     再定它长什么样、说什么文案。那时一次到访能同时验它和 `Auto` 档。
   ⚠ 顺带记一句：`HANDOFF.md:450` 记过一次「面板曾显示『可能已经发出去了』
   而对话流根本没有新消息」——那是 `fill_input_box` 假报 `PossiblySent`
   造成的，已由 `DeliveryReceipt::Filled` 修掉，**面板现在如实写「没有发出去」**。
   所以现在这屏不是「报错」，是**真的不确定**——措辞要区分这两种。
4. ~~**设置页的键字失败后要能重试。** 现在读不到设置就显示默认。~~
   → **2026-10-18 已修**，且原文有两处不成立：

   - **「读不到设置就显示默认」从来不是这样。** `fail` 一直在渲染
     （`<p class="cs-fail" role="alert">`），而 `view` 为 `null` 时
     **整块设置体不渲染** ⇒ 失败屏上除了那条红字**什么都没有**。
     （票面自己第 5 行的规矩：「撒谎的告警比没有告警更坏」——这条是反过来的，
     它没撒谎，是清单在撒。）
   - **真正的缺口是「没有重试入口」**：`refresh()` 只在打开面板时调一次，
     于是一次性故障（凭据管理器读不到、自定义路由坏了）只能靠关掉再打开，
     而那正好是最不想丢当前输入的时候。已在 `{#if fail}` 里加一颗
     `.cs-btn cs-btn-mini` 的「重试」，**复用既有按钮族**、不新造样式。
   - ⚠ **顺带修掉一个当时看不见的 bug**：`fail` **只被设置、从不复位**
     （只有 DEMO 分支与 catch 分支在设它）。在「没有重试入口」时看不出来——
     因为一屏之内根本不会成功第二次。**一给重试按钮，不复位就等于报错是假的。**
     `refresh()` 成功时现在会 `fail = null`。
