## 1. 编译与门禁

```bash
cargo check --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cd ui && pnpm check && pnpm lint
```

**最可能出问题的地方**（历史上真的在这几处挂过）：

| 位置 | 为什么容易错 |
|---|---|
| `main.rs` 的 `build_tray` | `TrayIconBuilder::with_id()` / `.menu()` / `on_tray_icon_event` 的签名容易凭 Tauri 2 记忆写错 |

| `commands.rs` 的 `refresh_tray` | `app.tray_by_id(TRAY_ID)` 在 Tauri 2 里是否是这个名字 |

⚠ **别只看退出码**，要读 `scripts/gate.ps1` 打印的那两行
（`GATE: ALL GREEN` / `GATE: FAILED`）。2026-10-11 实测：它当时只打印
没有 `exit`，于是 `pwsh -File` 永远返回 0，一个带红门禁的 commit 被提交了。

## 2. 窗口出口

**这是硬约束**：改之前这个程序**启动之后没有任何办法停掉**。

| 做什么 | 预期 | 不对就是 bug |
|---|---|---|
| 启动 | 面板出现，右上角 `⚙` 与 `×`；`−` **只在「收进托盘」档出现** | 只剩一颗、或没有 |
| 点 `×` | **程序退出**（托盘图标也消失） | 只是面板关了，进程还在 |
| 设置 →「窗口」→「收进托盘」，**重启** | 面板上**多出一颗 `−`** | 按钮数没变 |
| 启动，点 `−` | 面板消失，**托盘图标还在** | 进程退出了 |
| 右键托盘图标 | 菜单出现，命令共 5 项（见下） | 菜单不出现 / 缺项 |
| 托盘菜单 →「显示面板」 | 面板回来 | |
| 托盘菜单 →「退出」 | 程序退出 | |
| 切到**「自动发送」**档，看托盘图标 | 图标的**无障碍名**从 `… 仅填入` 变成 `… 自动发送` | 档位信号没进托盘 |
| 主面板选 `Alt+F4` | **面板关不掉**（被 `CloseRequested` 拦了），只能从托盘退 | 能关掉→托盘也一起没了，找不回来 |
| 面板**顶栏空白处**按住拖动 | 窗口跟着动 | 拖不动 |
| 点 `⚙` | 切到设置屏（**互斥主区**，不是叠在上面的一层） | 变成叠层 / 回不来 |
| 设置屏再点一次 `⚙` | 回到主区 | 回不来 |

### 本轮真机实测（2026-10-18）

托盘菜单的真实内容（截图 `target/probe/traymenu.png`，**不含聊天正文**）：

```
显示面板
锁定当前会话
打开设置
识别画布
────────
退出
```

⚠ **菜单里没有灰字状态行**——档位信号在**图标的无障碍名**里。
UIA dump 实测托盘按钮为 `副驾 · chat-servant · 仅填入`（class
`SystemTray.NormalButton`）。面板看不见的时候，这是唯一告诉用户「现在什么档」
的地方，所以这一格验的是**名字**，不是「右下角多一颗红点」。

已实测通过的四条（台架都在 `target/probe/`，判据取退出码/进程状态）：

| 验什么 | 怎么做的 | 结果 |
|---|---|---|
| 托盘图标在溢出区 | 点「显示隐藏的图标」展开，UIA 找 Button，再用 `hittrace` 交叉验坐标 | `副驾 · chat-servant · 仅填入` rect (2106,1295,40x40) |
| 托盘「退出」真能停 | 右键 → 点最后一行 | `QUIT_OK`，进程消失 |
| 面板 `×` 真能停 | UIA 找 Button「退出」→ **发真鼠标事件**点正中 | `PANEL_QUIT_OK`，进程消失 |
| `Alt+F4` 关不掉 | 面板置前 → 发 Alt+F4 | `ALT_F4_BLOCKED`，面板还在、进程还在 |

⚠ 三条坑，都是这轮踩出来的：
- **`#32768` 原生菜单在 UIA 下返回 0 个后代元素** ⇒ 菜单内容只能靠
  **截图 + 读像素**，读不了控件树。
- **菜单弹出后不能另起子进程去读**：起 `pwsh` 去 dump 会抢焦点把菜单收掉，
  读回来是空。**「菜单没建起来」与「菜单被抢掉了」在输出上完全同形**
  ⇒ 点与读必须同一个进程（`target/probe/traymenu_shot.ps1`）。
- `Alt+F4` 那条**判据不能只看进程还在**：托盘常驻时「面板关了但进程留着」
  与「完全拦住了」在进程层面同形 ⇒ 必须**再看面板窗口在不在**。
> ⚠ **`···` 这个控件已经不存在了**（2026-10-18 订正）。
> 清单原来按 `⚙ ··· − ×` 四颗验，**第三颗是照着一个更早的面板写的**：
> 那时 `··· → 设置` 弹的是另一个 640×520 的独立窗口（`open_settings`），
> `···` 纯粹是个窗口启动器。设置改成面板内的一屏之后它就被删了。
> 源码里现在只剩**两处**提到 `···`，都在 `PanelSettings.svelte` 顶部注释里
> 讲这段历史。真机 UIA dump 也证实：标题栏只有 `设置` / `收进托盘` / `退出`。
> ⇒ 本清单里凡是验 `···` 的行都改成了验 `⚙` 的切换行为。

> ⚠ 「拖动」那一行历史上写的是「预期窗口跟着动 / 不对就是 bug」——
> 实测确实就是 bug，根因是 ACL 缺 `core:window:allow-start-dragging`。
> **这类「控件点不动 / 拖不动」不会在控制台冒泡**，clippy、svelte-check、
> 测试一个都不报，详见 `AGENTS.md` 的踩坑区。
>
> ⚠⚠ **2026-10-18 订正：拖拽带只挂在顶栏（`.cs-topbar`），不在面板左缘。**
> `PaperPanel.svelte:688` 是 `<div class="cs-topbar" data-tauri-drag-region>`，
> 而正文区 `.cs-cpanel` 标的是 `data-no-drag`（689 行）——所以「左缘空白处」
> 那一行照着试**必然拖不动**，而那不是 bug。
> 实测（`target/probe/paneldrag.ps1`，2026-10-18）：
>   · 面板本地 (24,250)（正文区）→ 位移 **0,0**，拖不动
>   · 面板本地 (24,20)（顶栏空白）→ 位移 **140,90**，与目标完全一致，进程仍在
> ⇒ 验收位置是**顶栏**，别去正文区试。

- [x] 设置页控件高度。⚠ 清单里记过的两组数**都已过期**，别照着验：

      **重设计后的实测**（浏览器 `http://localhost:1420/?settings=1&demo=1`，
      505px 视口，`getBoundingClientRect`）：

      | 控件 | rect | 说明 |
      |---|---|---|
      | API key 输入框 | 217 × **46** | 撕边 10px + 内容 26px，`box-sizing: border-box` |
      | 「保存」 | 65 × **46** | 与输入框**逐项等高** |
      | 供应商按钮 / 「换新 key」/「测连通」/「删除」等 9 颗 | × **46** | 族内统一 |
      | 「打开」 | 65 × **46** | `.cs-btn-ink`，**同族**（原写「独立变体，非主按钮族」是错的） |

      ⚠⚠ **2026-10-18 全表重测并改了两处**：
      ① **高度全部统一到 46**。之前这一屏有 **62 / 58.5 / 55.5 / 46 / 44 五种**，
         根因是撕边 16px 比内容盒 30px 还厚，`min-height: 30px` 在
         `box-sizing: border-box` 下量的是**总高**、一直是空转的，
         各族于是各按自己的 padding 走；再叠上 `.cs-set`（列向 flex）
         的默认收缩，「打开」「重试」被压到 46 / 44。
         现改为撕边 **10px** + 内容 **26px**，`min-height: 46px` 真值。
      ② 「打开 / 重试」**不是独立变体**，它们走 `.cs-btn` / `.cs-btn-mini`
         同一族（原表把 46 / 44 标成「独立变体」是按结果反推的，方向反了）。
      ⚠ 撕边 16 → 10px 的那一格是**出图看的**，不是算出来的：
      `stripgen.py` 那条「纸芯最早只内缩 ~5.5 CSS px」是相对 16px 说的，
      按同比例换算 10px 下是 3.4px。`slice 32` 没变（slice 量源图像素、
      width 量画到边框盒多宽），**不需要重跑生成器**。

      ⚠ 两点如实说明：
      ① 这些数是**浏览器**里量的，不是 Tauri 真机窗口——两者 DPI 都是 1，
         面板 rect 380×560 与 CSS 一致，但没有分别复核过每个控件。
      ② 量完之后我只删了一条**没人用的** `.cs-lead` 规则（svelte 报
         `Unused CSS selector`），未使用样式不影响布局 ⇒ 这组数应当仍成立。
         要更硬的证据就在真机上再点一遍。

## 7. 我知道还没做的

按该做的顺序。前两条要你给方向再动。

1. **主面板上加一个改档位的入口。** 现在档位只能去设置页改。
2. **「先不发」要不要真的清掉微信输入框里的字？** 现在只清了本地状态。
   如果不清，那颗按钮该改名叫「不自动发送了」之类——语义完全不同。
3. **`PossiblySent` 单独一屏。** 它是唯一不能自动恢复的 Outcome，
   现在跟别的回执一样混在 `reason` 里。
   ⚠ **2026-10-18：我的判断是「先别做」，并把触发条件写死**——
   不是搁置不管，而是**它和票 20/21 是同一次到访**：
   · `CONTEXT.md:177` 定义了它的**语义**（禁止自动重放），**没定怎么呈现**；
     「单独一屏」是 UI 决定，属于要有依据才动的那类。
   · 它**只在 `Auto` 档（真的会发出去）出现** ⇒ 验收必须走真机发送路径，
     而那要人授权（票 20/21）。
   · 现在写一屏没人看过的界面 = **发出去未验收的 chrome**，正是本仓反复记的坑。
   ⇒ **触发条件**：票 20/21 的真机发送验收做完、且你在那一屏上看过现状之后，
     再定它长什么样、说什么文案。那时一次到访能同时验它和 `Auto` 档。

## 8. 提交前的真人原文闸（2026-10-24 加）

这道**不在门禁里**（门禁跑的是 `scripts/gate.ps1`，不碰提交路径），
它是 **pre-commit** 与 **commit-msg** 两个 hook 里的闸 ⇒ **要自己提交才验得到**。

它拦什么：暂存区的新增行与提交信息里，**逐字**出现了本机真帧的 OCR 文本
（黑名单 `target/probe/real-chat-blacklist.txt`，本机私有、gitignored）。
**门槛 = 6 个字符**（2026-10-24 从 8 降下来：票 93 泄漏的是六个字，8 抓不到）。

| 验什么 | 怎么做 | 预期 | 不对就是 bug |
|---|---|---|---|
| 黑名单在不在 | `Test-Path target\probe\real-chat-blacklist.txt` | 存在且非空 | 空的 ⇒ 跑一遍刷新脚本 |
| 黑名单**不入库** | `git check-ignore -v target\probe\real-chat-blacklist.txt`；`git ls-files target/probe/real-chat-blacklist.txt` | 前者**有输出**；后者**空** | 后者有输出 ⇒ 它要被提交了，**停下** |
| 拦得住 | 从黑名单里挑一句，粘进一个临时文件，`git add` 之后 `git commit` | 提交**被拒**，并打印命中的那行与命中的条目 | 放行了 ⇒ 这道闸没接上 |
| 不误伤 | 提交一句与黑名单无关的话 | 提交**成功** | 拦了 ⇒ 看打印的「命中的条目」是什么 |
| 缺黑名单时**不是静默跳过** | 把黑名单挪走，再提交 | 打**横幅**、提交**放行** | 静默放行 ⇒ 少了那道显眼提示 |
| 提交信息那一半 | 提交信息里写一句黑名单里的话 | 提交**被拒** | 放行了 ⇒ `commit-msg` 那道没接上 |

### 明写的豁免口

真遇到合理命中（某个词恰好也在私聊里出现过）时，在**那一行末尾**写：

```text
real-chat-ok: 这个词在设计文档里指的是 UI 元素，不是聊天内容
```

- ⚠ **理由不能空**：`real-chat-ok:` 后面什么都没有 ⇒ 照样拦。
- ⚠ 豁免**不是静默放过**：输出里会**点出来**（文件、行号、理由）。
- ⚠ 只对**这一行**生效，且**必须由人明写** ⇒ 它不是「关掉这道闸」。
- ⇒ **门槛不是旋钮**：别为了绕过一处命中把门槛调回去，用豁免口。

### 本仓自己有没有残留

- 清单在 `target/probe/real-chat-leaks-in-repo.txt`（gitignored，含原文，**别贴进会话**）。
- 它第一段是**按条目汇总**（次数 / 长度 / 字符类别 / 涉及文件数）⇒ **按那个分诊**：
  **涉及文件数大 ⇒ 通用词 ⇒ 误报**；小且所在行像人话 ⇒ 才是残留。
- ⚠ 实测：本仓已有内容里，门槛 8 时 **131 处**命中（21 个条目），
  门槛 **6**（现行）时 **333 处**命中（26 个条目）。
  其中 **2~3 个条目就占了一两百处**（分别出现在 5~12 个文件里）⇒ **通用词、误报**，
  机械地「清」会改坏正常代码。

⚠ **验证用的那句话是真人聊天原文** ⇒ 它只能待在**临时文件**里，
验完**物理删除**，**绝不 commit**。

⚠ 正例要**从黑名单里取**
（`Get-Content target\probe\real-chat-blacklist.txt | Select-Object -First 1`），
**不要自己编**——自己编的那句不在黑名单里，测的就不是这道闸了。

### 刷新黑名单

```powershell
pwsh -NoProfile -File scripts\refresh-real-chat-blacklist.ps1
```

⚠ 它**慢**：每帧一次 OCR（实测 ~13 s/帧）⇒ 全量刷一遍是**分钟级**。
⇒ 刷完**不用重启任何东西**（提交时现读那份文件）。
