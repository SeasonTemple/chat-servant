# 设计规范 · 纸面

> **状态：定稿前的唯一依据。** 设计稿定稿之前不许改 `ui/src`。
> 上一版 `docs/面板设计.md` 已被否决——被否决的理由逐条记在
> [§10 已否决的做法](#10-已否决的做法别再走一遍)，那一版仍然保留在仓库里，
> 是为了让人看得出错在哪，不是因为它还有效。

---

## 0. 这份规范解决什么

现有面板的病根不是配色难看，是**没有规则**。

按钮一个样、备选条一个样、滑块又一个样，每个都是「手搓毛胚」——
因为没有一条东西能让它们从同一个源头长出来。所以这份规范先立规则，
再让每个零件从规则里长出来。**规则只有四条裁法**，其余全是推论。

本文按「理念 → 材质 → 边缘 → 字体 → 配色 → 组件 → 文案 → 纪律」排列。
前两节是根，后面每节都可以从它们推出来。

## 1. 设计理念

### 1.1 一句话

> **整块面板是一张棉浆纸，上面所有东西都是这张纸的另一种裁法。**

### 1.2 为什么是「纸」而不是「玻璃」

玻璃的材质在边框上（高光、折射、厚度），纸也一样。
所以「做出质感」不是给面板加个纹理背景，而是——
**面板的每一个零件都必须有厚度和来历。**

这也是本项目唯一被验证过的材质隐喻：
这套产品的工作是「在你自己的对话里，替你写下一句话」。
一张**正在被写**的纸，是这个动作唯一贴得住的东西。

### 1.3 四种裁法

| 裁法 | 物理 | 唯一的机械特征 | 用在哪 |
|---|---|---|---|
| **面** | 纸平铺在桌上 | 只有纹理，**零阴影** | 面板底、消息流、静态文字 |
| **压** | 纸被压下去一块 | **只有内阴影**，上缘暗 / 下缘亮，零外阴影 | 备选条槽、对方来话的槽 |
| **贴** | 另一小片纸贴上来 | **只有外阴影**，顶/左受光、底/右背光 | 按钮、档位标 |
| **裁** | 纸被裁断 | 一条毛边断口，**零阴影** | 分隔线、底边露头 |

### 1.4 从四条裁法长出来的四条硬推论

这四条就是「组件一致性」的全部含义，不是口号：

1. **凸起程度 = 可交互程度。**
   贴片是能按的，压槽是你往里写的，面是你只是看的。
   任何元素一旦**立体感和它的角色打架**，就是错的。

2. **压和贴的阴影方向必须相反。**
   凹进去：上缘挡光所以**暗**，下缘露出下面的纸所以**亮**。
   凸出来：上缘朝天所以**亮**，下缘背光所以**暗**。
   这一条最容易写反，也最容易被人一眼验出来——弄反了就立刻塌回毛胚。

3. **静止的东西是纸，动起来的才有厚度。**
   窗口控制键静止时是「面」，悬停才变「贴」。
   否则三颗按钮会在头顶铺成一块浮雕。

4. **文字没有厚度。**
   静态字一律铺在面上，谁都不许给字加投影。

## 2. 材质

### 2.1 纸的品类：棉浆纸（画册纸 / 机制纸）

| 候选 | 判断 | 理由 |
|---|---|---|
| **棉浆纸 rag** | ✅ **采用** | 画册纸、档案纸、卡纸的材质。厚、吸墨、笔迹能吃住、有分量。日常但不廉价 |
| 羊皮纸 vellum | ❌ | 那是**契约**的材质。这张纸是「我正在替你写」，不是「条款已生效」。黄褐色本身还带不可逆暗示，和「温和地帮你回消息」冲突 |
| 宣纸 / 和纸 | ❌ | 太薄太透，密集字会糊进纤维里。且「雅」过头——这是日常工具，不是雅集 |
| 牛皮纸 kraft | ❌ | 棕色 + 粗糙 = 运输、工地。屏幕上的轻量感和它打架 |

**棉浆纸的准确规格**：暖象牙白、长纤维可见、有轻微帘纹、低对比。
注意「低对比」是硬要求——高对比的纹理贴到 380px 的面板上会变噪点。

### 2.2 材质的纪律：不许用 CSS 假造

**棉纤维长什么样，不是几条渐变能编出来的。** 所以：

- **纹理一律用生成的位图**，不许用 `feTurbulence` 之类冒充。
  上一版的 `.grain::after` 就是反例——它做出了「脏」，没做出「棉」。
- **色块不等于材质。** 给一个元素加了 `box-shadow` 但没有真纹理，
  它读作「毛胚」而不是「纸」。
- 允许 CSS 负责的只有**裁法**（厚度、明暗、轮廓），
  纹理本身必须来自图片。

### 2.3 三种材质，各自的职责

| 材质 | 贴图 | 用在哪 | 为什么 |
|---|---|---|---|
| **棉浆纸** | `tex-rag.jpg`（512², 36 KB） | 面板底、压槽内部、底边露头 | 主材质 |
| **棉毡** | `tex-felt.jpg`（512², 42 KB） | 所有贴片（按钮、档位标） | 毡就是**压实的棉纤维**，与纸同源不同密度。所以「同一张纸的另一种裁法」在材质上是成立的，不只是嘴上说说 |
| **朱砂印泥** | `tex-seal.jpg`（512², 82 KB） | 只给 Auto 档的封口 | 见 §3.6 |

生成记录：`mcode-tools connector call connector__matrix__generate_image`，
源图 2048² 居中裁半再降到 512²——裁半是为了让纤维的每像素密度翻倍，
否则缩到面板尺寸后只剩一片糊。`target/design/prep-tex.ps1` 是可复跑的脚本。

> ⚠ **印泥贴图不许再 `multiply`。** 它本身就是成品朱砂色，
> 拿一张暗红去乘会把红压成黑泥（实测 `#B3261E × 印泥 ≈ #690905`）。

### 2.4 贴图的两种用法，别搞混

| 用法 | 做法 | 什么时候 |
|---|---|---|
| **材质叠色** | `background-blend-mode: multiply` + 一张**亮**的材质图（均值 ≥ 230） | 纸、毡这类要透出底色的 |
| **材质即成品** | `background-blend-mode: normal`，贴图直接铺 | 印泥这类本身就是颜料的 |

染色贴片（深色按钮、红色发送）要用**第三种**：
底色 + `::before` 挂毡图 `mix-blend-mode: overlay`。
因为 `background-image` 若不撤掉，它会以原样盖在深色底上，
按钮直接变成一块浅米色。

## 3. 边缘 —— 上一版最假的地方

> 用户判断：「还是没有把普通的边框处理掉，非常明显的劣质」。
> 这一节是对那句话的完整回答。

### 3.1 纸边的解剖：从内往外五层

`border: 3px solid <色>` 的毛病是它是一根**等宽、等色、平的带子**。
真实纸边是个三维侧壁：

| 层 | 是什么 | CSS 现状 |
|---|---|---|
| ① 表面 | 棉浆纸的纤维纹理 | ✅ 有 |
| ② 内缘亮口 | 切面顶部露出的纤维反光，1px，全边最亮 | ⚠ 只有顶部 |
| ③ **侧壁本体** | 纸的断面厚度，**纹理是纤维断面而非纸面**，受光面亮背光面暗 | ❌ **纯色块** ← 劣质根因 |
| ④ 外缘暗线 | 纸边自身的遮蔽，不是投影，1px，最暗 | ⚠ 只有底部 |
| ⑤ 轮廓 | 不是完美直线，哪怕机制纸也有 ±0.3px 抖动 | ❌ 完美直线 |

上一版只做对了 ① 和一部分 ④，**③⑤ 全是色块**——所以它一眼假。

### 3.2 真正的做法：侧壁用「断面纹理」，不是用颜色

```
❌ border: 3px solid; border-color: 四色分向      ← 等宽色带，永远假
✅ padding: 3px                                      ← 让出厚度
   外层 3px 环 = 纸的**断面纹理**（不是纸面纹理）
   内层     = 纸面纹理，填满 padding box
   四条边各叠一条分向的半透明白/黑     ← 不是改 border-color，是叠加
   顶部内缘 1px 亮线                   ← ② 纤维反光
   底部/右侧轮廓 ±1px 抖动             ← ⑤ 靠位移，不是靠 border-radius
```

**判据：把厚度调大到 40px，如果还是像色块，就是没做对——
侧壁必须看得出是「切开的纤维」，不是「涂了一层漆」。**

### 3.3 四条边来历不同，处理也不同

| 位置 | 边的来历 | 处理 |
|---|---|---|
| 面板外框 | 这张纸被**裁**下来 | 裁切边：断面纹理 + 分向受光 + 内缘亮口 |
| 底边露出的那层 | 唯一能看见纤维的地方 | **毛边**：真位移，边缘参差外伸 |
| 压槽内缘 | 凹进去了 | 上暗 / 下亮 |
| 贴片外缘 | 凸起来了 | 上亮 / 下暗 |

### 3.4 「溢出」怎么做

纸的质感不只在表面，在**它压过东西的那一圈**：

```
⑤ 轮廓抖动（±1px 位移）
   ↓
⑥ 露头 —— 底下那张纸的边。这是你唯一能看见「纸有多少层」的地方
   ↓
⑦ 纸叠自己的落影 —— 近而短，远影会让 380px 面板上的小贴片糊成一团灰
```

**露头必须是毛边，不能是圆角色块。** 明明是最该看见纸性的地方，
上一版却给了它最假的一个处理——这是「CSS 毛胚」的典型症状。

### 3.5 毛边 / 绒毛从哪来

| 效果 | 做法 |
|---|---|
| 毛边（轮廓参差外伸） | `feTurbulence` + `feDisplacementMap` **真位移**。位移的边缘才会随纤维不规则，那才像撕的；画出来的锯齿永远假 |
| 绒毛 / 纤维断面 | **必须用生成的位图**，CSS 做不出单根纤维的受光 |
| 蜡口 / 印泥不匀 | 位移 + `saturate`/`brightness` 接在滤镜链后面 |

⚠ 滤镜链只有一条，所以调色必须串在位移后面，不能另起一条。

### 3.6 火漆：为什么不是烧焦

- **烧焦 = 破坏**。这张纸不是被破坏的，它是拿来写的。
  四条边都焦 = 整个界面一直在喊「危险」，
  那会直接破掉「红只给不可逆」这条原则，还会引入第三种颜色（棕黑）跟红抢戏。
- **火漆 = 封缄**。它不毁掉纸，它是盖在纸上的一个封口。

而且火漆天然对应档位——这是材质能表达、而色块表达不了的东西：

| 档 | 语义 | 材质 |
|---|---|---|
| 只填入 | 纸还在你手里 | 边是**裸的**，无染色 |
| 确认后发 | 笔递到你手边 | **1/3** 的一条染色毡 |
| **自动发送** | **已经盖了火漆** | 满幅朱砂蜡条，下缘不齐 |

只有 Auto 档没有「先不发」——因为封上了，你能做的只是看着它出去。

### 3.7 这一节的验证状态

| 项 | 状态 |
|---|---|
| 毛边 / 蜡口位移 | ⚠ 在设计稿上出现过，但**外框侧壁仍是 `border` 色块**，被用户判为劣质。§3.2 的做法**尚未实现** |
| 纸边断面纹理 | ❌ **素材还没有**。已下过生成请求（纸边断面 / 绒毛 / 毛边 / 羊皮 / 牛皮共五张），执行中被中止，需要重跑 |
| 轮廓抖动 | ❌ 未实现 |

## 4. 字体

### 4.1 三种字体，三个职责，越界即错

| 字体 | 唯一职责 | 为什么 |
|---|---|---|
| **楷体** `楷体, STKaiti` | **机器替你落笔的那句话** | 楷体一出现，就意味着「这是内容，不是界面」 |
| **无衬线** `Microsoft YaHei UI` | **界面本身**：标签、数值、状态、按钮字 | — |
| **等宽** `Cascadia Mono` | **真数据**：把握 %、耗时、条数 | 见 §4.4 |

### 4.2 为什么是楷体不是宋体

**宋体不是手写——它是印刷衬线。** 所以用宋体的话，
台词读起来永远是「排版好的」，而不是「有人写的」。这是上一版「平」的根因。

本机实测 184 个字族，`楷体 / 仿宋 / 黑体 / 宋体 / 微软雅黑 / 等线` 均在列。

### 4.3 字号阶与配对

只有五档，**不许随手加第六档**（源自 `ux-guidelines.csv` 的 font-scale 12/14/16/18/24/32）：

| token | 值 | 用途 |
|---|---|---|
| `--t-micro` | 12px | 等宽数字专用 |
| `--t-label` | 13px | 界面字下限 |
| `--t-mid` | 14px | 界面字 |
| `--t-body` | 16px | **手写体下限** |
| `--t-hand` | 19px | 机器落笔的那句话，全产品最大 |

⚠ **楷体 16px 以下笔画会糊**（且楷体没有 italic 可用）。
所以手写体的下限是 16px——这不是审美偏好，是字体的物理限制。

### 4.4 等宽的边界

`frontend-design` 把「满屏等宽小标注」列为 **AI 特征**，
`number-tabular` 又要求**数字**必须等宽。两者不冲突，解法只有一条：

> **等宽只给数字，绝不用于装饰性小字。**

### 4.5 行高与稿纸格

台词行高锁死 **26px = 稿纸格距**，所以每一行都正好坐在格线上。
这是格线存在的**唯一理由**——它告诉用户字落在哪。
装饰性的横线一律删掉。

## 5. 配色

### 5.1 纸色

底色 `#FBF7EF`（暖中性），**刻意比常见「奶油纸」淡**。

理由是 skill 之间的冲突，裁决过程如下：
`ui-ux-pro-max/data/colors.csv` No.93「Notes & Writing App」给的是 `#FFFBEB`；
而 `frontend-design` 把「暖奶油底 + 陶土色」列为**第一号 AI 特征**。
两边同色。

**区别不在色相，在有没有真材质。** AI 味那版是「奶油底 + 衬线 + 陶土，什么都没有」。
所以本规范的做法是：把底色往中性挪，**让生成的棉纤维照片去提供暖意**，
颜色本身不再承担「这是纸」这件事。陶土色整支不用。

### 5.2 墨色

`colors.csv` 给的 `#0F172A`（slate-900）数字够好，但它是**冷**的。
墨落在暖纸上该是暖黑，所以往暖里拉：

| token | 值 | 对比度 | 用途 |
|---|---|---|---|
| `--ink` | `#17130C` | 16.0:1 | 你写下的 / 机器落笔的 |
| `--ink-2` | `#3A3223` | 9.6:1 | 次级 |
| `--pencil` | `#5A5140` | 7.0:1 | 机器认出来的 |
| `--mark` | `#776D59` | 5.1:1 | 标注 |

### 5.3 红只有两处

| token | 值 | 含义 |
|---|---|---|
| `--live` | `#B3261E` | **不可逆**：发送、封口 |
| `--proof` | `#C9705F` | **校样批注**：淡到读作铅笔痕，只做图形不做正文 |

两条量级不能一样。批注栏那道红刻意淡到 3.1:1——
它是铅笔痕，不是警报。

> Auto 档的蜡条也是红的，因为它同样是**不可逆**。
> 红仍然只标记不可逆，不破例。

### 5.4 格线

`--grid: #D8CFB4` / `--rule: #C9BFA2`。

⚠ 印刷线是**压上去的墨线**，所以它清晰——它不是裁口。
第一版取 `#E4DCC6`，在棉浆纸纹理上几乎看不见，等于没有格。

## 6. 组件

### 6.1 组件 → 裁法 对照

| 组件 | 裁法 | 备注 |
|---|---|---|
| 面板底 / 消息流 | 面 | 零阴影 |
| 对方来话的槽 | 压 | 它是内容，不是能按的东西 |
| 备选条槽 | 压 | 它**不是按钮的兄弟**，是一个「可以往里挑的槽」 |
| 按钮（反白 / 发送 / 裸纸） | 贴 | 可点的必须有厚度 |
| 窗口控制键 | 面 → 悬停变贴 | 静止无厚度 |
| 顶边档位条 | 裁 / 贴 / 蜡 | 三档三种材质，见 §3.6 |
| 分隔线 | 裁 | 毛边断口 |
| 稿纸横线 | 印刷线 | **不是裁口**，不许加毛边 |

### 6.2 一致性自检清单

新增或修改任何组件，逐条过：

1. 它属于四种裁法的哪一种？
2. 阴影方向对吗？（贴片上亮下暗 / 压槽上暗下亮 / 面无阴影）
3. 它可交互吗？不可交互就不许有厚度。
4. 它的文字用哪种字体？（手写=内容 / 无衬线=界面 / 等宽=数据）
5. 字号在 12/13/14/16/19 五档里吗？
6. 它用红了吗？只有不可逆能用。
7. 它的贴图是哪一张？**材质图不许被 CSS 渐变冒充**。
8. 高对比度模式下它还成立吗？（`forced-colors: active`）
9. 焦点可见吗？触摸目标够大吗？
10. 八态里每一态它都出现吗？缺的补上，多余的删掉。

### 6.3 尺寸下限

| 项 | 下限 | 出处 |
|---|---|---|
| 点击目标 | 24×24 | WCAG 2.2 AA `web-target-size`（**Web 指针**） |
| 触摸目标 | 44×44 | `touch-target-size` |
| 相邻目标间隙 | 8px | `touch-spacing` |

> ⚠ 实测踩过的坑：上一版三个窗口键矩形 x=730/764/794，
> 间隙 6px 和 2px，**中的是 `touch-spacing`**。
> 28×32 其实过了 `web-target-size`——把它说成「按不中」是夸大了。
> 这条要记住：先查清是哪一条规则，别笼统说「无障碍不过」。

## 7. 文案与状态

### 7.1 文案裁法

| 规则 | 含义 |
|---|---|
| `redundant-entry` | 能从界面本身看出来的，一律删 |
| `input-helper-text` | **后果不可推断的必须留**（如「画面会发给第三方模型」） |
| `progressive-disclosure` | 默认折叠，别一屏铺开 |

上一版设置页的毛病就是把 1、3 两条当 2 用：
「全部改完立刻生效，不用重启面板。」——能自己看出来；
「画面切分只在 1 张真实样本上验证过」——这条该留，而且是硬约束级别的提醒。

### 7.2 八态

`noprep / silent / drafting / drafted / armed / confirm / auto / failed`。

每个态只回答一个问题，**不解释机制**：

| 态 | 只回答 |
|---|---|
| `noprep` | 卡在哪 + 唯一可做的事（不认人就是闸，不是一个错误） |
| `silent` | 在等谁 + 「没新消息就不动，零调用」 |
| `drafting` | 在成形 |
| `drafted` | 草稿 + 把握 + 备选 + 唯一动作「填入」 |
| `armed` | 已进输入框（看得见）+ 先不发 / 发送 |
| `confirm` | 和 drafted 相同，但明确「这一档会等你按发送」 |
| `auto` | 已封口，会直接发出去。**没有按钮**——封上了就不该有「我按了就发」 |
| `failed` | 说在哪 + 能不能重试，**不说堆栈** |

### 7.3 布局

- 尺寸锁死 `tauri.conf.json` 的真实面板 **380 × 560**（`minWidth 340`）。
- **不做响应式。** 用户已明确否决。
- 结构自上而下：档位材质条 → 头（会话名 + 档位 + 三键）→ 裁口分隔 →
  对方来话（压槽）→ 草稿（手写体，占主体）→ 把握/备选 → 备选（压槽）→
  动作（贴片，贴底）。
- 底部留 12px：少了它最后一条说明会被 3px 纸边切掉。

## 9. 纪律

1. **先想清楚，再动手。** 设计稿没定稿前不许改 `ui/src`。
2. **不许把 CSS 色块当材质。** 色块 + 阴影 = 毛胚，不是纸。
3. **材质一律用生成的位图**，不许用 SVG 噪点冒充。
4. **改界面前先读这份文档**，不是凭手感写。
5. **不引 Tailwind。** 材质 token 的单一出处是本文件加 `paper.css`。
6. **高对比度必须单独验。** `--live-dim` 就是这么漏掉的：高对比度下悬停
   会退回 OS 从没选过的裸红（`cfeecba` 修的同一个类的洞）。
7. **凡是有「还没验的」，在文档里如实标注**，不许写得像已经验过。
8. **验证要掐到「改回去会变红」的程度**，只看通过不算验过。

## 10. 已否决的做法（别再走一遍）

| 做法 | 否决理由 |
|---|---|
| 稿纸质感只做背景 | 用户原话：「从边框到每一环细节都是稿纸的模拟」。材质在边缘最明显 |
| 用 CSS `feTurbulence` 假造纸纹 | 做出「脏」，做不出「棉」。违反 §2.2 |
| `border: 3px solid` 四色分向 | 等宽色带，纸边是三维侧壁。见 §3.1 |
| 边缘做成烧焦 | 破坏的隐喻 + 破掉「红只给不可逆」+ 引入第三种颜色。见 §3.6 |
| 底边露头做成圆角色块 | 最该看见纸性的地方给了最假的处理 |
| 宋体当手写体 | 宋体是印刷衬线，读起来永远是「排版好的」 |
| 陶土色点缀 | `frontend-design` 的第一号 AI 特征 |
| 等宽做装饰性小标注 | 同上；只给数字 |
| 暖奶油底 #FFFBEB 原样照搬 | 会退回 AI 味；改由材质提供暖意 |
| 羊皮纸 / 宣纸 / 牛皮纸 | 见 §2.1 |
| 响应式 | 用户明确否决 |
| shadcn-svelte / Melt UI / Tailwind v4 | 见 §8 |
