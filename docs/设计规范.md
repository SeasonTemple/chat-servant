## 2. 纸

### 2.1 纸边的物理：为什么边缘必须长那样

`border: Npx solid <色>` 是**等宽、等色、平的色带**。
真实纸边是三维侧壁，从内 outwards 五层：

| 层 | 是什么 | 能在代码里对应到吗 |
|---|---|---|
| ① 表面 | 棉纤维纹理 | 📐 位图内部 |
| ② 内缘亮口 | 切面顶部露出的纤维反光，1px，全边最亮 | 📐 位图内部 |
| ③ **侧壁本体** | 纸的**断面**，纹理是切开的纤维而非纸面 | 📐 位图内部 |
| ④ 外缘暗线 | 纸边自身的遮蔽，1px | 📐 位图内部 |
| ⑤ 轮廓抖动 | 不是完美直线 | 📐 位图内部 |

**这张纸不是 CSS 造出来的，是一张照片。** 所以五层一次到位——
用 CSS 分层去凑这五层，每层之间都会露出接缝。

> 💭 **手写 CSS 版为什么否决**：调不出 ② 和 ③ 的关系。侧壁要的是
> 「切开的纤维」，那是**一张照片**，不是几个 `box-shadow` 能编的。

### 2.2 现行做法：整张纸烘成位图 🔒

`ui/static/probe-sheet.svg`，291 KB，10 行：

```
<filter id="sheetDrop"><feDropShadow dx=0 dy=10 stdDeviation=13 opacity=0.34/></filter>
<g filter="url(#sheetDrop)" transform="translate(16,0)">
  <image width="348" height="512" preserveAspectRatio="none" href="data:image/png;base64,…">
```

- **撕口即顶边** —— 面板顶部没有装饰，撕口本身就是上边界
- **不用 `SetWindowRgn`** —— 它是二值掩码，撕口会变成硬阶梯；
  交给合成器抗锯齿 🔒 `panel/+page.svelte` `SetWindowRgn`

### 2.3 实测数据 📐


| 缩放比 | x **0.4579** / y **0.4571** |

1. ⚠ `preserveAspectRatio="none"` 意味着**这不是等比缩放**，

**撕口那档对 alpha 门槛不敏感**：从 250 降到 1，五个列的读数只在
5.5 ~ 11 之间动，够不到任何别的数。（原注释写「17.5px」，对不上，已订正。）

### 2.4 🔴 纸的**原始生成方式**已不可考，但纸现在可复现了

这两件事要分开说，混起来就会得出「这张纸没救」的错误结论。

**已不可考的是「这张图当初是怎么画出来的」**（2026-10-12 五处取证，全部落空）：

- `app.css` 提到的 `paper-fixed.png`，本机与 git 全都找不到
- `git rev-list --all --objects` 里全部 17 条 png 路径，逐条核对，**没有一张纸**
- `git fsck --dangling` 的 35 个悬空 blob 按大小与魔数逐个查过，**无一是那张 217,945 B 的图**
- 唯一那个悬空 commit 时间戳比纸诞生早三个月
- 关键词扫「折痕」「水渍」各 **0 命中**；「纤维」全是定性描述，**一个数值都没有**

所以**没有办法重画它**，也没有办法换纸色而不重画。

**但「不可复现」这个说法本身已经不成立了** 🔒：

- 源图 `ui/static/probe-sheet.png` 现在**在库里**（760 × 1120，217,945 B，
  sha256 `9C85D6BD…9961`），它与 SVG 内嵌段**逐字节相同**（已验）
- `probe-sheet.svg` 是**生成物**，由 📁 `ui/scripts/sheetpack.ps1` 把 PNG
  重新打包进去；`sheetpack.ps1 -Check` 供门禁校验两者是否同步
- 这套「源 + 生成物都入库 + 一个打包脚本」是本仓**既定的做法**，红铅笔笔迹
  就是这么管的（`pencilgen.py` → `marks.js`）

「产物入库、来源没入库」这个问题当时**只修了一半**：
`pencilgen.py` 从 `.scratch/tmp-probe/` 搬进了 `ui/scripts/`，纸没有对应脚本。
**2026-10-12 补上了另一半。**

> ⚠ **为什么不能干脆让 SVG 外链 PNG**（2026-10-12 实测）：那样 SVG 能缩到
> 439 字节，但**行不通**。SVG 一旦被当作 `background-image` / `<img>` 载入，
> 就处于「安全静态模式」，浏览器**不加载任何外部资源**，纸整个画没。
> 实测 `/panel` 截图从 454,974 B 塌到 12,690 B，851,200 px 里 670,001 px 变了
> （78.7%）；同时 `GET /probe-sheet.png` 返回 200 / 217,945 B——**不是文件没
> 伺服，是策略拦的**。所以 SVG 必须保持自包含。

### 2.5 纸的品类：为什么不用别的 💭

以下仍是**主张，未做对照图**。若要推翻，先去材质台 `/studio` 做并排对照。

| 候选 | 判断 | 理由 |
|---|---|---|
| **棉浆纸 / 机制纸** | ✅ 现行 | 厚、吸墨、笔迹能吃住。日常但不廉价 |
| 羊皮纸 vellum | ❌ | 那是**契约**的材质。这张纸是「我正在替你写」，不是「条款已生效」。黄褐本身还带不可逆暗示，和「温和地帮你回消息」冲突 |
| 宣纸 / 和纸 | ❌ | 太薄太透，密集字会糊进纤维。且「雅」过头——日常工具不是雅集 |
| 牛皮纸 kraft | ❌ | 棕色 + 粗糙 = 运输、工地。屏幕上的轻量感和它打架 |

> ⚠ 这条从未被挑战过。`probe-sheet` 到底是不是棉浆纸，**没有人验过**。

## 3. 红铅笔笔迹

这一整块是 v1 完全没覆盖的新工作，v1 只字未提。

### 3.1 生成器 🔒

`ui/scripts/pencilgen.py` → 产物 `ui/src/lib/marks.js`。
按「**中心线 + 宽度剖面**」生成，不是手写 path —— 手写过一次收放方向反了
🔒 `panel/+page.svelte` `pencilgen`。

### 3.2 两条不同的羽化机制，不能混用 🔒

| | 用在哪 | 机制 |
|---|---|---|
| **嵌套同中心线** | 勾（粗笔） | 五级同心收窄，宽度系数 1.00 / 0.86 / 0.70 / 0.52 / 0.30，累计密度 0.22 → 0.41 → 0.56 → 0.69 → 0.85 |
| **三道叠画** | 圈（细笔） | 圈的柔边来自多道细线叠加，**不是**嵌套。×0.30 会让 1.15~1.5px 的圈直接看不见 |

> **叠笔偏移产生不了羽化。** 外层那道的最外缘仍是满 opacity 的硬边，
> 叠出来只是变粗 + 多几级台阶。

### 3.3 颗粒：三个滤镜各干一件事 🔒

```
feTurbulence  baseFrequency=0.62 numOctaves=4 seed=11
  → feColorMatrix         alpha = 0.72×(R+G+B) − 0.30      三通道求和映射成 alpha
  → feComponentTransfer   tableValues="0 0.08 0.30 0.62 0.88 1"   拉对比
  → feDisplacementMap     scale=2                                抖 ±1px
```

- **为什么要 `feComponentTransfer`**：线性映射出的 alpha 集中在 0.6~1.0，
  那是**均匀变淡**，和平涂一个毛病。拉高对比后才出现 0.1 附近的低谷，
  也就是笔尖「跳格」的断续。
- **为什么位移给合成器**：位移不产生二值掩码，所以不会出现
  `SetWindowRgn` 那种硬阶梯。scale 2 ≈ 抖动 ±1px，再多就变成毛边而不是石墨。

### 3.4 🔴 CSS 兜底会毁掉笔迹

`.cs-tick path` **只能设 `fill`，绝不能设 `fill-opacity`**。

每层的透明度是**笔迹数据**，由生成器算出来。CSS 声明会盖掉每层 path 上的
`fill-opacity` 属性，**五层嵌套立刻塌成单层平涂** —— 羽化全没了，
成为唯一一支不像铅笔的。

> 这个坑已经踩过一次：给 `.cs-tick path` 写 `fill-opacity` 会把五级全覆盖掉。
> 现在**只换 `fill`**
> 🔒 `panel/+page.svelte` 「只能改 fill」。
> **要改浓度就改生成器里的剖面，让五级一起动。**

**而且看不出哪里错了** 🔒 `(panel)/+page.svelte` 「收尾」。

### 4.2 🔴 宋体还是楷体：**上一版定案已推翻，2026-10-13 重测，分歧重开**

**先记一条自我更正，因为它会让人重读错的东西。**
2026-10-12 那一版在这里写「宋体着墨 2.02 倍、紧邻间隙余量 5.8 倍，所以定宋体」，
**那两个数是从一个量错了东西的指标上读出来的，结论整个反了。**

原脚本里那句是：

```python
elif not d and run2 is not None: gaps.append(x - run2)   # 记的是墨游程的**宽度**
```

`gaps` 里装的是**一根竖笔画有多宽**，不是**两个字之间有多空**。
所以「楷体紧邻 39.8%」的真实含义是「楷体有 39.8% 的竖笔画细到 ≤1px」——
**笔画细是「不容易糊」的方向，不是危险方向**。用它把楷体否掉是把指标读反了。
当时还打了 🔒，🔒 打错了。

**为什么汉字上根本不该问「字间距」——两个方法都试过，都不成立：**

| 试法 | 结果 |
|---|---|
| 列投影（数全 0 列） | 全角顶满字身框，19px 下相邻两字首尾相接，**一个空白列都没有**。三种字体 min=0 / 均 0 / ≤1px 占 100%，**完全一致，零区分度** |
| 连通域按 x 重叠聚类 | 楷体相邻两字的墨迹包围盒在 x 上**仍然重叠**，整行聚成 **1 个**「字」（宽 18.5px） |

⇒ 「字和字之间空不空」**不是汉字小字号可读性的问题**。汉字本来就贴着走。
真正该问的是：**手写体笔画细，多大才够黑、才不会在纸纹上发虚断笔。**

**重测环境**：纯色纸底 `rgb(247 233 194)`，内容栏 316px，字体 × 字号两轴，字距一律 0。
台子与脚本 `target/typo/typebench.html`、`target/typo/analyse-type.py`（gitignored）。

| 候选 | 字面率（墨量） | **≤1px 细笔画** | 墨迹高 ÷ 字号 |
|---|---|---|---|
| 宋体 `SimSun` 19px（现状） | **31.5%** | **8.3%** | 0.97× |
| 宋体 21px | 32.7% | 7.2% | 0.95× |
| 楷体 `KaiTi` 19px | 13.8% | 48.4% | 0.92× |
| **楷体 21px** | 13.6% | **38.1%** | **0.95×** |
| 楷体 23px | 13.9% | **25.2%** | 0.93× |
| 仿宋 `FangSong` 19px | 12.5% | **77.7%** | 0.92× |
| 仿宋 21px | 12.7% | **75.9%** | 0.90× |

**读法**：手写感的代价不是「挤」，是「淡」——楷体字面率只有宋体的 43%，
纸是有纤维的，字越淡越容易和纸纹混掉。这两条都能靠字号买回来：
**21px 把细笔画从 48.4% 压到 38.1%，墨迹高度回到 0.95× 字号**（19px 只有 0.92×，上下都贴着）。
23px 最实（25.2%）但 316px 栏里一屏只剩半句。**仿宋出局**：19/21px 都是 75%+ 的笔画细到 ≤1px，必然断。

**本机可用的手写/书法向只有楷体与仿宋**（184 个字体族全查过）：
没有华文行楷、没有隶书、没有幼圆。
⚠ **这不是通用结论** —— 别的机器上装了行楷就该重测。

**未定案**（2026-10-13，等拍板）：19 / 21 / 23px。倾向 21px。

**新增的量具坑（都踩过，脚本注释里有记）**：
④ 纸的**边缘抗锯齿**把页底灰 `#6b7278` 混进掩码，那个灰的亮度 0.171 **低于**墨阈值 0.374，
于是**整张纸每一行都判成有墨**，行切分退化成「一整块」，脚本安静地返回**空结果**。
必须把取样区内缩 2 CSS px。⑤ 渲染倍率会让坐标整体错位——脚本自动从纸块宽折回倍率，
**别硬写 `scale=2`**。这两个和 v1「台子不写 height 会把背景图压扁」是同一类：
**量具坏了，数字看着还挺正常。**

### 4.2c 📐 按钮组件族提案（2026-10-13，未进实现）

三种，共用同一套几何：**高 30 / padding 0 16 / radius 4 / 13px 600 / 全是 1px 描边**。

| 变体 | 用途 | 规则 |
|---|---|---|
| **墨线** | 可撤销、可逆 | 1px 墨描边 + 透明底 + 墨字；hover 墨 7% |
| **实墨** | **每屏最多一颗**，唯一主动作 | 墨底 + 纸色字 |
| **红批** | 不可逆 | 红**只出现在页边一道 3px 竖笔**（hover 加宽到 5px），框与字仍是墨色 |

**因为三种都是 1px 描边，S5 的「先不发 / 发送」天然等宽等高**——
不再需要给 ghost 补透明边框去凑那 2px（旧实现的 `.cs-btn-live` 那条注释就是在防这个）。

焦点环**用墨不用红** 🔒 §5.4；禁用是 `opacity .34`，不换色。

> ⚠ 红批的红条必须用**绝对定位的伪元素**，不许改 `padding`——
> 早先为它把 `padding-left` 加到 19px，文字整体右移 9px，看着没居中。
> **几何必须由 box 一处说了算，装饰不许改 padding。**

## 5. 配色

**唯一出处是 `ui/src/app.css`。** v1 §5 的全部色值**作废**。
下面只记代码之外的东西。

### 5.1 纸底是暖黄，不是冷灰 🔒

实测屏上中位数 `rgb(243 230 192)` 📐。早先把底色锁在冷侧（hue 195°），
理由是「别跟微信的暖白撞」—— **这条现在不成立**
🔒 `app.css` 「纸底是暖黄」。

于是分工明确：**纸 = 真实暖黄，配置界面 = 中性白**，
两者不再假装是同一张纸。

### 5.2 对比度全部在**真实纸底上**重算过 🔒

不是看着还行。换纸底后两支翻了：

| token | 旧 | 实测 | 结果 |
|---|---|---|---|
| `--cs-mark` | 3.81 : 1 | **3.00 : 1** | **掉出 AA 正文**，只配 ≥18.66px 粗体 / ≥24px 常规，或非文本 |
| `--cs-live` | 4.65 : 1 | **5.95 : 1** | 升过 AA |

### 5.3 🔴 红铅笔与警报红，对比度打平

`--cs-pencil-red` **5.90 : 1** vs `--cs-live` **5.95 : 1**。

所以「红 = 警告」**根本不是对比度能定输赢的** —— WCAG 只量亮度差，
而这两支的亮度差本来就在噪声里 🔒 `app.css` 「红铅笔」。

能分开它们的只有两样：

1. **形** —— 手画的一根勾 vs 一根实心横条
2. **质地** —— 蜡质 vs 纯色

> 所以档位标记必须是**手画的**。换成实心红条，它立刻变成警报，
> 而默认档恰恰是最不危险的那一档。

### 5.4 焦点环用墨，不用红 🔒

红是状态色，不是导航色。焦点环和「活」是两件事，
混在一起红就又要兼职了 🔒 `app.css` 「焦点环」。

撕边纸上不能靠描边，得用一圈**纸色的负空间**把底下笔画顶开
🔒 `panel/+page.svelte` 「负空间」。

### 5.5 🔴 `--cs-rule` 在暖黄纸上等于隐形

`--cs-rule` **1.05 : 1**、`--cs-rule-strong` **1.20 : 1**（这两个数是
**在暖黄纸上**实测的，不是照抄旧纸底的）。

> ⚠ 别和 `app.css` 里 `--cs-rule` 那条注释混：那里写的 1.24 : 1 是
> 对**旧冷灰底**的比值，换纸底后已经不准了。

**尚未处理**。稿纸格线要靠它们。

## 6. 组件自检清单

新增或修改任何零件，逐条过。**不通过的别合。**

### 6.1 材质与形

1. 它有厚度吗？有厚度 = 它可交互。**不可交互的东西不许有厚度**
   🔒 `app.css` 「面板是纸，直角」——圆角只给字条和可点的按钮
2. 它的边缘是真撕的还是画的？撕口必须是位图的一部分，不能是 CSS `border` 📐
3. 它有第二个边界吗？撕边纸上多一圈描边就是**两个边界打架**
   🔒 `panel/+page.svelte` 「第二个边界」
4. 它的纸纹和面板是同一张纸吗？

### 6.2 颜色与字

5. 它红了吗？**只有不可逆能红** 🔒 `app.css` 「红色只有一处」
6. 它用的是 `--cs-mark`（3.00:1）吗？那个色**只配大字或非文本**，
   拿它写小字就是不合规 🔒 `app.css` 「达不到 AA 正文」
7. 对比度**在真实纸底上**算过吗？不是在冷灰上
8. 字体栈**以 Windows 真有的字收尾**了吗 🔒 `(panel)/+page.svelte` 「收尾」
9. 它是手写体 / 界面体 / 数据体？分对了没有？数据才用等宽

### 6.3 状态与可达

10. 焦点环可见吗？撕边纸上要用负空间，不要描边
11. 相邻可点目标间隙 ≥ 8px（`touch-spacing`）
12. `forced-colors: active` 下它还成立吗？
13. `prefers-reduced-motion` 下它还成立吗？（时长压 1ms 不是 0，
    因为 0 会让 `transitionend` 永不触发 🔒 `app.css` `transitionend`）
14. 它在每一态里都出现过吗？缺的补上，多余的删掉

## 9. 已否决的做法

| 做法 | 否决理由 |
|---|---|
| 稿纸质感只做背景 | 「从边框到每一环细节」——材质在边缘最明显 |
| 用 CSS `feTurbulence` 假造纸纹 | 做出「脏」，做不出「棉」 |

| **用 CSS 分层去凑纸边五层** | 调不出 ②③ 的关系，接缝会露出来 §2.1 |
| `SetWindowRgn` 做撕口 | 二值掩码，撕口变硬阶梯 |
| 叠笔偏移当羽化 | 外缘仍是满 opacity 硬边，只是变粗 |
| 线性 alpha 映射当颗粒 | 集中在 0.6~1.0，那是均匀变淡，和平涂同毛病 §3.3 |
| CSS 设 `fill-opacity` | 覆盖笔迹数据，嵌套五级塌回单层平涂 §3.4 |

| 响应式 | 用户明确否决 |
| 用 macOS/Linux 常见字收尾字体栈 | 会静默掉到默认无衬线，且**看不出哪里错了** |
