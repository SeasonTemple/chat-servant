## 一句话

**它不是仪表盘，是抄写员。** 坐你旁边，把对方说的话记下来，递一张条子给你，写
「你该回这句」。材质取自它自己的世界——纸、笔、誊写、校样上的红铅笔批注。

## 六个状态

`types.ts` 的 4 个 Phase × 3 个 Tier × 5 个 Outcome，加重锁、刷新、识别画布、
设置、托盘 —— 十一个功能，每个都有落位。**状态是这套设计的主结构，不是配色。**

| | 状态 | 正文说什么 | 动作 |
|---|---|---|---|
| S1 | 没认出会话 | 面板不认人，就不动手（+ 为什么） | **锁定当前会话**（墨底主按钮） |
| S2 | 静默 | 在等 X 的新消息 / 不会空转 | 无 |
| S3 | 起草中 | 正在成形… / 通常几秒 | 无 |
| S4 | 已起草 | 台词 + 把握 + 备选 | **填入** |
| S5 | 待发射 | 那句话 + 已填进 X 的输入框 + 现在按下去它就出去了 | **先不发** / **发送**（同尺寸） |
| S6 | 出错 | 错误原文 | **再试一次**（墨底主按钮） |

浏览器里看：`?demo=1&state=<名字>`，`名字` ∈ `noprep / silent / drafting /
drafted / armed / failed / confirm / auto`。数据在 `ui/static/demo/*.json`。

## 三条结构性决定

**① 修问题的按钮和问题在同一屏。**
重锁只在 S1、刷新只在 S6，都是正文里的墨底主按钮。原版正文写「点标题栏的锁」
「点右上角的 ⟳」—— 按钮在 13px 的角落，正文只给一句指路。

**② 档位长在面板顶边。**
它描述的是「你交出去多少控制权」，也就是面板和外界的关系，不是里面写了什么，
所以不该参与内容布局。用**填充长度**编码递进：不亮 / 1/3 / 满+红。
取代原来的右侧 72px 竖柱（`TierColumn`，已退役）—— 那根柱子在 400px 宽的
面板上占 18%，而且面板一变宽它就跑到余光外了。

**③ armed 占满整个面板。**
全产品最不可逆的一瞬：已经有字躺在对方输入框里了。此刻**「先不发」和「发送」
一样重** —— 做成更小的一颗等于暗示可以随便撤回，那不是真的。
原版把它塞在按钮内的一行小字里。

⚠ **「占满」说的是占满哪一块**（2026-10-12 订正，这一版措辞有歧义）：
不是把内容纵向撑到 560px，而是**接管整个主区、并占住整条顶边**——
顶边那条红（状态）与两颗并排满宽的按钮一起说明「现在是这一个时刻」。
代码里那句注释说得更准：「显形不够，它得占整条顶边」。

⚠ **两颗按钮的措辞改过一轮，理由在 `+page.svelte` 里**：
- 「发出去」是从**收信那侧**说的，可用户就坐在微信前面，他才是发的那个；
  把视角写在别人位置上，一颗按钮就把用户的角色说反了。所以是**「发送」**。
- 「撤回」「拿回来」都在暗示**输入框被清空了**，可它只清掉「程序要替你发」
  这件事，那行字仍然在输入框里、用户自己在微信里看得见也能改。
  说自己做不到的事就是假话。「**先不发**」是用户犹豫时嘴里的话，也是真的。

## 配色：四个色，各有出处

```
纸    #EDF0F1   hue 195°  偏青，因为米白会跟微信的暖白撞
墨    #141A1F   hue 207°  15.31 : 1   你写下的
铅笔  #4C5A63   hue 210°   6.22 : 1   机器认出来的
红    #C8322A   hue   3°   4.65 : 1   唯一有彩度的
```

**红只给不可逆。** 发送是「字已经出去了」，退出是「字不会再出去了」——
两件都不可逆。看到红就是有东西出去过，或者要出去。
它在纸上只有 4.65 : 1，**不够高到能当装饰色用**，这正好：一个刚够读的颜色，
天生只能干一件事。（旧的亮金色黄铜 #D9A441 能到处用，于是到处被浪费。）

红色出现在两个时间尺度上，**别混**：
- **状态**（S5）：红顶边 + 红字，持续存在，余光可见
- **确认**（悬停 ×）：一瞬，手一开就没

## 字体的分工

| | 字体 | 说什么 |
|---|---|---|
| 台词 | 衬线（Songti / Source Han Serif / SimSun 兜底） | 这是替你写下的那句 |
| 证据条、把握、备选%、档位名 | 等宽 | 这是机器读出来的 |

⚠ 字体栈**必须以 Windows 上真有的字体收尾**。只写 `Songti SC`（macOS）
的话在用户机器上会静默掉到默认无衬线，衬线这个设计决定整个丢失，
**而且看不出哪里错了**。`SimSun` / `宋体` 兜底。

## 窗口控制

三颗记号用 **`@lucide/svelte` 的 `Ellipsis` / `Minus` / `X`**，不手搓。
项目里早就装了这个库（1869 个图标，经过视觉平衡与无障碍审校）。

- `size` / `strokeWidth` / 底盘 / 间距 **三颗完全一样**
- 形态永远不变，**只有颜色分岔**：`…` 和 `—` 悬停是墨底，`×` 悬停是红底
- 一颗**不能有两种含义**：`×` 永远退出，`—` 永远收起

「关闭时」在设置页 →「窗口」：**退出（默认）/ 收进托盘**。

⚠ **默认退出，不是收进托盘。** 没有托盘时「收起」没有落点——
一个离屏 + `alwaysOnTop` + `skipTaskbar` 的程序就是用户看不见的僵尸，
而它还在替人说话。**没有落点的动作不提供。**

### ⚠ 一条对不上的账：紧凑模式在真实窗口里进不去

这一节早先写着「紧凑模式：320px 下档位名隐藏、衬线降 17px、无横向溢出」。
那个 320 是**在浏览器里把演示外框拖窄测的**，而真实窗口拖不到那么窄：

```text
tauri.conf.json   "minWidth": 340
+page.svelte      const COMPACT_AT = 340;
+page.svelte      compact = entry.contentRect.width < COMPACT_AT;
```

`340 < 340` 永远不成立，所以**紧凑分支在真实窗口里是死代码**。
两条路可选，**都还没验过**（浏览器里没法把这个面板拖到 380 以下）：

1. `minWidth` 降到 300 左右 —— 承认 320 本来就是想要的下限。
2. `COMPACT_AT` 抬到 360 —— 窗口下限不动，让 340 那档真的走紧凑。

改完必须实机把面板拖到最窄看一眼，否则又是一条「测过但测不到」的账。

## 没验的（2026-10-12 重判）

⚠ **这一节原来写的是「这台机器没有 Rust 工具链，`cargo` 不存在，所以下面
这些一行都没编译过」。那条前提已经不成立了** —— 工具链在，
而且下面六条**全部已经在代码里**。所以真正剩下的问题不是「有没有写」，
而是「**交互路径有没有被真的点过一遍**」。这两件事不是一回事：
门禁能证明它们编得过，证明不了托盘菜单点得动。

| # | 项 | 代码在 | 门禁证明 | 还差什么 |
|---|---|---|---|---|
| 1 | `cargo check -p chat-servant-app` | — | ✅ 九步门禁每次都跑 clippy `--workspace --all-targets` | 无 |
| 2 | 托盘图标与菜单 | ✅ `build_tray` / `build_tray_menu` | ✅ 编得过 | **实机点一遍**：图标真出来、菜单三项都点得动 |
| 3 | `hide_panel` / `quit_app` / `get_close_behavior` | ✅ `commands.rs` | ✅ 编得过 | **实机点一遍** |
| 4 | `on_window_event` 拦 `CloseRequested` | ✅ `main.rs` | ✅ 编得过 | **实机按 ×** |
| 5 | `minWidth: 340` 的实际效果 | ✅ `tauri.conf.json` + `COMPACT_AT = 340` | ✅ 编得过 | **窄面板实跑**：见下 |
| 6 | 设置页「关闭时」切换 | ✅ `PanelSettings` 的 `SegSlider` | ✅ 编得过 | **实机切一次** |

第 5 条单独说一句：紧凑模式是 `ResizeObserver` 量**面板自己**的宽度
（`entry.contentRect.width < 340`），**不用媒体查询** —— 窗口可以被拖到
任意宽度，媒体查询只看视口。浏览器里没法把这个面板拖到 340 以下
（演示模式外框固定 380），所以这条仍然只有代码层面的证据。

## 一条纪律

**先查库，再谈设计。**

在 `@lucide/svelte` 已经装着的情况下手搓了三轮 SVG 图标，还配了两张刻度表
（「光学尺寸平衡」「圆头 vs 尖角」「统一基线」）—— 全是这个图标库**已经
解决**的问题。而且手搓那版标了「12 × 12」，实际画成了 6 × 6。

> 把「我决定用 17 × 17 配平」写进文档，比写「用 lucide 的 x，size 14」
> 危险得多：前者把一个可复用的决策固化成了个人品味。

## 另一条

`ui/src` 每一行都带注释，注释写的是**为什么**，不是「这里是什么」。
几处关键决定的理由写在了原地 —— 改之前先读那些注释，它们记的都是
「早先不是这样，以及为什么现在是这样」。
